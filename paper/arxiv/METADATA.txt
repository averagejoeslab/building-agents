TITLE
Agent = Harness(Model): Five Mechanistic Primitives of LLM Agent Harnesses

AUTHORS
Chase Dovey (Average Joes Lab)

ABSTRACT
The software that surrounds a large language model in an agent goes by many names: framework, scaffold, runtime, orchestration layer, harness. Recent work shows that this layer accounts for a substantial share of agent performance, yet it has not been characterized in terms of its parts. We separate an agent into a fixed model, TokensOut = Model(TokensIn), and a harness comprising everything else, so that Agent = Harness(Model). We argue that every harness is composed of five mechanistic primitives: control flow, which sequences the others and determines termination; input, which gathers what is sent to the model; context, which determines what the request contains and fits it to the context window; the model interface, which sends the request and receives the response; and output, which presents the response or executes it as a tool call. Each primitive is defined both by what it does and by what it never does, making the five mutually exclusive. The central argument is constructive: starting from a single API call and adding one primitive at a time, the deficiency at each step is precisely the next primitive, yielding a working agent of 86 lines of code and a system prompt, with nothing outside the five. Production concerns (sandboxing, guardrails, observability, resilience, performance and evaluation) are shown to be hardening within the primitives rather than new ones. A decomposition of three production coding agents (Claude Code, OpenAI Codex CLI and opencode) finds no component requiring a sixth primitive and refines the boundary rules. A case study of the constructed agent working across ten sessions from its own memory illustrates the decomposition's use in failure diagnosis.
