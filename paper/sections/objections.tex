\section{Objections}
\label{sec:objections}

\paragraph{Memory is a sixth primitive.} Memory is prominent in agent architectures \citep{sumers2024coala,packer2023memgpt}. We place it as a store in the world that \prim{Context} reads and \prim{Output} writes, governed by the persistence concern. The model has no memory of its own, and every implementation we examined (memory files loaded into the instructions, stores searched through tools, summaries carried forward, transcripts replayed on resume) is a decision about what \prim{Context} includes and which actions \prim{Output} offers. Making memory a primitive would split one decision, what the model is shown, across two components.

\paragraph{Planning is a sixth primitive.} Planning is either something the model does in its own tokens, which needs no harness support, or a structure the harness imposes: a mode that restricts actions, a plan kept in a file, a separate planning call. Each of these is \prim{Control flow} (which steps run, under what restrictions) or \prim{Context} (where the plan is kept and shown). Every planning feature in \S\ref{sec:deconstruction} decomposed this way.

\paragraph{A workflow is not a harness.} A workflow fixes the sequence of model calls in code; an agent lets the model direct its own process \citep{anthropic2024effective}. Both are harnesses. They differ in \prim{Control flow}, and only there: a graph with named nodes and edges is one design decision, an open loop is another. The LangGraph deconstruction in \S\ref{sec:deconstruction} is included for this reason.

\paragraph{Multi-agent systems are something else.} A system of several agents, each a model in a harness, is itself a harness whose \prim{Output} includes delegating to another agent and whose \prim{Input} includes that agent's result. Sub-agents, hand-offs and orchestrator--worker patterns are \prim{Control flow} decisions at the outer level. The primitives compose: a harness of harnesses still has five.

\paragraph{The harness will be absorbed into the model.} Models increasingly learn behaviours that harnesses once imposed: when to stop, how to call tools in a trained format, when to reason before acting. But a model cannot open a file, keep a log or refuse a command on its own. Training moves \emph{policy} into the model (what to do); the \emph{mechanism} (how anything happens) remains in the harness. If models are trained inside a particular harness (\S\ref{sec:uses}), the harness defines the world the model was trained for, and its decomposition matters more, not less.

\paragraph{Five boxes can describe anything, and so explain nothing.} The primitives are a coordinate system, not an explanation. Their value is in placing a design decision, a failure or a difference between two systems in one location, so that it can be studied, compared and changed independently of the rest. The claim is falsifiable in a specific way (\S\ref{sec:limitations}), and the content is in the design decisions of \S\ref{sec:primitives} and the deconstruction of \S\ref{sec:deconstruction}, not in the boxes.
