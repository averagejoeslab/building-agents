\begin{abstract}
An agent is a model wrapped in a harness, and the harness has five parts. \prim{Input} captures what comes in. \prim{Context} assembles what the model is shown. \prim{Model interface} sends the request and returns the response. \prim{Output} carries the response out. \prim{Control flow} decides whether to go again, hand back or stop. We propose this as the architecture of every harness, and show each primitive as the smallest program that adds it. Everything else said about a harness is a design decision within one primitive or a production concern, persistence, safety and security, observability, resilience, performance and evaluation, asked of every primitive. The vocabulary is needed because harnesses change results as much as models do, so a result belongs to the pair and comparison needs the harness stated in parts; it lets research compare primitives by their implementations, and lets debugging isolate a failure to the primitives an implementation touches. We deconstruct the popular harnesses against the five: six from their sources at pinned versions, Claude Code, Codex CLI, opencode, pi, Hermes Agent and a LangGraph workflow, and a wider set of thirteen from their sources or documentation. Every component found has a home. What the deconstruction cannot show is which implementation of a primitive is better; the vocabulary makes that comparison well-posed, by holding the model and four primitives fixed and varying one, and we set out the comparisons that would both use the framework and test it. The minimal harnesses and the evidence for every assignment are published with the paper.
\end{abstract}
