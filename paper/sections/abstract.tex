\begin{abstract}
Large language model (LLM) agents are usually described by the model inside them, yet the same model can behave as a careful engineer in one system and fail to finish a task in another. What differs is everything around the model: the software that decides what the model sees, what it can do, and when it runs again. Practitioners call this a \emph{scaffold}, a \emph{framework}, a \emph{runtime} or, increasingly, a \emph{harness}, but the term has no shared definition, and published comparisons rarely separate the harness from the model.
We take the position that every LLM agent is a model wrapped in a harness, $\textit{Agent} = \textit{Harness}(\textit{Model})$, and that every harness, however large, is built from the same five primitives: \prim{Input}, which captures what comes in; \prim{Context}, which assembles what the model is shown; \prim{Model interface}, which requests a response from the model; \prim{Output}, which carries the response out; and \prim{Control flow}, which decides whether to go again, hand back, or stop. We argue that each primitive is necessary, by showing the specific failure of an agent built without it, and that together they are sufficient to express the agents in common use. We then suggest how the concerns of production use (persistence, safety and security, observability, resilience, performance and evaluation) fold into these primitives rather than standing beside them. In a case study, we map widely used harnesses, from command-line coding agents to research systems and agent frameworks, onto the five primitives, and argue that the differences between them are implementation decisions within each primitive, not differences in kind. We close with what this view implies for how agents are built, compared, and trained.
\end{abstract}
