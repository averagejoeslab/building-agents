# Google Agent Development Kit (Python)

**Source:** https://github.com/google/adk-python · **Version:** commit f78149a97e109e9c947ade06e3a9ab8a45385e0e (2026-10-15) · **Language:** Python
**Path conventions:** `adk/` = `src/google/adk/`; `fl/` = `src/google/adk/flows/llm_flows/`. All paths relative to the repo root.
**What it is:** ADK is Google's framework for building agents as a tree of `BaseAgent`s (an `LlmAgent` with tools and sub-agents, plus `SequentialAgent`, `ParallelAgent`, `LoopAgent` workflow agents) executed by a `Runner` over a `Session` of `Event`s held by a session service. The canonical agent is an `LlmAgent` with `FunctionTool`s run by `Runner.run_async`. The model is reached through `BaseLlm` adapters: `Gemini` over the `google-genai` client (Gemini API or Vertex AI), with Claude (`AnthropicLlm`) and LiteLLM providers resolved by model name.

## Control flow
- **Runner loop:** `Runner.run_async` gets or creates the session, appends the user event, picks `agent_to_run` (`_find_agent_to_run`: the agent whose pending function call the message answers, else the last-replying transferable `LlmAgent`, else root), then iterates `active_agent.run_async(ctx)` inside `_exec_with_plugin`, appending every non-partial event to the session, and runs post-invocation compaction. `adk/runners.py:L1124–L1136`, `adk/runners.py:L1190–L1215`, `adk/runners.py:L1336–L1370`, `adk/runners.py:L1815–L1846`, `adk/runners.py:L1531–L1557`
- **Flow loop and stop rule:** `BaseLlmFlow.run_async` runs `while True: _run_one_step_async` (request processors, one model call, response processors, function calls) and breaks when the step's last event `is_final_response()` (no function calls or responses, not partial, or a long-running tool id) or the context is aborted or `end_invocation` is set. `fl/base_llm_flow.py:L332–L353`, `fl/base_llm_flow.py:L377–L450`; `adk/events/event.py:L286–L309`
- **Budgets:** `increment_llm_call_count` runs before every model call and raises `LlmCallsLimitExceededError` once calls exceed `RunConfig.max_llm_calls` (default read from `ADK_MAX_LLM_CALLS`); `LoopAgent.max_iterations` bounds workflow loops, and an `escalate` action exits them. `fl/core/_model_call.py:L227`; `adk/agents/invocation_context.py:L63–L96`, `adk/agents/invocation_context.py:L596–L609`; `adk/agents/run_config.py:L41–L45`, `adk/agents/run_config.py:L264–L282`; `adk/agents/loop_agent.py:L92–L130`
- **Gates the harness consumes:** plugin then agent `before_model_callback`/`before_tool_callback` may return a replacement and short-circuit (first non-None wins); a tool whose `check_require_confirmation` is true emits an `adk_request_confirmation` long-running call that pauses the invocation until a `ToolConfirmation` function response arrives, which the confirmation request processor replays. `fl/core/_finalizer.py:L150–L195`; `adk/plugins/plugin_manager.py:L277–L325`; `adk/tools/function_tool.py:L404–L430`; `fl/tools/_confirmation.py:L259–L300`; `adk/agents/invocation_context.py:L745–L770`
- **Sub-agents:** `AutoFlow` adds a `transfer_to_agent` tool and instructions listing peers and parent; the tool sets `actions.transfer_to_agent` and the postprocessor runs the target's `run_async` in the same invocation and session; `AgentTool` instead spawns a nested `Runner` with in-memory services and returns its last text as a tool result; `SequentialAgent`, `ParallelAgent` (one `TaskGroup` task and branch per child) and `LoopAgent` sequence children without a model. `fl/extensions/_agent_transfer.py:L44–L98`; `fl/core/_function_call_postprocessor.py:L72–L140`; `adk/tools/agent_tool.py:L224–L300`; `adk/agents/parallel_agent.py:L134–L136`, `adk/agents/parallel_agent.py:L176–L200`; `adk/agents/sequential_agent.py:L96–L130`

## Input
- **User message:** `run_async(user_id, session_id, new_message: types.Content, state_delta, run_config)`; the message becomes an `Event(author='user')` appended through `session_service.append_event`, with input blobs optionally saved as artifacts. `adk/runners.py:L1124–L1136`, `adk/runners.py:L705–L735`, `adk/runners.py:L1667–L1700`
- **Tool results re-enter:** `_build_response_event` wraps each tool result as a function-response `Event`; parallel results are merged into one event by `merge_parallel_function_response_events`; the event is yielded, appended to the session, and rebuilt into `contents` by the next step's content processor. `fl/tools/_caller.py:L321–L360`; `fl/tools/_batch_executor.py:L61–L118`, `fl/tools/_batch_executor.py:L146–L170`
- **Answers the model consumes:** `request_input` and `get_user_choice` are long-running tools that pause the invocation; the user's function response arrives as the next `new_message` and `_find_agent_to_run` routes it to the agent that asked. `adk/tools/_request_input_tool.py:L27–L56`; `adk/tools/get_user_choice_tool.py:L23`; `adk/runners.py:L1815–L1846`
- **Resume input:** for a resumable app, `run_async` with an `invocation_id` and no message resumes the paused invocation from stored events. `adk/runners.py:L1254–L1300`; `adk/apps/_configs.py:L29–L48`

## Context
- **Ordered request processors:** `SingleFlow` assembles one `LlmRequest` (model, `contents`, `GenerateContentConfig`, `tools_dict`) by running basic, auth, request_confirmation, instructions, identity, compaction, interactions, contents, context_cache, planning, code_execution and output_schema processors in that order. `fl/single_flow.py:L42–L80`; `fl/base_llm_flow.py:L451–L485`; `adk/models/llm_request.py:L52–L95`
- **Instructions:** `_build_instructions` appends the root `global_instruction`, the agent's `static_instruction`, and `instruction` (string or `InstructionProvider`, with `{state_key}` injection from session state) as system instruction, fencing dynamic text between begin/end markers. `fl/prompt/_instructions.py:L69–L160`; `adk/agents/llm_agent.py:L327–L354`, `adk/agents/llm_agent.py:L824–L860`
- **Conversation:** `_ContentLlmRequestProcessor` rebuilds `contents` from session events filtered by branch and visibility (`include_contents='default'`) or only the current turn (`'none'`), rearranging function responses and dropping orphans; `_maybe_append_user_content` guarantees a trailing user turn. `fl/context/_contents.py:L116–L200`, `fl/context/_contents.py:L473–L640`; `adk/models/base_llm.py:L234–L275`
- **Memory:** `BaseMemoryService.search_memory` (in-memory, Vertex AI Memory Bank, Vertex RAG) is reached by `PreloadMemoryTool.process_llm_request`, which injects past conversations into the instructions, or by the `load_memory` function tool. `adk/memory/base_memory_service.py:L44–L141`; `adk/tools/preload_memory_tool.py:L33–L75`; `adk/tools/load_memory_tool.py:L38–L60`
- **Window fitting:** `EventsCompactionConfig` (sliding-window `compaction_interval`/`overlap_size` after an invocation, `token_threshold` at request time) summarizes events with `LlmEventSummarizer` into a compaction event that `_process_compaction_events` substitutes for raw events; `ContextFilterPlugin` keeps the last N invocations; `ContextCacheConfig` enables Gemini context caching. `adk/apps/_configs.py:L50–L85`; `adk/apps/compaction.py:L675–L800`; `adk/apps/llm_event_summarizer.py:L29–L160`; `fl/context/_compaction.py:L33–L100`; `adk/plugins/context_filter_plugin.py:L101–L120`; `fl/context/_cache.py:L36–L80`

## Model interface
- **Client:** `BaseLlm.generate_content_async(llm_request, stream)` is an async generator of `LlmResponse`; `Gemini` calls `genai.Client().aio.models.generate_content` or `generate_content_stream` (or the Interactions API); `LLMRegistry.resolve` picks the adapter class by model-name regex (Gemini, `AnthropicLlm` for `claude-*`, `LiteLlm` for other providers). `adk/models/base_llm.py:L132–L160`; `adk/models/google_llm.py:L99`, `adk/models/google_llm.py:L228–L383`; `adk/models/registry.py:L62–L84`, `adk/models/registry.py:L147–L200`; `adk/models/anthropic_llm.py:L1099`; `adk/models/lite_llm.py:L3679`
- **Streaming:** `call_llm_async` passes `stream=True` when `RunConfig.streaming_mode` is `SSE` and yields partial `LlmResponse`s as partial events, running `after_model_callback` on the final one. `fl/core/_model_call.py:L170–L310`; `adk/agents/run_config.py:L145`
- **Retries and fallback:** `Gemini.retry_options` (`types.HttpRetryOptions`) is handed to the SDK's `HttpOptions`; `FallbackModel` tries each listed model in turn on retriable status codes (429 and friends) unless a response was already yielded; `ReflectAndRetryModelPlugin` feeds model errors back as guidance. `adk/models/google_llm.py:L190–L205`, `adk/models/google_llm.py:L427–L462`; `adk/models/_fallback_model.py:L207–L260`, `adk/models/_fallback_model.py:L352–L410`; `adk/plugins/_reflect_retry_model_plugin.py:L36–L70`
- **Tool-call format:** each `BaseTool.process_llm_request` registers a `FunctionDeclaration` on `GenerateContentConfig.tools` and itself in `tools_dict`; responses carry `types.FunctionCall` parts that the postprocessor dispatches by name. `adk/tools/base_tool.py:L144–L200`; `adk/tools/function_tool.py:L118–L150`

## Output
- **Tool set:** `BaseTool` subclasses: `FunctionTool` (declaration generated from a Python callable, argument validation, optional confirmation), `LongRunningFunctionTool`, `AgentTool`, MCP, OpenAPI and toolsets, plus Google-hosted search, code execution and data tools. `adk/tools/base_tool.py:L57–L200`; `adk/tools/function_tool.py:L76–L150`, `adk/tools/function_tool.py:L370–L453`
- **Executor and parallelism:** `handle_function_call_list_async` prepares one `asyncio.Task` per function call and executes them concurrently, wrapping `tool.run_async(args, tool_context)` with plugin and agent before/after tool callbacks and an `execute_tool` span, then merges the responses into one event. `fl/tools/_batch_executor.py:L215–L250`, `fl/tools/_batch_executor.py:L384–L404`; `fl/tools/_caller.py:L471–L640`, `fl/tools/_caller.py:L663–L671`
- **Code execution:** an agent's `code_executor` runs model-written code via `BuiltInCodeExecutor` (inside Gemini), `UnsafeLocalCodeExecutor` (`exec` in process), `ContainerCodeExecutor` (Docker image), or GKE, Vertex and Agent Engine sandboxes; request and response processors extract code blocks and feed results back. `adk/code_executors/built_in_code_executor.py:L31`; `adk/code_executors/unsafe_local_code_executor.py:L120`; `adk/code_executors/container_code_executor.py:L126–L240`; `fl/extensions/_code_execution.py:L146–L190`
- **Result presentation:** every step is yielded to the caller as an `Event` (an `LlmResponse` with author, `actions`, `partial`), and `is_final_response()` marks the user-facing answer; `output_key` writes the final text into session state. `adk/events/event.py:L87–L160`, `adk/events/event.py:L286–L309`; `adk/agents/llm_agent.py:L1093–L1120`
- **Tool effects as actions:** `EventActions` carries `state_delta`, `artifact_delta`, `transfer_to_agent`, `escalate`, `requested_tool_confirmations` and `end_of_agent`, which the session service and loops apply. `adk/events/event_actions.py:L78–L204`

## Hard to place
- **`transfer_to_agent`:** a tool call (output) whose effect is control flow, but the target runs inside the same invocation, session and event stream, so the "inner agent" is not a separate harness; transfer depth is unbounded via peer and parent hops. `fl/core/_function_call_postprocessor.py:L72–L140`
- **Agent routing by history:** `_find_agent_to_run` decides control flow by reading the session's events (context) rather than from the loop's own state. `adk/runners.py:L1815–L1846`
- **Plugins and callbacks are bundles:** a `before_model_callback` returning content both skips the model call (control flow) and stands in for the response (model interface); a `before_tool_callback` can replace a tool result (output); each resolved by function. `adk/plugins/base_plugin.py:L41–L105`; `fl/core/_finalizer.py:L150–L195`
- **Hosted execution:** `BuiltInCodeExecutor` and Google-hosted tools run inside Gemini; the harness declares them (context) and never executes (output). `adk/code_executors/built_in_code_executor.py:L31`
- **`output_key` into state:** model text is written to session state (persistence) and read back by `{key}` instruction injection, so an output effect feeds the next context. `adk/agents/llm_agent.py:L1093–L1120`; `fl/prompt/_instructions.py:L85–L95`

## Summary
| Primitive | Design decision |
|---|---|
| Input | types.Content user message appended as an Event; tool results and HITL answers re-enter as function-response events |
| Context | Ordered request processors rebuild LlmRequest from session events each step; instructions, memory tool, compaction, caching |
| Model interface | BaseLlm adapters resolved by model name; Gemini via google-genai; SSE streaming; SDK retries; FallbackModel |
| Output | BaseTool subclasses run concurrently as asyncio tasks with callbacks; code executors from in-process to Docker |
| Control flow | Runner picks agent, flow loops until final response; max_llm_calls; confirmation pauses; transfers run sub-agents in place |
