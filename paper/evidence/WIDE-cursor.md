# Cursor Agent

**Source:** https://cursor.com/docs (official docs; source not published) · **Version:** documentation as of 2026-10-16 · **Language:** not documented
**Path conventions:** `D` = https://cursor.com/docs (https://docs.cursor.com now returns a 308 redirect to `D`); every citation is `D/page § Section heading` and was read on 2026-10-16. Where a page states what happens but not how, I write "not documented".
**What it is:** Cursor's Agent is the agentic coding harness inside the Cursor editor (sidepane), the Agents Window, the `agent` CLI and Cloud Agents, made by Anysphere (Cursor). The docs say an agent "is built on three components": instructions (system prompt and rules), tools and the model you choose, with instructions and tools tuned per model (`D/agent/overview § How Agent works`). Requests go from the client to Cursor's backend and on to third-party providers (OpenAI, Anthropic, Google) or to inference providers hosting Cursor's own models (`D/enterprise/privacy-and-data-governance § 1. LLM requests`).

## Control flow
- **Core loop and budgets:** the agent plans, calls tools, observes results and repeats; "There is no limit on the number of tool calls Agent can make during a task"; the stop rule (a response without tool calls) is not documented; no turn or token budget flag exists in the CLI reference, so spend is capped only by account usage limits and spending caps. `D/agent/overview § How Agent works`, `§ Tools`; `D/cli/reference/parameters § Global options`; `D/models-and-pricing § Top-ups and spending caps`
- **Stop hook as loop extender:** the `stop` hook receives `status` (completed, aborted, error) and `loop_count` and may return `followup_message` to auto-submit the next user turn; `loop_limit` caps this at 5 by default (`null` = no limit). `D/hooks § Reference § Hook events § stop`, `§ Configuration § Per-Script Configuration Options`
- **Approval gates the harness consumes:** Run Modes govern shell, MCP and Fetch calls: Auto-review (allowlisted calls run, other shell commands run in the sandbox, the rest go to an LLM classifier on the Cursor backend, Gemini 3.5 Flash Lite with Haiku fallback), Allowlist (no classifier), Run Everything (no prompts); "When the classifier blocks a call, Cursor can try another approach", and if the agent still wants it the user gets an approval prompt; hook decisions merge as deny over ask over allow and exit code 2 blocks; Plan Mode writes nothing until the user clicks to build after clarifying questions, research, plan creation and review. `D/agent/security/run-modes § Pick a mode`, `§ How Auto-review works`; `D/hooks § Configuration`, `§ Hook Types § Command-Based Hooks`; `D/agent/plan-mode § How it works`
- **Sub-agent delegation and model keyed to work:** the agent delegates via the Task tool; each subagent "operates in its own context window" and returns a final message plus an agent ID for resumption; foreground blocks, background returns immediately; several Task calls in one message run in parallel; a subagent launched by a subagent "can't launch further ones" (depth 2); the Explore subagent "runs in its own context window with a faster model", custom subagents set `model: inherit` or a specific ID, and Cursor Router (Auto with Balance/Intelligence) runs a classifier on each request by task type and complexity to pick the model. `D/subagents § How subagents work § Foreground vs background`, `§ Using subagents § Parallel execution`, `§ FAQ § Can subagents launch other subagents?`, `§ Custom subagents § Model configuration`; `D/agent/tools/search § Explore subagent`; `D/cursor-router § How it works`
- **Outer harness (Projects):** a coordinator agent on Cloud Agents "doesn't write code itself"; it plans and delegates to agents "running as many in parallel as the work needs" and starts a local agent when something must run on the user's machine; `/goal` gives a long-lived objective and `/loop` reruns a prompt on an interval. `D/agent/projects § How a Project works`, `§ Cloud by default, local when needed`; `D/agent/overview § Goals with /goal`; `D/skills § Built-in Cursor skills`

## Input
- **Prompt capture:** the sidepane chat input (with `@` mentions, image and voice input), `agent "prompt"` in the CLI, and `agent -p` for scripts with `CURSOR_API_KEY`. `D/agent/prompting § @ mentions`, `§ Image input`; `D/cli/overview § Interactive mode`, `§ Non-interactive mode`; `D/cli/headless § Setup`
- **Mid-turn messages:** Enter queues a message until the task finishes; "Send now" or Enter twice delivers it "at the agent's next tool call instead of cutting off work mid-action"; in the CLI, Enter steers at a safe boundary and a second Enter interrupts the turn. `D/agent/overview § Queued messages`, `§ Steer a running agent`
- **Model-consumed answers:** the Ask questions tool asks clarifying questions and "the agent continues reading files, making edits, or running commands" while waiting; answers are incorporated when they arrive. `D/agent/overview § Tools § Ask questions`
- **Tool results and events re-enter the conversation:** tool results appear in the Conversation segment of the context window; for Cloud Agents, subscription events (Slack replies, PR comments, CI results) "land as follow-ups in the same conversation", and bursts wake the agent once. `D/agent/prompting § Context usage`; `D/cloud-agent/capabilities § Subscriptions`

## Context
- **Rules:** Project Rules (`.cursor/rules/*.mdc`), User Rules, Team Rules and `AGENTS.md`; "rule contents are included at the start of the model context"; `alwaysApply`, `globs` (auto-attach when a matching file is in context), `description` (agent decides, via the Fetch Rules tool) or @-mention only; files referenced from a rule are not inlined; precedence is Team, then Project, then User Rules; nested `AGENTS.md` combine with parents. `D/rules § How rules work`, `§ Project rules § Rule anatomy`, `§ Referencing files from a rule`, `§ Team Rules § Format and how Team Rules are applied`, `§ AGENTS.md § Nested AGENTS.md support`; `D/agent/overview § Tools § Fetch Rules`
- **Skills:** discovered from `.cursor/skills/`, `.agents/skills/` and compatibility folders; "The agent is presented with available skills and decides when they are relevant based on context" and resources load on demand; `paths` scopes a skill to files; a skill used as a Custom Mode "stays in context on every turn". `D/skills § How skills work`, `§ Skill directories`, `§ Scoping a skill to specific files`; `D/agent/prompting § Custom Modes`
- **Codebase retrieval:** Instant Grep "builds and queries its index on your machine" and Cursor "does not store embeddings of your codebase for search"; the agent gathers files through search and read tools, and "When Agent opens a match, that file content can still be included in the model request". `D/agent/tools/search § Instant Grep`, `§ Privacy and security`
- **Summarization and window accounting:** "When the window gets close to full, Cursor compresses older parts of the conversation into a summary"; the context ring breaks the prompt into System prompt, Tools, Rules, Skills, MCP, Subagents, Summarized conversation and Conversation; the CLI `/summarize` (alias `/compress`) frees space on demand; `preCompact` hook can show a message but cannot block compaction. `D/agent/prompting § Context usage`; `D/cli/using § Working with Agent § Selecting context`; `D/hooks § Reference § Hook events § preCompact`
- **Memory:** no native memories feature is documented; the nearest is Projects' "Shared context", a set of files synced across the cloud and local machines where agents store research, artifacts, codebase knowledge and preferences; side chats use the parent thread as hidden reference context; `postToolUse` and `sessionStart` hooks can inject `additional_context`. `D/agent/projects § Shared context`; `D/agent/overview § Side chats`; `D/hooks § Reference § Hook events § postToolUse`, `§ sessionStart`

## Model interface
- **Models and reach:** Claude, GPT, Gemini, Grok, Composer and others are selectable; "Models are hosted by the model provider, a trusted partner, or Cursor"; the client sends prompts and code context to Cursor and on to the provider; most models run under zero-data-retention agreements; BYOK API keys and custom base URLs are supported (not on Plus). `D/models-and-pricing § FAQ § Where are models hosted?`, `§ Plans`; `D/enterprise/privacy-and-data-governance § 1. LLM requests`, `§ Models with data retention`
- **Routing and fallback:** Auto has Cost, Balance and Intelligence modes served by Cursor Router; on Enterprise the router routes to an allowed model when one is blocked; "If a Fable request triggers a security guardrail, Cursor automatically routes it to Claude Opus"; a subagent's configured model falls back to a compatible one when blocked by an admin or plan. `D/models-and-pricing § Auto modes`; `D/cursor-router § How it works`; `D/enterprise/privacy-and-data-governance § Models with data retention`; `D/subagents § Custom subagents § Model configuration § When the configured model won't be used`
- **Context window limits:** Grok 4.7 defaults to 256k with long context to 500k at 2x above 256k; Claude 4.5+ models up to 1M at the same rate; GPT-5.x up to 1M with 2x input pricing; Max Mode (legacy plans) extends the window at API rate plus 20%. `D/models-and-pricing § Included usage § Cursor models`, `§ Third-party models § Model pricing`, `§ Legacy request-based pricing § Max Mode`
- **Streaming:** `--output-format stream-json` with `--stream-partial-output` streams text deltas; events are `system` (init with model), `assistant`, `tool_call` (started/completed) and `result` with `duration_ms`. `D/cli/headless § Example scripts § Real-time progress tracking`

## Output
- **Tool set:** Search files and folders, Web, Fetch Rules, Read files (including images for vision models), Edit files (applied automatically), Run shell commands, Browser, Image generation (saved to `assets/`), Ask questions; plus the Task tool for subagents. `D/agent/overview § Tools`; `D/subagents § Using subagents § Parallel execution`
- **Terminal execution:** "Cursor runs shell commands directly in your terminal" using the default terminal profile; `CURSOR_AGENT` is set in the shell; sudo passwords in the CLI go to `sudo` over a secure IPC channel and "the AI model never sees it". `D/agent/tools/terminal § Terminal`, `§ Troubleshooting § Disable heavy prompts for Cursor sessions`; `D/cli/overview § Sudo password prompting`
- **Sandboxing:** macOS uses Seatbelt through `sandbox-exec`; Linux uses Landlock and seccomp (kernel 6.2+, Bubblewrap as a reported fallback backend); network is "Blocked by default, then opened by your network mode" (sandbox.json Only, sandbox.json + Defaults, Allow All); `.git/config`, `.git/hooks`, `.vscode` and `.cursorignore` are protected; a command that fails on a sandbox restriction may be rerun outside the sandbox under classifier review. `D/agent/security/run-modes § Sandboxing § How sandboxing works on your platform`, `§ Network access`, `§ Sandbox configuration`
- **MCP:** servers configured in `.cursor/mcp.json` or `~/.cursor/mcp.json` over stdio, SSE or Streamable HTTP; "Cursor asks for approval before using MCP tools by default"; responses appear in chat with expandable arguments and results; prompts, resources and elicitation are supported; Cursor "isolates server failures to prevent one server from affecting others". `D/mcp § Installing MCP servers § Configuration locations`, `§ What is MCP? § How it works`, `§ Using MCP in chat § Tool approval`, `§ Tool response`, `§ FAQ § What happens if an MCP server crashes or times out?`
- **Result presentation and rollback:** edits save to disk immediately and are reviewed in chat or with Ctrl+R in the CLI; checkpoints snapshot modified files before significant changes and are "stored locally and separate from Git"; print mode emits text, json (`.result`) or stream-json. `D/agent/security § First-party tool calls`; `D/cli/using § Working with Agent § Review`; `D/agent/overview § Checkpoints`; `D/cli/headless § How it works § File modification in scripts`

## Production concerns
- **Persistence:** chat transcripts are searchable from a local index and resumable (`agent ls`, `agent resume`, `--continue`); checkpoints live locally; Projects' shared context syncs across machines (context); Cloud Agent conversation state is kept indefinitely by default and VM snapshots are deleted after 30 days of inactivity. `D/agent/overview § Conversation search`; `D/cli/overview § Sessions`; `D/agent/projects § Shared context`; `D/cloud-agent/security § What data is stored, where, and for how long`
- **Safety & security:** "By default, sensitive actions require your manual approval" (output and control flow); terminal commands need approval, config-file edits need approval, `.cursorignore` hides files, "All MCP connections need your approval", agents "cannot make arbitrary network requests with default settings"; Auto-review "is not a security boundary"; CLI permissions `Shell()`, `Read()`, `Write()`, `WebFetch()`, `Mcp()` with "Deny rules take precedence over allow rules"; Cloud Agents keep Runtime Secrets out of the transcript and the model, sign commits with an HSM-backed Ed25519 key and never merge without review. `D/agent/security § First-party tool calls`, `§ Third-party tool calls`, `§ Network requests`; `D/agent/security/run-modes § How Auto-review works § Auto-review is not a security boundary`; `D/cli/reference/permissions § Permission types`, `§ Pattern matching`; `D/cloud-agent/security § Autonomy and prompt injection`
- **Observability:** the context ring shows token use by category; hooks observe every event (`afterShellExecution`, `afterAgentThought`, `sessionEnd`) as spawned processes exchanging JSON over stdio; MCP Logs in the Output panel; Cloud Agent runs are logged, with audit logs streamable to a SIEM, webhook or S3. `D/agent/prompting § Context usage`; `D/hooks § Hook categories`; `D/mcp § FAQ § How do I debug MCP server issues?`; `D/cloud-agent/security § Auditability`
- **Resilience:** compaction when the window nears capacity; a failed subagent "returns an error status" and the parent can retry or resume it by agent ID; hooks fail open by default (`failClosed: false`) and a classifier-blocked call lets the agent "try another approach"; retry policy for failed model requests is not documented. `D/agent/prompting § Context usage`; `D/subagents § FAQ § What happens if a subagent fails?`; `D/hooks § Configuration § Per-Script Configuration Options`; `D/agent/security/run-modes § How Auto-review works`
- **Performance:** parallel subagents and the Explore subagent on a faster model; cache-read token pricing implies prompt caching but the mechanism is not documented; streaming deltas in the CLI; Cursor Router picks "the most cost-effective model"; "Requests are never downgraded in quality or speed". `D/subagents § Using subagents § Parallel execution`; `D/models-and-pricing § Third-party models § Model pricing`, `§ Top-ups and spending caps § What happens when I reach my limit?`; `D/cursor-router § How it works`
- **Evaluation:** not documented (no eval or test-suite material on any page read).

## Hard to place
- **Auto-review classifier:** a second model call that decides whether a tool call runs. By the rules it is control flow (an approval gate the harness consumes), but it also makes its own read-only tool calls (`ReadFile`, `Grep`, `Glob`, `ListDir`) on the machine, which is output of a nested mini-harness; placed under control flow with that note. `D/agent/security/run-modes § How Auto-review works`
- **Fetch Rules tool:** a tool call the model makes (output) whose only effect is to decide what the model is shown next (context); assigned by function to context, consistent with the rule that code inside a tool deciding what the model sees is context. `D/agent/overview § Tools § Fetch Rules`
- **Cloud Agents versus local Run Modes:** "Run Modes apply to local agents"; Cloud Agents auto-run commands on their own VM and never ask, so the approval gate is absent and replaced by egress controls and human PR review. Same harness family, different control flow per deployment. `D/agent/security/run-modes § Changelog § Cloud Agents do not use Run Modes`; `D/cloud-agent/security § Autonomy and prompt injection`
- **Sandbox rerun on failure:** the agent may rerun a sandbox-blocked command outside the sandbox with classifier review, mixing an output concern (sandbox) with a control-flow gate; resolved by treating the rerun as a new tool call under the gate. `D/agent/security/run-modes § Sandboxing`

## Summary
| Primitive | Design decision |
|---|---|
| Input | Chat or CLI prompt, queued or steered messages delivered at next tool call, Ask-questions tool answers mid-work |
| Context | Rules at prompt start, skills on demand, local grep search, compaction near capacity, no native memory |
| Model interface | Cursor backend to many providers, Auto routing by classifier, 256k to 1M windows, guardrail reroute |
| Output | Nine first-party tools plus MCP, Seatbelt or Landlock sandbox, network blocked by default, local checkpoints |
| Control flow | Unbounded tool loop, Run Mode gate with LLM classifier, two-level subagents, stop hook loops, coordinator Projects |
