# OpenHands

**Source:** https://github.com/All-Hands-AI/OpenHands · **Version:** commit aa593c72103862d4f1851988ecacd30f514368dc (2026-10-16) · **Language:** TypeScript (Agent Canvas UI) over Python (software-agent-sdk)
**Path conventions:** `ui/` = `src/` in OpenHands/OpenHands at the commit above. The agent loop, model client and tools no longer live in that repo; they live in https://github.com/OpenHands/software-agent-sdk, read at commit 5fa4dea24c52fe3ac53fa4e3e67a1376b72189e2 (2026-10-15): `sdk/` = `openhands-sdk/openhands/sdk/`, `tools/` = `openhands-tools/openhands/tools/`, `srv/` = `openhands-agent-server/openhands/agent_server/`, `sdkt/` = `tests/` in that repo.
**What it is:** OpenHands (All Hands AI / OpenHands org) is at this commit "Agent Canvas", a self-hosted React control center that starts conversations on an Agent Server over REST and WebSocket and can run the OpenHands agent or third-party ACP agents (Claude Code, Codex, Gemini CLI, Pi, OpenCode). The agent itself is the SDK's `Agent` driven by `LocalConversation`, which the Agent Server hosts locally, in Docker, on VMs or in OpenHands Cloud. The model is reached through `litellm` (chat completions or Responses API) with tenacity retries and profile-based fallbacks.

## Control flow
- **Run loop:** `LocalConversation._run` loops `while True` under the state lock: break on PAUSED/STUCK; on FINISHED break unless a Stop hook denies and injects feedback (then continue); stuck check; clear WAITING_FOR_CONFIRMATION; `agent.step()`; then break on WAITING_FOR_CONFIRMATION, on budget exceeded, or when `iteration >= max_iteration_per_run` (default 500). `sdk/conversation/impl/local_conversation.py:L1933–L2063`, `L221`
- **Stop rule inside a step:** a text-only response sets FINISHED ("awaits user input"); a FinishTool action sets FINISHED via `_ActionBatch.finalize` unless an iterative-refinement follow-up is injected; `send_message` after FINISHED/STUCK resets to IDLE so the next `run()` continues. `sdk/agent/response_dispatch.py:L259–L281`; `sdk/agent/agent.py:L381–L412`; `local_conversation.py:L1845–L1854`
- **Budgets and stuck detection:** `max_budget_per_run` compares accumulated cost across all LLMs (agent, condenser) and emits `MaxBudgetReached`; `StuckDetector` nudges once on an action-error streak, then marks STUCK on repeated action/observation, error, monologue, alternating or context-window-error patterns. `local_conversation.py:L727–L775`, `L2031–L2037`; `sdk/conversation/stuck_detector.py:L104–L155`
- **Approval gate:** `_requires_user_confirmation` runs the security analyzer on the batch (Finish/Think never require it), records a `SecurityAnalysisEvent`, and `confirmation_policy.should_confirm(risk)` (AlwaysConfirm, NeverConfirm, ConfirmRisky with HIGH threshold) sets WAITING_FOR_CONFIRMATION; the next `run()` executes the pending unmatched actions as implicit confirmation; Canvas posts accept/reject through `EventService.respondToConfirmation`; PreToolUse hooks block individual actions. `sdk/agent/agent.py:L1131–L1200`, `L707–L722`; `sdk/security/confirmation_policy.py:L43–L60`; `ui/hooks/mutation/use-respond-to-confirmation.ts:L12–L32`; `sdk/hooks/conversation_hooks.py:L127–L177`, `L355–L388`
- **Delegation and routing:** `DelegateExecutor` spawns one `LocalConversation` per sub-agent (persisted under the parent, inheriting MCP config, confirmation policy and `max_iteration_per_run`), runs delegated tasks in parallel threads and returns each agent's final response as the observation; Canvas's `launch_child_conversation` client tool starts an independent conversation (local worktree or cloud) whose result arrives later as a message; `classify_and_switch_llm` asks a classifier model and switches the LLM profile keyed to the task; `/plan` routes a message to a planner conversation. `tools/delegate/impl.py:L210–L245`, `L287–L365`, `L112–L131`; `ui/api/launch-child-conversation-client-tool.ts:L14–L20`, `L61–L108`; `sdk/tool/builtins/classify_and_switch_llm.py:L1–L10`, `L147–L195`; `ui/hooks/chat/use-plan-mode-interceptor.ts:L16–L29`, `L60–L85`

## Input
- **Canvas chat input:** `useSendMessage` turns the chat payload into `{role:"user", content:[text, image]}` and `AgentServerConversationService.sendMessage` posts it with `ConversationClient.sendEvent(..., {run: true})` to the Agent Server (per-conversation host and session key on cloud); events come back over a WebSocket with reconnect. `ui/hooks/use-send-message.ts:L13–L70`; `ui/api/conversation-service/agent-server-conversation-service.api.ts:L475–L510`; `ui/hooks/use-websocket.ts:L29–L64`, `L118–L145`
- **SDK message capture:** `send_message` wraps text into `MessageEvent(source="user")`, resets terminal states to IDLE, and attaches knowledge-skill content triggered by the message as `extended_content`; the loop deliberately does not break on FINISHED so a message sent concurrently is picked up on the next iteration. `local_conversation.py:L1823–L1886`, `L2019–L2030`
- **Tool results re-enter:** `_execute_action_event` runs one tool and returns `ObservationEvent` or, on `ValueError`, an `AgentErrorEvent` for self-correction; `_ActionBatch.emit` emits results in order after the batch. `sdk/agent/agent.py:L1499–L1559`, `L352–L380`
- **Harness-generated user messages:** stuck nudges, Stop-hook feedback, content-filter and malformed-tool-call corrections are injected as `role="user"` messages from `source="environment"` or `"user"`. `local_conversation.py:L759–L767`, `L1972–L1984`; `sdk/agent/agent.py:L798–L825`

## Context
- **System prompt:** `static_system_message` builds from a typed section registry preset (default or planning), or an inline `system_prompt` plus tool guidance, or a custom Jinja template; `AgentContext` contributes repo skills (`AGENTS.md`), knowledge skills, `system_message_suffix`, memory and secrets descriptions. `sdk/agent/base.py:L357–L393`, `L174–L204`, `L451–L500`; `sdk/context/agent_context.py:L56–L110`, `L265–L297`
- **Message assembly:** `prepare_llm_messages` takes the incrementally maintained `state.view`, lets the condenser return either a `View` or a `Condensation` event (which ends the step without a model call), then converts events to messages; images for non-vision models are swapped for references. `sdk/agent/utils.py:L581–L634`; `sdk/agent/agent.py:L742–L785`
- **Compaction:** `LLMSummarizingCondenser` condenses when token count exceeds the effective max (HARD), when events exceed `max_size` 240 (SOFT) or on request, keeps the first `keep_first` 2 events, and replaces forgotten events with an LLM-written summary. `sdk/context/condenser/llm_summarizing_condenser.py:L64–L70`, `L136–L204`, `L224–L276`
- **Overflow recovery:** `LLMContextWindowExceedError` or a malformed-history rejection emits `CondensationRequest` and returns to the loop, which condenses on the next step. `sdk/agent/agent.py:L826–L876`
- **Caching and truncation:** prompt-cache markers with `prompt_cache_retention`, retried without caching when the provider minimum is not met; terminal output is middle-truncated at `MAX_CMD_OUTPUT_SIZE` 30,000 chars with the full output saved to a file. `sdk/llm/llm.py:L602–L610`, `L1837–L1855`; `tools/terminal/definition.py:L192–L199`; `tools/terminal/constants.py:L18`; `sdk/utils/truncate.py:L50–L62`

## Model interface
- **Client:** `LLM.completion` resolves runtime metadata, formats messages and tools in `_prepare_completion_params`, and calls `litellm` (chat completions, or the Responses API via `responses`); non-native models get prompt-mocked tool calls through `NonNativeToolCallingMixin`. `sdk/llm/llm.py:L1752–L1816`, `L1415–L1445`, `L2011–L2040`; `sdk/llm/mixins/non_native_fc.py:L27–L80`
- **Retries:** tenacity `stop_after_attempt(num_retries=5)` with `wait_exponential(multiplier=8, min=8, max=64)` on `LLM_RETRY_EXCEPTIONS` (connection, 502, 429, 503, timeout, 500, no response) and transient HTTP errors, skipping quota exhaustion; a 401 refreshes the key and retries once. `sdk/llm/llm.py:L180–L188`, `L379–L382`, `L1141–L1160`, `L1856–L1867`; `sdk/llm/utils/retry_mixin.py:L77–L116`
- **Fallback:** after retries fail on a transient error, `FallbackStrategy.try_fallback` tries alternate LLM profiles in order (nested fallback disabled, metrics merged into the primary), and budget errors are never bypassed. `sdk/llm/fallback_strategy.py:L45–L131`; `sdk/llm/llm.py:L1014–L1038`
- **Streaming:** `stream` flag with an `on_token` callback and `stream_idle_timeout`; streaming is silently downgraded when no callback is wired; the agent opens a `StreamContext` per step. `sdk/llm/llm.py:L505–L512`, `L393–L400`, `L1789–L1800`; `sdk/agent/agent.py:L694–L705`

## Output
- **Tool set:** `openhands-tools` (terminal, file_editor, grep, glob, browser_use, task_tracker, delegate, planning_file_editor, apply_patch) plus MCP and skill tools; each `ToolDefinition` pairs an action schema with a `ToolExecutor` and declares resources for locking. `tools/terminal/definition.py:L185–L199`; `sdk/tool/tool.py:L283–L328`, `L347–L400`, `L529–L545`
- **Dispatch:** `_handle_tool_calls` converts each tool call into an `ActionEvent` (thought and reasoning attached to the first), then `_ActionBatch.prepare` truncates the batch at the first FinishAction, partitions hook-blocked actions and executes the rest. `sdk/agent/response_dispatch.py:L154–L201`; `sdk/agent/agent.py:L226–L306`, `L628–L656`
- **Parallelism:** `ParallelToolExecutor` runs a batch sequentially by default (`tool_concurrency_limit` 1) or in a `ThreadPoolExecutor` with per-resource locks when raised. `sdk/agent/parallel_executor.py:L51–L126`; `sdk/agent/base.py:L314–L322`; `sdk/agent/agent.py:L473–L475`
- **Sandbox:** tools run in the Agent Server's workspace, which can be the local machine or an ephemeral Docker/Kubernetes workspace; Canvas picks the backend (local, Docker, VM, cloud). `software-agent-sdk/README.md:L37–L38`; `README.md:L35–L41`; `srv/docker_runtime/__init__.py:L1`; `srv/docker_runtime/provisioning.py:L1–L20`
- **Presentation:** events are persisted then published to subscribers (visualizer prepended for terminal rendering); Canvas renders them from the WebSocket with per-tool visualizers and a confirmation prompt. `local_conversation.py:L432–L470`; `ui/components/features/chat/tool-visualizers/index.ts:L1–L20`

## Production concerns
- **Persistence:** `ConversationState` keeps events in an `EventLog` on a `FileStore` (one JSON file per event under a lock with a length marker) and autosaves `base_state.json`; a conversation resumes from `persistence_dir` and can be forked (context plus control flow state). `sdk/conversation/event_store.py:L34–L60`, `L188–L244`; `sdk/conversation/state.py:L233–L234`, `L429–L432`; `local_conversation.py:L353–L374`, `L409–L412`, `L804–L830`
- **Safety & security:** security analyzers (model-reported `security_risk`, defense-in-depth policy rails, Grayswan, ToolShield) feed confirmation policies (control flow); PreToolUse hooks block actions; `SecretRegistry` masks secrets in emitted events; sub-agent scope narrows tools; the Agent Server requires a session API key. `sdk/security/llm_analyzer.py:L10–L28`; `sdk/security/analyzer.py:L29–L60`; `sdk/security/defense_in_depth/policy_rails.py:L1–L40`; `sdk/subagent/scope.py:L38–L60`; `sdk/conversation/secret_registry.py:L24–L75`; `srv/credential_binding.py:L1–L30`
- **Observability:** `Telemetry.on_response` records latency, cost and tokens into `Metrics`, optionally logs each LLM call as JSON and annotates a span; Laminar `observe` spans wrap steps and tool executions; Canvas reports usage in a metrics modal. `sdk/llm/utils/telemetry.py:L190–L242`, `L401–L470`; `sdk/observability/laminar.py:L155–L234`, `L235–L260`; `sdk/agent/agent.py:L1527–L1537`
- **Resilience:** retries and fallback on the model call; condensation on overflow; stuck nudge; iteration and budget caps; event-log resume; `ConversationRunError` carries the persistence dir; Canvas WebSocket reconnects. `local_conversation.py:L2064–L2080`; `sdk/agent/agent.py:L826–L876`; `ui/hooks/use-websocket.ts:L118–L145`

## Hard to place
- **The repo is a shell:** at this commit OpenHands/OpenHands holds no loop, model client or tools; AGENTS.md assigns those to software-agent-sdk, and most of Canvas is UI framework and transport (out of scope), yet Canvas keeps control-flow pieces (plan-mode routing, child-conversation launch, confirmation answers, router-at-start). The harness is split across three repos and the primitives cross repo boundaries. `AGENTS.md:L30–L37`; `ui/api/conversation-service/agent-server-conversation-service.api.ts:L456–L470`
- **ACP agents:** `ACPAgent` drives a third-party agent (Claude Code, Codex, ...) through its own `step`; OpenHands' loop, persistence and confirmation then wrap another complete harness, which the multi-agent rule treats as an inner harness, although here it is a peer at depth 0 rather than a delegate. `sdk/agent/base.py:L1077–L1080`; `sdk/agent/acp_agent.py:L1718–L1730`, `L3952–L3960`
- **Model-predicted risk:** `add_security_risk_prediction=True` adds a `security_risk` field to every tool schema, so the approval gate (control flow) is fed by the model's own output rather than by the harness; by rule it is output whose effect is control flow. `sdk/agent/agent.py:L790–L795`; `sdk/security/llm_analyzer.py:L20–L28`
- **Condenser as loop step:** when the condenser returns a `Condensation`, the step emits it and returns without a model call, so a context operation spends one loop iteration; the stop-hook path likewise fabricates a user message to keep the loop going. `sdk/agent/agent.py:L748–L756`; `local_conversation.py:L1963–L1991`

## Summary
| Primitive | Design decision |
|---|---|
| Input | Canvas posts user events to an Agent Server; SDK wraps them as MessageEvents; tool results are ObservationEvents |
| Context | Section-registry system prompt with AGENTS.md skills; event view condensed by LLM summary on token or size limit |
| Model interface | litellm chat or Responses API; 5 exponential retries; profile fallbacks; optional token streaming |
| Output | Typed ToolDefinitions with executors in a local or Docker workspace; batch truncated at Finish; optional parallelism |
| Control flow | Status-machine loop with iteration and budget caps, stuck detector, risk-based confirmation, hooks, threaded delegation |
