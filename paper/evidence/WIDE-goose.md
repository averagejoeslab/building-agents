# Goose (Block)

**Source:** https://github.com/block/goose · **Version:** commit 5eca486214c86945ac6de2603ee27f51083822fb (2026-10-16) · **Language:** Rust
**Path conventions:** `g/` = `crates/goose/src/`; `sm/` = `crates/goose/src/agents/state_machine/`; `ga/` = `crates/goose-agent/src/`; `gp/` = `crates/goose-providers/src/`; `gpt/` = `crates/goose-provider-types/src/`; `cli/` = `crates/goose-cli/src/`. All paths relative to the repo root.
**What it is:** Goose is an open-source general-purpose agent started by Block and now attributed to the Agentic AI Foundation, with a CLI, a desktop app and a server sharing one Rust core. Each user message runs an ordered state machine of "operations" over a persisted SQLite conversation, with a single inference step at the end of the order. The model is reached through a `Provider` trait with many HTTP implementations (Anthropic, OpenAI, Google, Bedrock, Ollama, ...) and some ACP/CLI-wrapper providers that run their own tool loop.

## Control flow
- **State machine loop:** `build_state_machine` orders operations (slash command, tool approval, skills, recipe, tool execution, remaining tool calls, subagent, steer, bang shell, compaction, tool-pair compaction, doctor, project, retry, empty response, stop hook, exit on error, max turns) and appends the `Inference` step; `StateMachine::step` runs the first applicable operation and returns `Continuing`, or `Yielded` when none applies, and `run` repeats load-step-apply until a yield or cancel. `g/agents/state_machine_builder.rs:L43–L136`; `ga/machine.rs:L121–L190`, `L211–L226`
- **Go-again rule:** inference applies only when the projected conversation ends with a provider turn (`should_infer`) and there is no trailing error; after tool results are appended the next step infers again, and a plain assistant reply leaves nothing applicable, so the turn ends. `ga/inference.rs:L277–L286`, `L377–L403`
- **Budgets:** `MaxTurnsOperation` ends the turn with a fixed message once assistant turns since kickoff reach `max_turns` (session config, `GOOSE_MAX_TURNS`, default 1000) and advertises a `<turn-budget>` part after half is used; `ExitOnErrorOperation` yields on a trailing error. `sm/ops_maxturns.rs:L14–L67`; `g/agents/agent.rs:L52`, `L565–L569`; `sm/ops_exit_on_error.rs:L21–L32`
- **Approval gate:** `ToolApprovalOperation` (skipped in `Chat` mode) runs tool inspectors, marks denied requests non-executable and emits `ActionRequired` confirmation messages; `stream_state_machine_turn` waits for all confirmation answers, then re-runs the machine; modes are `Auto`, `Approve`, `SmartApprove`, `Chat`. `sm/ops_tool_approval.rs:L43–L148`; `g/agents/agent.rs:L793–L837`; `gpt/goose_mode.rs:L22–L32`
- **Stop hook, steering, sub-agents:** `StopHookOperation` lets a plugin deny ending the turn up to `stop_hook_block_cap` times; `SteerOperation` drains queued user messages between model and tool turns; `SubagentOperation` with `ForegroundSubagentRunner` runs a delegated `SubAgent` session (own recipe, max_turns and provider) through `stream_subagent_turn` and delivers its outcome back as a message. `sm/ops_stop_hook.rs:L80–L119`; `sm/ops_steer.rs:L60–L97`; `g/agents/subagent_handler.rs:L35–L82`, `L102–L130`; `g/agents/platform_extensions/summon.rs:L396–L421`, `L460–L470`

## Input
- **User message:** `Agent::reply` → `reply_impl` → `reply_with_state_machine_inner`, which persists the message with `session_manager.add_message` before the machine runs; the CLI calls `agent.reply` per prompt. `g/agents/agent.rs:L953–L1035`, `L637–L660`; `cli/session/mod.rs:L1333–L1340`
- **Mid-turn messages:** `Agent::steer` pushes into a per-session queue that `SteerOperation` consumes; a message carrying an `ElicitationResponse` completes a pending MCP elicitation instead of starting a turn. `g/agents/agent.rs:L293–L302`, `L996–L1031`
- **Tool results:** executed, declined and unparseable requests are recorded into one user message of tool responses, emitted and persisted as an `AppendMessage` effect. `sm/ops_toolcalling.rs:L1044–L1100`; `sm/session.rs:L52–L56`

## Context
- **System prompt:** `PromptManager::build_system_prompt` renders `system.md` (extension list and instructions, mode, date) or a session `system_prompt_override`, then appends hints and per-operation `prompt_parts`; inference tools are gathered from every operation. `g/agents/prompt_manager.rs:L114–L160`, `L201–L213`; `g/prompts/system.md:L1–L30`; `sm/inference_preparation.rs:L40–L90`; `ga/machine.rs:L143–L155`
- **Project files:** `.goosehints` and `AGENTS.md` (configurable `CONTEXT_FILE_NAMES`) are loaded from the global config dir and the working directory. `g/hints/load_hints.rs:L10–L21`, `L232–L252`
- **Per-turn context event:** a `<turn-context>` user-role message with working dir, context limit and operation `moim_parts` (such as the turn budget) is appended to the request when it changed. `g/agents/moim.rs:L92–L122`; `sm/ops_maxturns.rs:L20–L28`
- **Compaction:** `CompactionOperation` fires when tokens/context_limit exceeds the threshold (default 0.8, lowered so compaction starts by 225k tokens) or reactively after a `ContextLengthExceeded` error (at most 2), summarizes with the provider via `compact_messages` and replaces the conversation; `ToolPairCompactionOperation` summarizes old tool pairs past a cutoff; providers that manage their own context skip both. `sm/ops_compaction.rs:L24`, `L192–L294`; `g/context_mgmt/mod.rs:L25–L42`, `L87`; `crates/goose-context-management/src/lib.rs:L32`; `sm/ops_tool_pair_compaction.rs:L65–L83`
- **Request projection and caching:** before sending, only agent-visible messages are kept, the conversation is repaired and consecutive messages merged; the Anthropic format sets `cache_control: ephemeral` on the request. `ga/inference.rs:L434–L439`; `g/agents/reply_parts.rs:L293–L306`; `gpt/formats/anthropic.rs:L126–L134`

## Model interface
- **Provider trait:** `stream` is the one required method, `complete` collects the stream, and `retry_config` is overridable; concrete providers are built from `ProviderDef::from_env`. `gpt/base.rs:L520–L565`; `g/providers/base.rs:L31–L68`
- **HTTP client and streaming:** the Anthropic provider POSTs `v1/messages` through `with_retry`, decodes SSE lines into a message stream, and retries once with thinking history stripped if the API rejects replayed thinking blocks; default timeouts are 600s per request and 30s connect. `gp/anthropic.rs:L184–L262`, `L434–L449`; `gp/api_client.rs:L19–L20`
- **Retry policy:** `RetryConfig` defaults to 3 retries with 1s initial delay, x2 backoff, 30s cap, retrying rate-limit, server and network errors and honoring a server `retry_delay`. `gpt/retry.rs:L14–L17`, `L107–L157`
- **Stream consumption:** `InferenceRunner::infer` calls `provider.stream`, records usage per chunk, tags assistant chunks with provider/model metadata, drops duplicate tool requests, and retries an empty response up to 3 times; provider errors become error messages in the conversation; no backup model was found. `ga/inference.rs:L77`, `L443–L520`; `g/agents/reply_parts.rs:L282–L352`

## Output
- **Tool set:** every tool is an MCP extension reached through an `ExtensionLease`: builtin platform extensions (developer shell/editor, summon with `delegate`, code execution, skills) and external stdio/HTTP MCP servers. `sm/ops_toolcalling.rs:L841–L848`; `g/agents/extension_manager/builtin.rs:L12–L26`; `g/agents/platform_extensions/developer/shell.rs:L229–L245`
- **Executor and parallelism:** `ToolExecutionOperation::run` dispatches each executable request (pre-tool hooks, `lease.call`, post-tool hooks) and merges the result streams with `select_all`, so calls from one response run concurrently and finish in any order. `sm/ops_toolcalling.rs:L397–L470`, `L910–L944`, `L1010–L1100`
- **Sandbox:** a session may carry a Docker container id; builtin extensions are then started with `docker exec` inside it, otherwise tools run as host processes. `g/agents/container.rs:L3–L12`; `g/agents/extension_manager/builtin.rs:L19–L26`; `sm/ops_toolcalling.rs:L443`
- **Result size:** shell output is capped at 2000 lines / 50,000 bytes with the full output saved to a file, and any tool text over 200,000 chars (`GOOSE_MAX_TOOL_RESPONSE_SIZE`) is written to a temp file and replaced by a reference. `g/agents/platform_extensions/developer/shell.rs:L159–L164`; `g/agents/large_response_handler.rs:L5–L30`
- **Presentation:** events flow through an mpsc channel to the caller's stream; the CLI renders them through a streaming markdown buffer with MCP spinners. `g/agents/agent.rs:L862–L920`; `cli/session/mod.rs:L1342–L1344`

## Production concerns
- **Persistence:** context record: sessions and messages live in a SQLite `sessions.db` (WAL) under the data dir; every machine effect is applied through `SessionManager::apply_effects` and the machine reloads the session each step, so a turn can be resumed after a crash. `g/session/session_manager.rs:L34`, `L1066–L1080`; `sm/session.rs:L33–L79`; `g/agents/agent.rs:L712`
- **Safety & security:** control flow and output: Goose modes, a persisted tool permission store (`tool_permissions.json`), an LLM permission judge for read-only classification, a prompt-injection scanner (threshold 0.8) that forces approval, and shell hooks with a 30s default timeout. `g/permission/permission_store.rs:L45–L90`; `g/permission/permission_judge.rs:L145–L158`; `g/security/scanner.rs:L126–L130`; `g/security/security_inspector.rs:L29–L53`; `g/hooks/mod.rs:L43`, `L1031–L1040`
- **Observability:** tracing spans carry `gen_ai.*` attributes (usage, tool arguments, finish reasons), exported via OTLP, a Langfuse layer, and PostHog product telemetry. `g/agents/gen_ai_telemetry.rs:L52–L70`; `g/otel/otlp.rs:L75–L143`; `g/tracing/langfuse_layer.rs:L155–L157`; `g/posthog.rs:L17–L50`
- **Resilience:** model interface, context and control flow: provider retries, reactive compaction on context overflow, empty-response retries, recipe `RetryOperation` with success checks and an on-failure command, cancellation tokens checked between steps. `sm/ops_retry.rs:L227–L266`; `sm/ops_compaction.rs:L203–L218`; `ga/machine.rs:L159–L171`
- **Performance:** output and context: concurrent tool streams, streamed provider responses, prompt-cache headers, tool-pair summarization, session naming done by a background task. `g/agents/agent.rs:L662–L682`; `gpt/formats/anthropic.rs:L126–L134`
- **Evaluation:** `evals/harbor` runs terminal-bench-2 style benchmarks across models and builds; `goose-self-test.yaml` is a self-testing recipe; the state machine has its own test module. `evals/harbor/README.md:L1–L14`; `goose-self-test.yaml:L1–L12`; `sm/mod.rs:L36–L37`

## Hard to place
- **Toolshim:** for models without native tool calling, the text reply is sent to a separate interpreter model that extracts tool calls, and the system prompt is rewritten to ask for JSON; this is a second model call that produces the wire format, so it sits in the model interface with a context side effect, not a routing decision. `g/providers/toolshim.rs:L1–L12`; `g/agents/reply_parts.rs:L248–L257`
- **Permission judge:** an LLM classifies pending tool calls as read-only to auto-approve them; the decision is a harness-consumed approval (control flow) made by a model call. `g/permission/permission_judge.rs:L145–L158`
- **Operations as bundles:** every control-flow operation also contributes `prompt_parts`, `moim_parts` and `inference_tools` to the request, so one object mixes control flow, context and the tool set and must be decomposed per method. `ga/machine.rs:L143–L155`; `ga/operation.rs:L89–L139`
- **Providers that run their own loop:** `ProviderDef::RUNS_OWN_TOOL_LOOP` hands the session's MCP servers to an external agent (ACP/CLI wrappers), and `manages_own_context` disables compaction; output and control flow then live outside this harness, so it degrades to input plus a thin model interface. `g/providers/base.rs:L40–L42`; `g/agents/state_machine_builder.rs:L66`, `L89–L96`

## Summary
| Primitive | Design decision |
|---|---|
| Input | User message persisted first; steer queue and elicitation answers; tool results batched into one message |
| Context | Templated system prompt plus hints, per-turn context event, 0.8 threshold summarization, tool-pair summaries, prompt caching |
| Model interface | Provider trait with required stream; reqwest SSE; 3 retries exponential; empty-response retries; no backup model |
| Output | All tools are MCP extensions; concurrent select_all execution; optional Docker container; 50k/200k output spill |
| Control flow | Ordered operation pipeline with one inference step; 1000-turn cap; approval wait and rerun; stop hook; foreground sub-agents |
