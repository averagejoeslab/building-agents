# LangGraph (prebuilt ReAct agent on the Pregel runtime)

**Source:** https://github.com/langchain-ai/langgraph · **Version:** commit 5eb60aef6f3837a1fb632a8abc6cf8e8da81785b (2026-10-14; packages `langgraph` 1.2.15, `langgraph-prebuilt` 1.1.1, `langgraph-checkpoint`; the local clone holds this single squashed commit, so no file history is available) · **Language:** Python
**Path conventions:** `LG/` = `libs/langgraph/langgraph/`; `PB/` = `libs/prebuilt/langgraph/prebuilt/`; `CP/` = `libs/checkpoint/langgraph/`; `T/` = `libs/*/tests/`. "User-written" marks a decision the framework leaves to the person building the graph.
**What it is:** LangGraph (LangChain Inc.) is a framework for writing agent control flow as a graph of nodes over a shared, checkpointed state; the Pregel runtime executes the graph in bulk-synchronous supersteps. The canonical harness deconstructed here is `create_react_agent` (`PB/chat_agent_executor.py`): an `agent` node that calls a LangChain chat model and a `tools` node (`ToolNode`) that runs the model's tool calls, cycling until the model stops calling tools. The model is reached through a `langchain_core` `BaseChatModel` (`.invoke`/`.ainvoke`), which lives outside this repository; LangGraph itself contains no provider client.

## Control flow
- **ReAct loop shape (user-written graph, built by the prebuilt):** `agent` and `tools` nodes are added and the `tools` node's edge returns to the entrypoint, so the loop is an edge, not a `while`. `PB/chat_agent_executor.py:L867–L872`, `L985–L990`
- **Go again / stop decision:** `should_continue` reads the last message; no `tool_calls` → `END` (or `post_model_hook` / `generate_structured_response`), otherwise route to `tools`. `PB/chat_agent_executor.py:L831–L859`; attached as a conditional edge `L964–L968`
- **v2 fan-out, one task per tool call:** `should_continue` returns one `Send("tools", ToolCallWithContext(...))` per tool call, so each call becomes its own Pregel task. `PB/chat_agent_executor.py:L849–L859`; `Send` type `LG/types.py:L738–L826`
- **`return_direct` hand-back:** tools flagged `return_direct` end the loop after they run; `route_tool_responses` returns `END` when the newest ToolMessages came from such a tool. `PB/chat_agent_executor.py:L597`, `L970–L990`
- **post_model_hook router (user-written hook, framework routing):** after the hook, pending tool calls without ToolMessages are re-sent to `tools`; a trailing ToolMessage routes back to the entrypoint; else END/structured. `PB/chat_agent_executor.py:L919–L962`
- **Step budget inside the agent (`remaining_steps`):** a managed value computed as `scratchpad.stop - scratchpad.step`. `LG/managed/is_last_step.py:L18–L24`; `stop = step + recursion_limit + 1` `LG/pregel/_loop.py:L1858–L1859`; `_are_more_steps_needed` returns True when `< 2` steps remain and the response has tool calls `PB/chat_agent_executor.py:L620–L634`; the model's response is then replaced by an AIMessage "Sorry, need more steps to process this request." `L684–L694`
- **Recursion limit (runtime step budget):** `tick()` sets `status = "out_of_steps"` when `step > stop`. `LG/pregel/_loop.py:L640–L643`; `stream()` then raises `GraphRecursionError` `LG/pregel/main.py:L3093–L3102`; error class `LG/errors.py:L68–L88`; default `DEFAULT_RECURSION_LIMIT = int(getenv("LANGGRAPH_DEFAULT_RECURSION_LIMIT", "10007"))` `LG/_internal/_config.py:L32`
- **Pregel superstep loop:** `while loop.tick(): ... runner.tick(...) ... loop.after_tick()`; channel updates from step N are visible only in step N+1. `LG/pregel/main.py:L3050–L3079`
- **Natural stop:** the loop ends when `prepare_next_tasks` yields no tasks (`status = "done"`). `LG/pregel/_loop.py:L686–L689`
- **Which node runs next (the scheduler):** `prepare_next_tasks` first consumes pending `Send` packets from the reserved `TASKS` topic (PUSH tasks), then PULL tasks for nodes whose trigger channels were updated. `LG/pregel/_algo.py:L391–L512` (PUSH `L441–L465`, PULL `L489–L511`); a node triggers when a trigger channel's version exceeds the version it last saw `L1259–L1276`
- **Apply writes between steps:** `apply_writes` sorts tasks by path for determinism, records `versions_seen`, updates channels and bumps versions. `LG/pregel/_algo.py:L254–L258`, `L293–L344`
- **Conditional edges as routing-by-channel:** `add_conditional_edges` stores a `BranchSpec` `LG/graph/state.py:L982–L1030`; at run time `_route` reads fresh state, calls the user's path function, maps results through `path_map`, and writes to `branch:to:<node>` channels `LG/graph/_branch.py:L146–L167`, `L192–L225`; `attach_branch` installs the branch as a writer on the source node `LG/graph/state.py:L1577–L1624`; plain edges write the same way `L1551–L1575`; each node is triggered by its own `branch:to:` ephemeral channel `L1525–L1532`
- **`Command(goto=...)` from a node or tool:** `_control_branch` turns `goto` into TASKS (`Send`) or `branch:to:` writes; `Command.PARENT` raises `ParentCommand`. `LG/graph/state.py:L1749–L1775`; `ParentCommand` is bubbled to the parent graph by `run_with_retry` `LG/pregel/_retry.py:L618–L631`; the exception class `LG/errors.py:L130–L134`
- **Send packets are tasks of the next (or same) superstep:** `prepare_push_task_send` turns `TASKS[idx]` into a task for the named node `LG/pregel/_algo.py:L937–L996`; `accept_push` schedules pushes emitted mid-step `LG/pregel/_loop.py:L584–L621`; `TASKS` is a non-accumulating `Topic(Send)` `LG/pregel/main.py:L814–L819`
- **Static breakpoints (`interrupt_before`/`interrupt_after`):** `should_interrupt` returns tasks whose node is listed, if any channel changed since the last interrupt `LG/pregel/_algo.py:L156–L186`; checked before running tasks `LG/pregel/_loop.py:L696–L701` and after the step is checkpointed `L787–L792`; the prebuilt passes the user's lists straight to `compile` `PB/chat_agent_executor.py:L995–L1002`
- **Dynamic pause (`interrupt()`):** first call in a task raises `GraphInterrupt` carrying an `Interrupt` whose id hashes the task namespace `LG/types.py:L1038–L1046`; on re-run it returns the stored resume value instead `L1019–L1036`; `GraphInterrupt` `LG/errors.py:L103–L108`
- **Pause bookkeeping:** the runner saves the interrupt as an `INTERRUPT` pending write `LG/pregel/_runner.py:L586–L592`; at the root graph the exception is swallowed, state is emitted and the run returns `LG/pregel/_loop.py:L1491–L1530`
- **Resume (harness-consumed answer):** `Command(resume=...)` maps to a `RESUME` write `LG/pregel/_io.py:L56–L78`; `_first` requires a checkpointer and demands interrupt ids when several interrupts are pending `LG/pregel/_loop.py:L992–L1009`; the task scratchpad looks up its resume value `LG/pregel/_algo.py:L1279–L1344`; resume is inferred from `None` input or a `Command` `LG/pregel/_loop.py:L915–L928`
- **Approval gate is user-written:** the framework ships only the `HumanInterrupt`/`HumanResponse` shapes (`accept`/`ignore`/`response`/`edit`); no code in the harness consumes them. `PB/interrupt.py:L51–L84`, `L87–L105`
- **Model routing keyed to the work (user-written):** `model` may be a callable `(state, runtime) -> BaseChatModel` resolved on every `agent` step. `PB/chat_agent_executor.py:L563–L564`, `L599–L618`, `L674–L677`
- **Second model call for structured output:** after the loop ends, `generate_structured_response` runs as its own node. `PB/chat_agent_executor.py:L744–L767`, wiring `L899–L910`
- **Node concurrency within a superstep:** all ready tasks are submitted to the executor and awaited with `FIRST_COMPLETED`; the first non-interrupt failure cancels the rest. `LG/pregel/_runner.py:L259–L290`, `L618–L636`, `L652–L699`
- **Cooperative drain (operator stop):** `RunControl.request_drain()` is checked at the superstep boundary; the loop sets `status="draining"` and `stream()` raises `GraphDrained` after checkpointing. `LG/runtime.py:L79–L104`; `LG/pregel/_loop.py:L706–L708`; `LG/pregel/main.py:L3103–L3106`; `LG/errors.py:L55–L65`
- **Per-node error-handler nodes (user-written handler, framework routing):** `compile` assigns default/explicit handler nodes `LG/graph/state.py:L1290–L1344`; the runner reroutes a failed task to its handler instead of panicking `LG/pregel/_runner.py:L298–L324`
- **Sub-agents / subgraphs:** a compiled agent is used as a node of another graph via `name` `PB/chat_agent_executor.py:L466–L468`; nesting is detected by `CONFIG_KEY_TASK_ID` in config `LG/pregel/_loop.py:L351`; a child's `Command(graph=PARENT, goto=[Send...])` is bubbled and merged by `ToolNode` so a tool can hand work to the parent `PB/tool_node.py:L903–L927`. Results return as channel writes to the parent task; depth is unbounded (namespace `parent|child:task_id`).
- **`tools_condition` helper:** standalone routing function (`"tools"` or `"__end__"`) for user-built loops. `PB/tool_node.py:L1616–L1619`
- **Hook nodes (user-written):** `pre_model_hook` runs before every `agent` step, `post_model_hook` after it; both are ordinary nodes the user supplies. `PB/chat_agent_executor.py:L876–L881`, `L891–L896`

## Design decisions (one line each: the choice this harness made within a primitive)
- Input: everything (user message, tool result, resume value, external `Command(update)`) enters as a write to a named channel of a typed state, merged by a user-chosen reducer (`add_messages` upserts by message id).
- Context: the model sees exactly `state["messages"]` (optionally prefixed by one system message); fitting to the window is delegated entirely to a user-written `pre_model_hook`, with `REMOVE_ALL_MESSAGES` as the only built-in rewrite primitive.
- Model interface: no client of its own; a LangChain `BaseChatModel` is invoked once per `agent` node, with retries/timeouts expressed as per-node policies that are off by default.
- Output: `ToolNode` runs every tool call of a response concurrently in-process, converts results and (configurable) errors into `ToolMessage`s, and lets a tool return a `Command` to reach the scheduler.
- Control flow: the loop is a user-written graph executed as Pregel supersteps; "go again" is a conditional edge, "stop" is an empty task set or `recursion_limit`, pauses are exceptions persisted as checkpoint writes and resumed by re-running the node.

## Hard cases
- **Conditional edge `should_continue`:** user code, but it decides go-again vs. stop and is executed by the scheduler as a writer on the node; placed in control flow by function (rule: assign by function). Note the whole graph is user-authored control flow; the prebuilt merely authors it for you.
- **`remaining_steps` managed value:** it is injected into the node's *state* (so it looks like context), but no model ever sees it; `call_model` uses it to replace the model's answer with a canned message. Placed in control flow (step budget). Its side effect — a synthetic AIMessage written into the conversation — is a context effect of a control-flow decision.
- **`Send("tools", ToolCallWithContext(state=...))`:** a scheduling packet (control flow) that also carries a state snapshot (context) to the tool task. Split: the `Send` is control flow; the snapshot and `_extract_state` are context.
- **Tool returning `Command(goto=...)` or `Command(graph=PARENT)`:** the tool call is output; its effect is routing, so `_combine_tool_outputs` and `_control_branch` are control flow (rule: a tool's EFFECT is assigned to what it changes).
- **`interrupt()` inside a tool and `HumanResponse`:** the pause/resume machinery is control flow, but the harness never consumes an approval; the framework hands the raw resume value to user code in the tool, which decides whether to execute. So the approval gate is user-written, and the value is input only if the tool shows it to the model.
- **Dynamic model callable:** a model change keyed to state/context (planning vs execution) is control flow by the rules, but the selection logic is user-written; the framework only re-resolves it before each call. No failure-keyed fallback exists, so "backup model" is absent from the model-interface primitive.
- **Checkpointer as conversation memory:** the same mechanism that makes the loop resumable (persistence of control-flow state) is what makes a `thread_id` a chat history (persistence of context). Recorded once under persistence, spanning both primitives.
- **Pregel channel/version scheduler:** it is a general dataflow scheduler (nodes fire when subscribed channels change), not a loop with explicit go-again/hand-back/stop. It fits control flow, but the "shape of the loop" is emergent from edges and versions rather than coded; the only explicit stop conditions are "no tasks" and the step budget.
- **`DEFAULT_RECURSION_LIMIT = "10007"`:** the value found at this commit (`LG/_internal/_config.py:L32`) differs from the widely documented default of 25; the clone has a single squashed commit, so the change cannot be traced. Recorded as found, not interpreted.
- **Run `context` / `Runtime`:** operator-supplied static data that is neither a person's message nor a tool result; it is closest to configuration (out of scope) but is delivered on the request path to tools, so it is noted under Input without a strong claim.
- **Error-handler nodes and `wrap_tool_call`:** both are user-written code that the framework schedules; they are resilience mechanisms whose primitive depends on what the user's code does (a retry inside `wrap_tool_call` is output-side; an error handler that routes is control flow).
