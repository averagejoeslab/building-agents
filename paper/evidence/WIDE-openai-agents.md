# OpenAI Agents SDK (Python)

**Source:** https://github.com/openai/openai-agents-python · **Version:** commit 17d994bd3045dae71acda676a4ef4762ed8ecd94 (2026-10-15) · **Language:** Python
**Path conventions:** `a/` = `src/agents/`; `ri/` = `src/agents/run_internal/`; `m/` = `src/agents/models/`. All paths relative to the repo root.
**What it is:** The Agents SDK is OpenAI's library for building agents as `Agent` objects (instructions, tools, handoffs, guardrails) run by a `Runner` that loops model call, tool execution and handoff until a final output. The canonical shipped agent is an `Agent` with `@function_tool` tools run via `Runner.run`/`run_streamed`. The model is reached through the OpenAI Python SDK, by default the Responses API over HTTPS (optionally a Responses websocket), with Chat Completions, LiteLLM and any-llm providers selectable by model-name prefix.

## Control flow
- **Run loop:** `AgentRunner._run_impl` runs `while True`, calls `run_single_turn` once per iteration, then branches on `turn_result.next_step`: `NextStepRunAgain` continues, `NextStepFinalOutput` runs output guardrails and returns, `NextStepHandoff` swaps `current_agent` and loops, `NextStepInterruption` returns a result holding pending approvals. `a/run.py:L1032–L1062`, `a/run.py:L1331–L1372`, `a/run.py:L1543–L1552`; `ri/run_steps.py:L164–L190`
- **Stop rule and turn budget:** a response with no tool calls or handoffs is the final output; after tools ran, `check_for_final_output_from_tools` applies `Agent.tool_use_behavior` (`"run_llm_again"` default, `"stop_on_first_tool"`, a StopAtTools name list, or a callable); `current_turn += 1` and `MaxTurnsExceeded` once `current_turn > max_turns` (`DEFAULT_MAX_TURNS = 10`). `ri/turn_resolution.py:L776–L809`; `a/agent.py:L396–L418`; `a/run.py:L1597–L1606`; `a/run_config.py:L45`; `a/exceptions.py:L354–L363`
- **Guardrails the harness consumes:** input guardrails run on turn 0 only (sequential ones before the model call, parallel ones gathered with the model task), output guardrails run on the final output; a tripwire raises `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered` and ends the run. `a/run.py:L1046–L1062`, `a/run.py:L1833–L1845`; `ri/guardrails.py:L116–L170`, `ri/guardrails.py:L172–L225`; `a/guardrail.py:L72–L100`
- **Approval gate:** `function_needs_approval` evaluates `FunctionTool.needs_approval` before execution; unapproved calls become `ToolApprovalItem`s inside `NextStepInterruption`, the caller calls `RunState.approve`/`reject` and resumes by passing the `RunState` back as `input` to `Runner.run`. `ri/tool_execution.py:L1306–L1315`; `ri/run_steps.py:L179–L190`; `a/run_state.py:L1380–L1410`; `a/run.py:L279–L300`
- **Handoffs and sub-agents:** a `Handoff` is a function tool whose invocation returns the target `Agent`; `execute_handoffs` calls `on_invoke_handoff`, applies `input_filter` or `nest_handoff_history`, and returns `NextStepHandoff`, so the same loop continues with the new agent (one hop per turn, same run, same session); `Agent.as_tool` instead runs a nested `Runner.run` with its own `max_turns` and returns its output as a tool result. `a/handoffs/__init__.py:L126–L182`, `a/handoffs/__init__.py:L320–L350`; `ri/turn_resolution.py:L544–L600`, `ri/turn_resolution.py:L605–L690`; `a/agent.py:L606–L640`

## Input
- **Caller input:** `Runner.run(starting_agent, input, ...)` accepts a string, a list of Responses input items, or a `RunState` to resume; a string is normalized to one user message by `input_to_new_input_list`. `a/run.py:L279–L300`; `a/items.py:L813–L826`
- **Tool results re-enter:** each executed call becomes a `ToolCallOutputItem` (`function_call_output` keyed by `call_id`) in `generated_items`; `_prepare_turn_input_items` converts caller input plus generated items into the next turn's input list. `a/items.py:L431`, `a/items.py:L845–L860`; `ri/run_loop.py:L349–L358`
- **Session input:** `prepare_input_with_session` loads `session.get_items()` history and concatenates the new input (or lets `session_input_callback` merge them); with a server-managed conversation only the new items are prepared. `ri/session_persistence.py:L424–L510`; `a/run.py:L716–L745`
- **Streamed input events:** `run_streamed` puts each raw model event on an event queue as `RawResponsesStreamEvent` (receiving the stream is model interface; the queue is the harness's input side of rendering). `ri/run_loop.py:L2621–L2652`; `a/stream_events.py:L11–L60`

## Context
- **Instructions:** `Agent.get_system_prompt` returns the static `instructions` string or calls `instructions(context, agent)` (sync or async); `get_prompt` resolves a server-side prompt object; both are gathered at the start of `run_single_turn`. `a/agent.py:L1129–L1170`; `ri/run_loop.py:L2838–L2841`
- **Tool and handoff descriptions:** `get_all_tools` merges MCP server tools with function tools filtered by `is_enabled`; handoffs are listed as function tools; name collisions resolved per `tool_name_collision_policy`. `a/agent.py:L286–L316`; `ri/run_loop.py:L2836–L2850`
- **Per-call assembly and filter:** the request is instructions plus caller input plus all run items so far; `call_model_input_filter` may rewrite instructions and input, then items are de-duplicated before `get_model`. `ri/run_loop.py:L2946–L2956`; `ri/turn_preparation.py:L51–L95`
- **Session history and server-held conversations:** the `Session` protocol (`get_items`/`add_items`/`pop_item`) is implemented by `SQLiteSession`, SQLAlchemy/Redis/Mongo/Dapr/encrypted extensions, and `OpenAIConversationsSession`; with `conversation_id` or `previous_response_id`, `OpenAIServerConversationTracker.prepare_input` sends only new deltas and records the last `response_id`. `a/memory/session.py:L53–L95`; `a/memory/sqlite_session.py:L18–L60`; `a/memory/openai_conversations_session.py:L29–L60`; `ri/oai_conversation.py:L124–L140`, `ri/oai_conversation.py:L350–L393`
- **Window fitting:** `OpenAIResponsesCompactionSession` calls `responses.compact` after a write when at least 10 candidate items exist (default trigger); `ToolOutputTrimmer` replaces tool outputs over 500 chars from older turns with a preview; `model_settings.truncation="auto"` delegates truncation to the server. `a/memory/openai_responses_compaction_session.py:L68–L71`, `a/memory/openai_responses_compaction_session.py:L92–L170`; `ri/session_persistence.py:L713–L735`; `a/extensions/tool_output_trimmer.py:L88–L115`; `a/model_settings.py:L123`

## Model interface
- **Client:** the `Model` ABC exposes `get_response` and `stream_response`; `OpenAIResponsesModel` builds kwargs and calls `client.responses.create(**kwargs)` (or a Responses websocket), `OpenAIChatCompletionsModel` calls `chat.completions.create`; `MultiProvider` maps the model-name prefix (`openai/` or none, `litellm/`, `any-llm/`) to a `ModelProvider`. `m/interface.py:L37–L136`; `m/openai_responses.py:L513`, `m/openai_responses.py:L590–L640`, `m/openai_responses.py:L860–L900`; `m/openai_chatcompletions.py:L55`, `m/openai_chatcompletions.py:L742`; `m/multi_provider.py:L62–L75`, `m/multi_provider.py:L155–L200`; `ri/turn_preparation.py:L134–L145`
- **Retries and timeout:** `get_response_with_retry` wraps the call with `model_settings.retry` (`ModelRetrySettings` max_retries, backoff), provider advice from `get_openai_retry_advice` (honours Retry-After), exponential backoff with jitter, and `model_settings.timeout` raising `ModelTimeoutError`; a rewind hook restores session and tracker state before replay. `ri/run_loop.py:L3024–L3047`; `ri/model_retry.py:L175–L205`, `ri/model_retry.py:L389–L420`, `ri/model_retry.py:L574`; `a/retry.py:L210–L231`; `m/_openai_retry.py:L41–L112`; `a/model_settings.py:L188`, `a/model_settings.py:L215`
- **Streaming:** `stream_response_with_retry` consumes the provider's event stream and yields raw `TResponseStreamEvent`s, with usage added to `context_wrapper.usage` at the end. `ri/run_loop.py:L2621–L2652`; `m/openai_responses.py:L683–L720`; `ri/run_loop.py:L3065`

## Output
- **Tool set:** `FunctionTool` (name, description, JSON schema, `on_invoke_tool`, `strict_json_schema`, `needs_approval`, `timeout`, tool guardrails) built by `@function_tool`; hosted tools (`WebSearchTool`, `FileSearchTool`, `CodeInterpreterTool`, `HostedMCPTool`, `ImageGenerationTool`) run inside the provider; `ComputerTool`, `ShellTool`, `ApplyPatchTool`, `LocalShellTool` run locally. `a/tool.py:L455–L530`, `a/tool.py:L2621`, `a/tool.py:L815–L1300`
- **Response processing:** `process_model_response` sorts output items into function runs, handoffs, computer actions, shell and apply-patch calls, custom tools and MCP approval requests, then `execute_tools_and_side_effects` runs the plan. `ri/turn_resolution.py:L3133–L3175`, `ri/turn_resolution.py:L941–L990`
- **Executor and parallelism:** `_FunctionToolBatchExecutor` creates one `asyncio.Task` per function call, bounded by `tool_execution.max_function_tool_concurrency`, isolating sibling failures and applying per-tool timeouts. `ri/tool_execution.py:L1548–L1600`, `ri/tool_execution.py:L1648–L1670`, `ri/tool_execution.py:L2341–L2371`; `a/run_config.py:L143–L163`
- **Sandbox:** `SandboxAgent` plus `RunConfig(sandbox=...)` run shell, file and patch tools inside a `DockerSandboxSession` or a `UnixLocalSandboxSession` (asyncio subprocess with PTY). `a/sandbox/sandbox_agent.py:L31–L60`; `a/sandbox/sandboxes/docker.py:L287`; `a/sandbox/sandboxes/unix_local.py:L261`
- **Result presentation:** `RunResult.final_output` and `RunResultStreaming.stream_events()` (`RawResponsesStreamEvent`, `RunItemStreamEvent`, `AgentUpdatedStreamEvent`); shell outputs are truncated to `max_output_length` before being shown to the model. `a/result.py:L547`, `a/result.py:L660`, `a/result.py:L1005`; `a/stream_events.py:L11–L60`; `ri/tool_execution.py:L1008–L1047`

## Production concerns
- **Persistence:** context: session history written by `save_result_to_session` to any `Session` store (SQLite, SQLAlchemy, Redis, MongoDB, Dapr, encrypted wrapper, OpenAI Conversations); control flow: `RunState.to_json`/`from_json` serialize an interrupted run for resume after approvals. `ri/session_persistence.py:L778–L800`; `a/extensions/memory/sqlalchemy_session.py`; `a/run_state.py:L842`, `a/run_state.py:L1899`, `a/run_state.py:L2423`
- **Safety & security:** control flow: `needs_approval` gate and input/output guardrails; output: tool input/output guardrails with `allow`/`reject_content`/`raise_exception` behaviours, Docker sandbox for shell and patches, mount-credential redaction in errors; no prompt-injection fencing of tool output found. `a/tool_guardrails.py:L60–L118`; `a/guardrail.py:L72–L100`; `a/sandbox/_mount_security.py:L487–L511`

- **Resilience:** model interface: retry policy, timeout, request rewind; output: `ToolTimeoutError` per tool; control flow: `MaxTurnsExceeded` handler via run error handlers, resumable `RunState`, session item rewind on failed writes. `ri/model_retry.py:L574`; `a/exceptions.py:L387`, `a/exceptions.py:L417`; `a/run.py:L1628`; `ri/session_persistence.py:L1622`
- **Performance:** streaming, concurrent tool tasks, parallel guardrails gathered with the model call, `PromptCacheKeyResolver` deriving `prompt_cache_key` from session or group id, `prompt_cache_retention`, `ToolOutputTrimmer`. `ri/prompt_cache_key.py:L17–L90`; `a/model_settings.py:L150`; `a/run.py:L1841`

## Hard to place
- **Server-managed conversation:** with `conversation_id`/`previous_response_id` the provider keeps the transcript; the harness's context primitive only sends deltas and the provider does assembly, so part of Context lives outside the harness. `ri/oai_conversation.py:L518–L630`
- **Hosted tools:** `WebSearchTool`, `CodeInterpreterTool`, `HostedMCPTool` execute inside the provider during the model call; the harness declares them (context) and reads results from the response (model interface), with no local Output step. `a/tool.py:L853`, `a/tool.py:L1158`, `a/tool.py:L1189`
- **Server-side compaction:** `OpenAIResponsesCompactionSession` fits the window (context) by calling `responses.compact`, an extra provider request issued from a session write rather than from the loop. `a/memory/openai_responses_compaction_session.py:L92–L170`
- **`tool_use_behavior` callable:** lives on `Agent` and receives tool results (output) but decides whether to go again (control flow); assigned by function. `ri/turn_resolution.py:L776–L809`
- **Sandbox memory generation:** `SandboxMemoryGenerationManager` turns rollouts into memory for the model (context) by issuing its own model calls (control flow) outside the main loop. `a/sandbox/memory/manager.py:L43`

## Summary
| Primitive | Design decision |
|---|---|
| Input | String or Responses items plus Session history; tool outputs re-enter as run items; RunState resumes |
| Context | Instructions callable, tools and handoffs as functions, full item list; server compaction and trimmer |
| Model interface | OpenAI Responses API via SDK; prefix-routed providers; configurable retry, timeout, streaming |
| Output | Function tools as concurrent asyncio tasks; hosted tools; Docker or local sandbox for shell and patches |
| Control flow | NextStep loop with max_turns=10; guardrail tripwires; approval interruptions; handoffs swap agent in place |
