# AutoGen (agentchat AssistantAgent and its runtime)

**Source:** https://github.com/microsoft/autogen · **Version:** commit 027ecf0a379bcc1d09956d46d12d44a3ad9cee14 (2026-04-06) · **Language:** Python
**Path conventions:** `ac/` = `python/packages/autogen-agentchat/src/autogen_agentchat/`; `core/` = `python/packages/autogen-core/src/autogen_core/`; `ext/` = `python/packages/autogen-ext/src/autogen_ext/`; `t/` = `python/packages/autogen-agentchat/tests/`. All paths relative to the repo root.
**What it is:** AutoGen is Microsoft's layered agent framework: `autogen-core` is an actor-style message runtime, `autogen-agentchat` builds chat agents and teams on it, and `autogen-ext` supplies model clients, tools and code executors. `AssistantAgent` is the canonical tool-using agent; it reaches the model through a `ChatCompletionClient` (for example `OpenAIChatCompletionClient` over the `openai` SDK) and runs tools through a `Workbench`.

## Control flow
- **Per-turn tool loop:** `on_messages_stream` adds the incoming messages to the model context, queries memory, calls the model once, then `_process_model_result` loops `for loop_iteration in range(max_tool_iterations)`: a text response returns immediately; tool calls are executed, their results added to context, and another model call is made unless this is the last iteration. `ac/agents/_assistant_agent.py:L901–L1013`, `ac/agents/_assistant_agent.py:L1149–L1270`
- **Stop rule and budget:** `max_tool_iterations` (default 1) bounds the loop; after it the agent either reflects (one more model call without tools) or emits a `ToolCallSummaryMessage` built from a format string; `reflect_on_tool_use` defaults to true only when a structured output type is set. `ac/agents/_assistant_agent.py:L738–L739`, `ac/agents/_assistant_agent.py:L842–L853`, `ac/agents/_assistant_agent.py:L1302–L1325`
- **Handoff as early exit:** if any executed call was a handoff tool, `_check_and_handle_handoff` returns a `HandoffMessage` carrying the tool-call context and the loop returns; multi-agent delegation then happens in the team. `ac/agents/_assistant_agent.py:L1245–L1251`, `ac/agents/_assistant_agent.py:L1328–L1408`
- **Team sequencing:** `BaseGroupChat.run_stream` starts a `SingleThreadedAgentRuntime`, publishes `GroupChatStart`, and reads an output queue until a `GroupChatTermination`; the manager's `handle_agent_response` applies the `TerminationCondition` and `max_turns`, then `select_speaker` (round-robin: next index modulo participants) and publishes `GroupChatRequestPublish` to the chosen `ChatAgentContainer`. `ac/teams/_group_chat/_base_group_chat.py:L489–L558`, `ac/teams/_group_chat/_base_group_chat_manager.py:L135–L238`, `ac/teams/_group_chat/_round_robin_group_chat.py:L72–L82`
- **Core runtime loop:** `SingleThreadedAgentRuntime._process_next` pops one envelope from an asyncio queue, runs intervention handlers (`on_send`/`on_publish`, which may return `DropMessage`), and dispatches to the agent's handler. `core/_single_threaded_agent_runtime.py:L332–L385`, `core/_single_threaded_agent_runtime.py:L671–L720`

## Input
- **Task entry:** `BaseChatAgent.run` wraps a string task as `TextMessage(source="user")`, accepts a message or message list, and calls `on_messages`; in a team the container buffers messages from other agents and passes them to `on_messages_stream` when asked to speak. `ac/agents/_base_chat_agent.py:L111–L153`, `ac/teams/_group_chat/_chat_agent_container.py:L86–L144`
- **Tool results re-enter the context:** each executed call yields a `FunctionExecutionResult` (content, `is_error`) and the batch is added as one `FunctionExecutionResultMessage`; `HandoffMessage.context` carries the prior tool calls into the receiving agent. `ac/agents/_assistant_agent.py:L1236–L1240`, `ac/agents/_assistant_agent.py:L1014–L1026`
- **Human input:** `UserProxyAgent` calls `input_func` (default `cancellable_input` over `input()`) and returns the text as a `TextMessage`, emitting `UserInputRequestedEvent` first; the model consumes it as the next turn. `ac/agents/_user_proxy_agent.py:L22–L27`, `ac/agents/_user_proxy_agent.py:L165–L170`, `ac/agents/_user_proxy_agent.py:L186–L200`

## Context
- **System prompt:** a single `SystemMessage` from the `system_message` argument (default tells the model to use tools and reply TERMINATE); it is prepended to the context's messages at call time. `ac/agents/_assistant_agent.py:L735–L737`, `ac/agents/_assistant_agent.py:L770`, `ac/agents/_assistant_agent.py:L1085–L1086`
- **History as `ChatCompletionContext`:** the agent keeps an `UnboundedChatCompletionContext` by default; `get_messages` returns what the model sees, and `on_reset` clears it. `ac/agents/_assistant_agent.py:L840`, `core/model_context/_chat_completion_context.py:L10–L60`, `ac/agents/_assistant_agent.py:L1626–L1628`
- **Window fitting variants:** `BufferedChatCompletionContext` keeps the last `buffer_size` messages (dropping a leading function-result), `TokenLimitedChatCompletionContext` pops middle messages until `remaining_tokens` or `token_limit` is satisfied, `HeadAndTailChatCompletionContext` keeps the first and last N; no summarization is built in. `core/model_context/_buffered_chat_completion_context.py:L34–L41`, `core/model_context/_token_limited_chat_completion_context.py:L57–L75`, `core/model_context/_head_and_tail_chat_completion_context.py:L41–L60`
- **Memory injection:** each `Memory.update_context` may rewrite the model context before the call, and the agent yields a `MemoryQueryEvent` with the retrieved items. `ac/agents/_assistant_agent.py:L1028–L1055`, `core/memory/_base_memory.py:L60–L94`
- **Client compatibility pass:** `_get_compatible_context` strips images when `model_info["vision"]` is false. `ac/agents/_assistant_agent.py:L1642–L1648`, `ac/utils/_utils.py:L36`

## Model interface
- **`ChatCompletionClient` protocol:** `create`/`create_stream` take messages, tool schemas, `json_output` and a `CancellationToken`, and expose `count_tokens`, `remaining_tokens` and `model_info`. `core/models/_model_client.py:L209–L295`
- **OpenAI client:** `BaseOpenAIChatCompletionClient.create` validates create args, awaits `chat.completions.create` linked to the cancellation token, records `RequestUsage`, and maps `tool_calls` to `FunctionCall`s with the content kept as `thought`; retries are delegated to the SDK via `max_retries`. `ext/models/openai/_openai_client.py:L663–L815`, `ext/models/openai/_openai_client.py:L131–L134`, `ext/models/openai/_openai_client.py:L1200`
- **Streaming:** `create_stream` iterates chunks, accumulates `content_deltas` and per-index tool-call fragments, and ends with a `CreateResult`; the agent re-emits text chunks as `ModelClientStreamingChunkEvent`. `ext/models/openai/_openai_client.py:L816–L1033`, `ac/agents/_assistant_agent.py:L1093–L1107`
- **Fallback:** no backup-model routing found in the agent or client; `ChatCompletionCache` wraps a client to serve repeated requests from a cache store. `ext/models/cache/_chat_completion_cache.py:L29–L70`

## Output
- **Tool set and workbench:** callables become `FunctionTool`s, and tools are wrapped in a `StaticWorkbench` (or the user passes workbenches); handoffs are separate tools; names must be unique. `ac/agents/_assistant_agent.py:L774–L805`, `ac/agents/_assistant_agent.py:L827–L838`, `core/tools/_function_tool.py:L105–L125`
- **Executor and concurrency:** all tool calls in one response run concurrently with `asyncio.gather`; `_execute_tool_call` parses arguments, tries handoff tools, then `workbench.call_tool_stream`, returning an error result for bad JSON or an unknown tool. `ac/agents/_assistant_agent.py:L1197–L1215`, `ac/agents/_assistant_agent.py:L1536–L1624`, `core/tools/_static_workbench.py:L94–L124`
- **Sandbox (code tools):** `DockerCommandLineCodeExecutor` writes each block to a work dir and runs `timeout <s> <cmd> <file>` inside a container (default 60 s, auto-remove); `LocalCommandLineCodeExecutor` runs subprocesses on the host with the same timeout. `ext/code_executors/docker/_docker_code_executor.py:L85–L222`, `ext/code_executors/docker/_docker_code_executor.py:L327–L376`, `ext/code_executors/local/__init__.py:L45–L173`
- **Result presentation:** `ToolCallRequestEvent` and `ToolCallExecutionEvent` are yielded as inner events, the final `Response` carries a `TextMessage`, `StructuredMessage`, `ToolCallSummaryMessage` or `HandoffMessage`, and `Console` prints the stream. `ac/messages.py:L445–L500`, `ac/agents/_assistant_agent.py:L1498–L1535`, `ac/ui/_console.py:L82–L103`

## Production concerns
- **Persistence:** `save_state`/`load_state` serialize the model context (context primitive) as `AssistantAgentState`; teams and the runtime save state the same way; nothing is written to disk by default. `ac/agents/_assistant_agent.py:L1630–L1640`, `core/model_context/_chat_completion_context.py:L73`
- **Safety & security:** code runs in Docker when that executor is chosen; runtime intervention handlers can drop or rewrite messages; `CancellationToken` cancels in-flight calls; no approval gate on tool calls or prompt-injection defense found. `ext/code_executors/docker/_docker_code_executor.py:L85–L120`, `core/_single_threaded_agent_runtime.py:L691–L711`
- **Observability:** the OpenAI client logs `LLMCallEvent`/`LLMStreamStartEvent` with prompt and usage tokens to the event logger, tools log `ToolCallEvent`, agentchat emits typed events on `autogen_agentchat.events`, and `_telemetry` adds OpenTelemetry tracing around runtime messages. `ext/models/openai/_openai_client.py:L716–L717`, `core/logging.py:L10–L160`, `ac/__init__.py:L8–L11`, `core/_telemetry/_tracing.py`
- **Resilience:** HTTP retries are the SDK's `max_retries`; code execution has a timeout; a `TimeoutTermination` and `TokenUsageTermination` exist for teams; no overflow compaction, only the trimming contexts. `ext/models/openai/_openai_client.py:L1200`, `ac/conditions/_terminations.py:L229–L354`
- **Performance:** concurrent tool execution, streaming chunks, `ChatCompletionCache`, and token-limited contexts. `ac/agents/_assistant_agent.py:L1200`, `ext/models/cache/_chat_completion_cache.py:L29`, `core/model_context/_token_limited_chat_completion_context.py:L19`
- **Evaluation:** pytest suites per package cover the assistant agent, group chats, termination conditions and executors with replay model clients. `t/test_assistant_agent.py`, `t/test_group_chat.py`, `t/test_termination_condition.py`

## Hard to place
- **Reflection call:** `_reflect_on_tool_use_flow` is a second model call whose request is assembled from the same context but with no tools; its decision to run is control flow, its assembly context, its call model interface, and it lives in one method. `ac/agents/_assistant_agent.py:L1409–L1497`
- **Handoff tool:** by rule the tool call is output and the delegation is control flow of the team; here the agent itself returns a `HandoffMessage` and the team's `Swarm` manager routes on it, so the delegation decision is split across two harness layers. `ac/agents/_assistant_agent.py:L1328–L1408`, `ac/teams/_group_chat/_swarm_group_chat.py`
- **Runtime intervention handlers:** `on_send`/`on_publish` can drop or rewrite any message between agents; they act on the transport, not the model request, so they sit between input and control flow rather than within one primitive. `core/_single_threaded_agent_runtime.py:L691–L711`

## Summary
| Primitive | Design decision |
|---|---|
| Input | Chat messages from user or peers; tool results batched as one function-result message |
| Context | One system message plus a pluggable ChatCompletionContext (unbounded, buffered, token-limited); memory hooks |
| Model interface | ChatCompletionClient protocol; OpenAI SDK client with usage logging and streaming; SDK retries |
| Output | Workbench tools run concurrently via asyncio.gather; Docker or local code executors |
| Control flow | Bounded max_tool_iterations loop, then reflect or summarize; teams via actor runtime, termination conditions |
