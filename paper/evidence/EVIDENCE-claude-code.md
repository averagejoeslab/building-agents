# Claude Code

**Source:** https://code.claude.com/docs/en/overview (official docs; source not published) · **Version:** documentation as of 2026-10-15; the docs state no single CLI version (pages reference behaviours by version, the highest seen being v2.1.299; agent-loop page bundles "Claude Code v2.1.290 or later" in SDK v0.3.290). Engineering posts: claude.dev/blog "Prompt caching is everything" (2026-04-30), "A harness for every task" (2026-06-02), "Getting started with loops" (2026-06-30) · **Language:** not documented (docs describe a native binary and an npm package; troubleshooting refers to a "JavaScript heap")
**Path conventions:** `D` = https://code.claude.com/docs/en ; `SDK` = `D/agent-sdk` ; `B` = https://claude.dev/blog ; every citation is `page § Section heading` and was read on 2026-10-15. Where a page did not say how something works I write "not documented".
**What it is:** Claude Code is Anthropic's agentic coding harness: a terminal/IDE/desktop/web/CI program that wraps Claude models with file, search, shell and web tools, permission gating, memory loading and the loop that chains actions (`D/glossary § Agentic harness`). It reaches the model over the Anthropic Messages API (`/v1/messages`, SSE streaming) or via Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry or an LLM gateway (`D/llm-gateway-protocol § API formats`). The same loop is exposed as a library (Agent SDK, Python/TypeScript) and as `claude -p` for scripts (`SDK/overview § Compare the Agent SDK to other Claude tools`).

## Control flow
- **Core loop:** "Claude continues calling tools and processing results until it produces a response with no tool calls"; each cycle (model output with tool calls → tools run → results fed back) is one turn, with no control returned to the caller between turns. `SDK/agent-loop § The loop at a glance`, `§ Turns and messages`
- **Stop condition / result:** the loop ends on a text-only response; the `ResultMessage.subtype` is `success`, `error_max_turns`, `error_max_budget_usd`, `error_during_execution` or `error_max_structured_output_retries`; `stop_reason` carries `end_turn`, `max_tokens` or `refusal`. `SDK/agent-loop § Handle the result`
- **Step budget:** `max_turns`/`--max-turns` "counts tool-use turns only"; no limit by default (print mode only). A message still queued when the limit ends a turn starts a new turn with a fresh count. `SDK/agent-loop § Turns and budget`; `D/cli-reference § CLI flags` (`--max-turns`)
- **Token/cost budget:** `max_budget_usd` is compared "after model responses arrive", so spend can pass the cap by one response; subagent spend counts; at the cap, spawning fails with `Budget limit reached` and background subagents are stopped. `SDK/agent-loop § Budget headroom`
- **Permission gate order (harness consumes the answer):** hooks → deny rules → ask rules → permission mode → allow rules → `canUseTool`/prompt; a hook `allow` never skips deny/ask; `dontAsk` denies at the last step. `SDK/permissions § How permissions are evaluated`; rule order "deny, then ask, then allow … first match" `D/permissions § Manage permissions`
- **Permission modes:** `default` (Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`; auto is the built-in starting mode for interactive terminal/VS Code on v2.1.283+. `D/permission-modes § Available modes`, `§ Which mode a session starts in`
- **Auto-mode classifier gate:** a second model decides most tool calls; "runs on Claude Sonnet 5 by default rather than on your /model selection"; reads/working-dir edits skip it; it sees user messages, non-read-only tool calls and CLAUDE.md but "Tool results are stripped"; falls back to prompting after 3 blocks in a row or 20 total. `D/permission-modes § How auto mode evaluates actions`, `§ When auto mode falls back`
- **Plan mode:** edits stay blocked until a plan is approved; the approval prompt (`Yes, and use auto mode` / `Yes, manually approve edits` / `No, keep planning`) switches the session's permission mode. `D/permission-modes § Analyze before you edit with plan mode`, `§ Review and approve a plan`. Entering/leaving is itself a tool call (`EnterPlanMode`/`ExitPlanMode`) so the tool set never changes. `B/lessons-from-building-claude-code-prompt-caching-is-everything § Using Plan Mode to design around the cache`
- **Stop hook as loop extender:** a `Stop` hook returning `decision: "block"` keeps Claude working; capped at 8 consecutive continuations (reset on tool use), `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`. `D/hooks § Stop`; `D/env-vars § Variables` (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`)
- **Goal loop:** `/goal` "is a wrapper around a session-scoped prompt-based Stop hook"; after each turn the condition plus conversation go to the small fast model, which returns Not yet met / Met / Impossible; the loop halts if no tool use for several turns. `D/goal § How evaluation works`
- **PostToolBatch gate:** fires once after all tool calls in a batch resolve, "before the next model request"; `decision: "block"` or `continue: false` stops the loop before the next model call. `D/hooks § PostToolBatch`
- **Sub-agent delegation (Agent tool):** the model spawns a subagent in its own context; depth default 3 layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, `1` disables nesting); at most 20 concurrent (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`); only the final message returns to the parent. `D/sub-agents § Let subagents spawn their own subagents`, `§ Concurrent subagent limit`; `SDK/subagents § What subagents inherit`
- **Foreground vs background sequencing:** order of decision: teammates → `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` → fork mode on (background, Claude can't request foreground) → fork mode off (background by default, foreground when Claude needs the result); background results arrive later as a completion notification. `D/sub-agents § Run subagents in foreground or background`
- **Model keyed to work:** `opusplan` "Uses opus in plan mode, then switches to sonnet for execution"; subagent model order: per-invocation `model` → frontmatter `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → main model; background functionality (titles, summaries, goal evaluator) uses the Haiku-class model. `D/model-config § Model aliases`, `§ Environment variables`; `D/sub-agents § Choose a model`; `D/sessions § Name your sessions`
- **Dynamic workflows (model-written program sequencing model calls):** "A dynamic workflow is a JavaScript script that orchestrates many subagents"; `agent()`, `parallel()`, `pipeline()`; up to 16 concurrent agents, 4,096 items per call, 1,000 agents per run; no mid-run user input; `Date.now()`/`Math.random()` throw so a relaunch replays deterministically. `D/workflows § What the saved script looks like`, `§ Behavior and limits`, `§ Edit a saved script`
- **Workflow resume:** completed agents return saved results; the first agent whose prompt differs, and every agent after it, runs again. `D/workflows § Which agents run again`
- **Agent teams (outer harness of peer sessions):** lead + teammates with a shared task list and a per-agent mailbox JSON file at `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`; experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; no nested teams. `D/agent-teams § Architecture`, `§ Limitations`
- **Prompt- and agent-based hooks (harness-sequenced model calls):** `type: "prompt"` sends hook input to a model (default: the background-functionality model, 30 s timeout) to allow/block; `type: "agent"` spawns a subagent with tools (60 s). `D/hooks § Prompt-based hooks`, `§ Agent-based hooks`
- **Scheduled turns:** `/loop` creates cron tasks; "The scheduler checks every second for due tasks and enqueues them at low priority"; fires between turns, never mid-response; 7-day expiry; self-paced loops end via `ScheduleWakeup` with `stop: true`. `D/scheduled-tasks § How scheduled tasks run`, `§ Stop a loop`
- **Non-interactive exit wait:** after the turn ends, a `claude -p` run stays open for background work; "stops whatever is still running after 10 minutes of continuous idle waiting" (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`). `D/headless § Background tasks at exit`

## Input
- **Prompt capture:** interactive terminal prompt, `claude "query"`, `claude -p "query"`, and piped stdin ("Piped stdin is capped at 10MB"). `D/cli-reference § CLI commands`; `D/headless § Pipe data through Claude`
- **Mid-turn message queue:** a message typed while Claude works is queued; "Claude Code passes it to Claude as soon as those tool calls finish, within the same turn"; commands are held until the turn ends. `D/interactive-mode § When Claude Code sends what you queued`
- **Interrupt:** `Esc` cancels the running tool call and Claude waits; queued messages are sent next. `D/how-claude-code-works § Interrupt and steer`; `D/interactive-mode § General controls`
- **Model-consumed answers:** `AskUserQuestion` returns the user's choice to the model; questions stay open until answered unless `askUserQuestionTimeout` (`60s`/`5m`/`10m`) is set. `D/tools-reference § AskUserQuestion tool behavior`
- **Tool results as input:** each tool execution yields a `UserMessage` carrying the tool result back to the model. `SDK/agent-loop § Message types`
- **Event/stream inputs:** `--input-format stream-json` accepts user messages over stdin; `Monitor` feeds "each output line back to Claude" and can treat WebSocket messages as events; channels push external events into the session. `D/cli-reference § CLI flags`; `D/tools-reference § Tools reference` (`Monitor` row); `D/glossary § Channel`
- **Non-human turns captured through the same entry:** `UserPromptSubmit` "also fires for scheduled tasks, background subagent reports, and messages from other sessions". `D/hooks § UserPromptSubmit`
- **Rich input:** `Ctrl+V` pastes an image as an `[Image #N]` chip; `@path` mentions expand file content; `@server:protocol://resource` fetches MCP resources as attachments. `D/interactive-mode § General controls`; `SDK/modifying-system-prompts § Turn off the context your agent replaces` (`CLAUDE_CODE_DISABLE_FILE_MENTIONS`); `D/mcp § Use MCP resources`
- **MCP elicitation:** a server's mid-task form/URL request is shown as a dialog and the answer goes back to the server (not the model); an `Elicitation` hook can answer it. `D/mcp § Respond to MCP elicitation requests`

## Context
- **Request layering (what one call contains):** system prompt (core instructions + tool definitions) → project context (CLAUDE.md, auto memory, unscoped rules) → conversation (messages, tool results); ordered most- to least-stable for prefix caching. `D/prompt-caching § How the cache is organized`
- **Two system prompts:** full vs "a shorter one with abbreviated tool descriptions"; newer models get the short one unless `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0`. `D/env-vars § Variables` (`CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT`)
- **System prompt attribution block:** "a short attribution block to the system prompt containing the client version and a fingerprint"; stripped by `api.anthropic.com`; `CLAUDE_CODE_ATTRIBUTION_HEADER=0` omits it. `D/llm-gateway-protocol § System prompt attribution block`
- **CLAUDE.md delivery:** loaded "as a user message after the system prompt"; all discovered files are concatenated root→working directory, `CLAUDE.local.md` after `CLAUDE.md`; subdirectory files load "once Claude reads, writes, or edits another file in that subdirectory". `D/glossary § CLAUDE.md`; `D/memory § How CLAUDE.md files load`
- **Imports and rules:** `@path` imports expand at launch; `.claude/rules/*.md` load every session, or on demand when `paths:` frontmatter matches a file Claude touches; a CLAUDE.md over 4 MiB is skipped. `D/memory § Import additional files`, `§ Path-specific rules`, `§ How it works`
- **Auto memory (model-kept record):** `~/.claude/projects/<project>/memory/MEMORY.md`; "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded"; topic files read on demand; a write past the limit returns an error telling Claude to rewrite the index. `D/memory § How it works`, `§ Storage location`
- **System reminders:** harness-added context delivered "wrapped in `<system-reminder>` tags inside a user message, or … a separate message with the `system` role": CLAUDE.md, output style, hook `additionalContext`, skill list, file-changed notes, attribution lines. `D/glossary § System reminder`
- **Output style injection:** "Claude Code sends the active style's instructions with every request" as a conversation message, so the cached prefix survives a switch. `D/output-styles § How output styles work`; `D/prompt-caching § Changing output style`
- **Skills in context:** descriptions (truncated at 1,536 chars) are always in context; the body loads on invocation as a user message and stays for the session; `disable-model-invocation: true` keeps the description out. `D/skills § Frontmatter fields`, `§ Controlling visibility and context cost`; `D/prompt-caching § Invoking skills and commands`
- **Skill dynamic context:** `` !`command` `` runs a shell command before the model sees the skill and splices the output in. `D/skills § Dynamic context injection`
- **MCP tool search (deferred definitions):** only names and server instructions load; schemas arrive via the `ToolSearch` tool; `ENABLE_TOOL_SEARCH` `auto` loads upfront while definitions are under 10% of context; description caps 4,096 (upfront) / 16,384 (deferred) chars. `D/mcp § Scale with MCP tool search`, `§ Configure tool search`
- **Environment and git snapshot:** working directory, platform, shell, OS and a git branch/status/recent-commits block are added at session start; `includeGitInstructions: false` drops the git snapshot. `D/context-window` (Environment info event); `SDK/modifying-system-prompts § Turn off the context your agent replaces`; `D/prompt-caching § Cache scope`
- **Fitting tool results:** Bash output inline "up to roughly 30,000 characters"; past that a file path plus 2,000-char preview; MCP results capped at 25,000 tokens and text over 50,000 chars spilled to a file; `Read` returns at most 25,000 tokens per call and refuses whole files over 256 KB. `D/tools-reference § Output limits`, `§ Large files`; `D/mcp § Raise the limit for a specific tool`; `D/env-vars § Variables` (`MAX_MCP_OUTPUT_TOKENS`)
- **Auto-compaction trigger:** by default "compacts when the conversation reaches the model's context limit"; native-1M models compact "at about 967K tokens"; window settable 100K–1M via `/autocompact`, `autoCompactWindow`, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`. `D/model-config § Default auto-compact thresholds`, `§ Set the auto-compact window`
- **Compaction order:** "It clears older tool outputs first, then summarizes the conversation if needed." `D/how-claude-code-works § When context fills up`
- **Compaction as a forked request:** the summarization call reuses the same system prompt, tools and history "plus a summarization instruction appended as a final user message"; inherits the session's thinking config. `D/prompt-caching § Compacting the conversation`; `D/context-window § What survives compaction`; `B/lessons-from-building-claude-code-prompt-caching-is-everything § COMPACTING WITHOUT BREAKING THE CACHE`
- **What survives compaction:** system prompt/output style still apply; project-root CLAUDE.md, auto memory, plan file re-injected from disk; up to five recently modified files re-read (over 5,000 tokens → path reference); invoked skill bodies re-injected "capped at 5,000 tokens per skill and 25,000 tokens total"; hook context is summarized away. `D/context-window § What survives compaction`
- **Hook-supplied context:** `additionalContext` is wrapped in a system reminder; `additionalContext`, `systemMessage`, `initialUserMessage` capped at 10,000 chars (longer saved to file with a 2,000-char preview); `PostToolUse.updatedToolOutput` replaces what Claude sees. `D/hooks § JSON output`, `§ Add context for Claude`, `§ PostToolUse`
- **Sub-agent context:** a non-fork subagent gets its own system prompt plus environment details, the task message, CLAUDE.md hierarchy (not for Explore/Plan), git snapshot, preloaded skills; not the parent history, output style or auto memory. A fork gets the full conversation, system prompt and tools. `D/sub-agents § What loads at startup`, `§ How forks differ from other subagents`
- **Sub-agent output scanning:** before the parent reads a report, control-tag imitations get a backslash and a `[harness: ...]` marker line is prepended; nothing is removed. `D/sub-agents § Subagent output scanning`; `SDK/subagents § What subagents inherit`

## Model interface
- **Wire format:** Anthropic Messages format, "Inference requests post to `/v1/messages?beta=true`"; optional `/v1/messages/count_tokens` (falls back to a character estimate); headers `anthropic-version: 2023-06-01`, `anthropic-beta`, `x-claude-code-session-id`, `x-claude-code-agent-id`. `D/llm-gateway-protocol § API formats`, `§ Optional endpoints and startup traffic`, `§ Request headers`
- **Providers/backends:** `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, Claude Platform on AWS, or any gateway via `ANTHROPIC_BASE_URL`; Bedrock uses `invoke-with-response-stream` binary eventstream. `D/env-vars § Variables`; `D/llm-gateway-protocol § API formats`
- **Streaming receipt:** "Claude Code reads each streaming inference response event by event as it arrives"; expects the full sequence through `message_delta`/`message_stop`, else treats it as a dropped connection. `D/llm-gateway-protocol § Streaming`
- **Retry policy:** "retries transient failures up to 10 times with exponential backoff" (`CLAUDE_CODE_MAX_RETRIES`, capped at 15); retries server errors/529/timeouts before output starts, dropped connections (up to 2 after thinking), stalled streams (once), no-headers (once per request), temporary 429s; never re-runs after a completed text or tool block "because that could execute the same tool calls twice". `D/errors § Automatic retries`
- **529 backoff:** `CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS` 500 → `CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` 32000; `retry-after` honoured, and >60 s stops retries outside watchdog sessions; `x-should-retry` read. `D/errors § Automatic retries`; `D/llm-gateway-protocol § Response headers`
- **Indefinite retry for unattended runs:** `CLAUDE_CODE_RETRY_WATCHDOG=1` "Retries 429 and 529 capacity errors indefinitely", backing off up to 5 minutes. `D/env-vars § Variables`
- **Timeouts and watchdogs:** `API_TIMEOUT_MS` default 600000; first-byte deadline 180 s (direct API) / 300 s (elsewhere) + 1 s per 32 KB of body; event-level watchdog 300 s; byte-level watchdog 180 s/300 s; body idle timeout 5 min. `D/env-vars § Variables` (`API_TIMEOUT_MS`); `D/network-config § Streaming idle watchdogs`
- **Backup model when the request can't be served:** `--fallback-model sonnet,haiku` / `fallbackModel` runs "when the primary model is overloaded, unavailable, or returns another non-retryable server error"; chain of ≤3; applies to the current turn only; subagents use it too. `D/model-config § Fallback model chains`
- **Safety-flag model fallback:** when a server safety classifier flags a request, Claude Code "can re-run it on a fallback model" (e.g. Opus 4.8 for cybersecurity); `switchModelsOnFlag`. `D/model-config § Automatic model fallback`
- **Capability-rejection recovery:** on a 400 rejecting `thinking`, a mid-conversation system message, `cache_control`, the advisor tool or `output_config.effort`, Claude Code retries without that capability for the rest of the conversation; a rejected thinking signature strips earlier thinking blocks. `D/llm-gateway-protocol § Automatic retry and error forwarding`
- **Context-limit rejection:** a request rejected because input + `max_tokens` exceeds the limit is retried "with a reduced max_tokens", then compacted when no reduction fits. `D/errors § Automatic retries`
- **Prompt-cache markers and TTL:** `cache_control` on system blocks and messages; main conversation gets 1 h TTL on subscription usage, 5 min otherwise; subagents/compaction/titles get 5 min; `promptCacheTtl`, `FORCE_PROMPT_CACHING_5M`, `DISABLE_PROMPT_CACHING`. `D/prompt-caching § Which TTL each request gets`, `§ Choose the TTL yourself`, `§ Disable prompt caching`
- **Reasoning parameters on the wire:** `thinking: {"type": "adaptive"}` for 4.6+ models; effort and structured output in `output_config` with paired beta headers; `MAX_THINKING_TOKENS` fixed budget (≥1,024, ≤ max output − 1); `CLAUDE_CODE_MAX_OUTPUT_TOKENS` (default 32000 / cap 128000 for unknown IDs). `D/llm-gateway-protocol § Feature pass-through`; `D/env-vars § Variables`
- **Retry visibility:** a `system/api_retry` event (attempt, max_retries, retry_delay_ms, error_status, error category) is emitted in stream-json before each retry. `D/headless § Handle API retries`

## Output
- **Built-in tool set:** Agent, AskUserQuestion, Bash, Edit, EndConversation, Glob, Grep, LSP, Monitor, NotebookEdit, PowerShell, Read, SendMessage, Skill, TaskCreate/TaskUpdate/TodoWrite, ToolSearch, WebFetch, WebSearch, Workflow, Write (+ MCP tools `mcp__<server>__<tool>`). `D/tools-reference § Tools reference` (table); `SDK/agent-loop § Built-in tools`
- **Concurrent execution of one response's calls:** "Read-only tools (like Read, Glob, Grep, and MCP tools marked as read-only) can run concurrently. Tools that modify state (like Edit, Write, and Bash) run sequentially"; custom tools opt in via `readOnlyHint`. `SDK/agent-loop § Parallel tool execution`
- **Bash executor:** default timeout 2 min (`BASH_DEFAULT_TIMEOUT_MS`), ceiling 10 min (`BASH_MAX_TIMEOUT_MS`); a foreground command that hits its timeout "moves it to the background instead of stopping it"; background commands get 30 min (max 2 h); env vars don't persist between commands; shell aliases/options captured in `~/.claude/shell-snapshots/`. `D/tools-reference § Timeout and output limits`, `§ Foreground commands that move to the background`, `§ Time limit for background commands`, `§ What persists between commands`; `D/claude-directory § Cleaned up automatically`
- **Sandbox technology:** macOS Seatbelt; Linux/WSL2 bubblewrap + socat; no sandbox on native Windows; covers Bash, PowerShell and Monitor commands only, not file tools, MCP servers or hooks. `D/sandboxing § OS-level enforcement`, `§ What runs outside the sandbox`
- **Sandbox network path:** "Claude Code runs the sandbox proxy on your machine, outside the sandbox, and directs commands to it with HTTP_PROXY, HTTPS_PROXY, ALL_PROXY"; the proxy checks hostnames against `allowedDomains`/`deniedDomains`, refuses names resolving only to local addresses, and can mask credentials with a sentinel (requires `tlsTerminate`). `D/sandboxing § Network isolation`, `§ Hostnames that resolve to local addresses`, `§ Mask credentials`
- **Sandbox filesystem path:** writable: working dir + per-user `$TMPDIR`; "Protected paths" (settings, hooks, MCP config) are denied even inside writable dirs; `excludedCommands` run unsandboxed; strict mode `allowUnsandboxedCommands: false`. `D/sandboxing § Filesystem isolation`, `§ Protected paths`, `§ Turn off the retry with strict sandbox mode`
- **WebFetch executor:** converts HTML to Markdown, "runs the prompt against the content in a separate model call, and Claude receives the result of that call rather than the raw page"; 15-min response cache; hostname first checked against an Anthropic blocklist at `api.anthropic.com` (`skipWebFetchPreflight`). `D/tools-reference § WebFetch tool behavior`; `D/data-usage § WebFetch domain safety check`
- **WebSearch:** server-side tool; "An interactive terminal session has a limit of 200 WebSearch calls" shared with subagents. `D/tools-reference § WebSearch tool behavior`, `§ Session search limit`
- **Read/Edit/Write executors:** Read returns numbered lines, resizes images (>500 KB re-encoded as JPEG), reads PDFs in ≤20-page ranges via `pdftoppm`; Edit/Write enforce read-before-edit on older models. `D/tools-reference § Read tool behavior`, `§ Edit tool behavior`, `§ Write tool behavior`
- **MCP executor:** stdio, HTTP (falls back to SSE), WebSocket transports; `MCP_TIMEOUT` 30 s startup, `MCP_TOOL_TIMEOUT` ~28 h, 60 s per HTTP request, idle timeout 5 min remote/30 min stdio, main-conversation calls auto-background after 2 min (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`); invalid schemas and names >128 chars are excluded per tool. `D/mcp § Transports`, `§ Timeouts`, `§ Tools with invalid input schemas`, `§ Tools with names longer than 128 characters`
- **Monitor executor:** Claude writes a script run in the background, or opens a WebSocket; deadline 5 min by default, max 30 min (10 min under `-p`). `D/tools-reference § Monitor tool`
- **Rendering the stream:** an `AssistantMessage` is emitted per content block; `stream_event` deltas (`text_delta`, `input_json_delta`) with `--include-partial-messages`; the spinner shows a live output-token count. `SDK/streaming-output § Message flow`; `D/costs § Read the token count beside the spinner`
- **Structured output:** `--output-format json|stream-json`, `--json-schema` validated output in `structured_output`; up to 5 attempts (`MAX_STRUCTURED_OUTPUT_RETRIES`). `D/headless § Get structured output`; `D/env-vars § Variables`
- **Hook executors:** handler types `command`, `http`, `mcp_tool`, `prompt`, `agent`; "All matching hooks run in parallel. Identical handlers from multiple settings files run once"; defaults 600 s command/http/mcp_tool; exit 2 blocks (PreToolUse) with stderr fed to Claude; `async: true` detaches; `PreToolUse.updatedInput` rewrites tool arguments before execution. `D/hooks § Configuration`, `§ Exit code output`, `§ Run hooks in the background`, `§ PreToolUse`
- **User-facing artifacts:** file checkpoints snapshot files "before each prompt you send that starts a turn", 100 most recent kept, `/rewind` restores code and/or conversation; Bash-made and subagent edits are not tracked. `D/checkpointing § Automatic tracking`, `§ Bash command changes not tracked`, `§ Subagent edits not restored`
- **EndConversation:** never prompts, PreToolUse hooks don't run for it, and deny rules/`--tools` can't remove it while any other tool remains. `D/tools-reference § EndConversation tool behavior`
- **Permission prompt surface:** Manual mode asks for Bash (except a built-in read-only set: `ls`, `cat`, `git status`…), file modification, WebFetch (except preapproved doc domains), WebSearch; "Yes, don't ask again" persists per repository. `D/permissions § Permission system`, `§ Read-only commands`

## Design decisions (one line each: the choice this harness made within a primitive)
- Input: one entry point for everything that starts a turn (typed prompts, piped stdin, queued mid-turn messages delivered after the current tool batch, scheduled/cron prompts, cross-session and channel messages, background-subagent reports), all passing through `UserPromptSubmit`. `D/hooks § UserPromptSubmit`; `D/interactive-mode § When Claude Code sends what you queued`
- Context: a stable cached prefix (system prompt + tools, then project context) with every later update appended as a message or `<system-reminder>`; MCP schemas deferred behind `ToolSearch`; compaction on reaching the window via a forked request that re-injects CLAUDE.md, memory, five recent files and invoked skills. `D/prompt-caching § How the cache is organized`; `D/context-window § What survives compaction`
- Model interface: direct Anthropic Messages API with streaming, 10 exponential-backoff retries that never re-issue after a completed tool block, four idle watchdogs, a user-configured fallback model chain, and capability-rejection downgrade for gateways. `D/errors § Automatic retries`; `D/llm-gateway-protocol § Automatic retry and error forwarding`
- Output: a fixed built-in tool set plus MCP; read-only calls run concurrently, mutating calls sequentially; shell commands run under an OS sandbox (Seatbelt/bubblewrap) with a local domain-allowlist proxy; large results spill to files; file edits are checkpointed for `/rewind`. `SDK/agent-loop § Parallel tool execution`; `D/sandboxing § OS-level enforcement`; `D/checkpointing § Automatic tracking`
- Control flow: loop until a text-only response, with the decision to stop extendable by Stop hooks and `/goal`'s evaluator model; a six-step permission pipeline whose default gate is a second model (auto mode); delegation through an `Agent` tool (depth 3, 20 concurrent, background by default) and, at scale, a model-written JavaScript workflow the runtime executes. `SDK/agent-loop § Turns and messages`; `SDK/permissions § How permissions are evaluated`; `D/workflows § When to use a workflow`

## Hard cases
- **WebFetch's inner model call:** a tool (output) that itself calls the model and decides what the main model sees (a summary, not the page). Resolved by rule 21: the tool call is output; the summarisation is a context decision (and a prompt-injection defence, `D/security § Additional safeguards`); the extra request is model interface. `D/tools-reference § WebFetch tool behavior`
- **Auto-mode classifier:** an approval gate the harness consumes (control flow) implemented as a separate model request with its own stripped-down context (`D/permission-modes § How auto mode evaluates actions`). Resolved: the decision is control flow; the request is model interface; the stripping of tool results is context assembly for that side call. Its "server-side classifier review" variant runs inside the API as part of the session's model requests, i.e. partly outside the harness. `D/permission-modes § Server-side classifier review`
- **Prompt/agent hooks and the `/goal` evaluator:** harness-sequenced model calls that decide whether to go again. Resolved by rule 27 (a program that sequences model calls is control flow). `D/hooks § Prompt-based hooks`; `D/goal § How evaluation works`
- **Dynamic workflows:** the model writes a JS program at run time whose `agent()` calls sequence model calls → control flow (rule 27); the `Workflow` tool call that launches it is output; the script's intermediate results live "in script variables" rather than any context. `D/workflows § How a workflow runs`
- **Compaction:** the trigger (window threshold) and the result (summary replaces history) are context; the summarisation is a model call (model interface); the thrashing stop after "a few attempts" is a loop decision (control flow/resilience). `D/model-config § Default auto-compact thresholds`; `D/troubleshooting § Auto-compaction stops with a thrashing error`
- **Context-limit retry with reduced `max_tokens`:** a retry of a failed request (model interface) that changes the request's parameters (context). Placed under model interface because the trigger is a rejected request and the content is unchanged; noted as a boundary case. `D/errors § Automatic retries`
- **Hook rewrites:** `PreToolUse.updatedInput` changes the action before execution (output executor side); `PostToolUse.updatedToolOutput` changes what the model is shown (context). Decomposed per rule 1. `D/hooks § PreToolUse`, `§ PostToolUse`
- **Two kinds of model switch:** `opusplan` (plan vs execution) and subagent `model` fields are keyed to the work → control flow; `--fallback-model` (overloaded/unavailable) and safety-flag fallback → model interface (rule 22). `D/model-config § Model aliases`, `§ Fallback model chains`, `§ Automatic model fallback`
- **Subagent output scanning:** modifies a tool result before the model reads it → context (what the model is shown) and a safety concern; not output, because nothing is executed. `D/sub-agents § Subagent output scanning`
- **Checkpoints and session titles:** file snapshots are a user artifact (output) that persists; the title is produced by a cheap-model call keyed to the work (control flow) and stored for the operator/user (persistence). `D/checkpointing § Automatic tracking`; `D/sessions § Name your sessions`
- **Queued messages mid-turn:** capturing the message is input; deciding to hand it to the model "as soon as those tool calls finish, within the same turn" is a loop decision (control flow). `D/interactive-mode § When Claude Code sends what you queued`
- **Agent teams' mailbox:** messages arrive as turns for the recipient (input) but the delivery, idle notifications and task-claim locking are an outer harness's control flow; the classifier reviewing each `SendMessage` is a safety gate. Depth: lead → teammates (no nested teams); results return via idle notifications containing the final answer. `D/agent-teams § Context and communication`, `§ Limitations`
- **Server-side classifier review and the server-side prompt-injection probe:** DOES NOT FIT the five primitives cleanly, because the safety decision is made inside the API during the model request rather than by the harness; the harness only consumes the verdict (denies when none arrives after ten responses). `D/permission-modes § Server-side classifier review`; `D/glossary § Prompt injection`
- **`EndConversation`:** a tool whose only effect is to stop the loop; by rule 21 the call is output and the stop is control flow; its un-removability is a safety choice. `D/tools-reference § EndConversation tool behavior`
