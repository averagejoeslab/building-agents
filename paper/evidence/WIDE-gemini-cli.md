# Gemini CLI

**Source:** https://github.com/google-gemini/gemini-cli · **Version:** commit b25669d84e1a404e30c176d779e732e25dafcec0 (2026-10-16) · **Language:** TypeScript (Node)
**Path conventions:** `core/` = `packages/core/src/`; `cli/` = `packages/cli/src/`. All paths relative to the repo root.
**What it is:** Gemini CLI is Google's open-source terminal coding agent. The `core` package holds the agent loop (`GeminiClient`), chat history (`GeminiChat`), the tool scheduler, policy engine, hooks, sandboxing and sub-agents; the `cli` package is an Ink/React terminal UI that drives the loop and runs tool calls. The model is reached through the `@google/genai` SDK (API key, Vertex AI, or a gateway) or through the Code Assist OAuth backend, always as a streaming `generateContentStream` call.

## Control flow
- **Turn loop and budgets:** `sendMessageStream` runs one model call through `processTurn` and recurses with `boundedTurns - 1` for continuations; recursion is capped by `MAX_TURNS = 100` and the session by `maxSessionTurns`, and a pre-flight overflow check or a `MaxSessionTurns` event ends the run. `core/core/client.ts:L79`, `L644–L663`, `L727–L744`, `L940–L1000`
- **Tool re-entry loop lives outside the client:** `LegacyAgentProtocol` collects `ToolCallRequest` events, calls `scheduler.schedule`, and re-sends the completed calls' `responseParts` as the next request, stopping when a response has no tool calls, on a `STOP_EXECUTION` tool error, or on a fatal tool error; the interactive CLI does the same in `handleCompletedTools` -> `submitQuery(..., {isContinuation: true})`. `core/agent/legacy-agent-session.ts:L199–L215`, `L260–L343`; `cli/ui/hooks/useGeminiStream.ts:L2109–L2130`, `L2314–L2326`
- **Stop rule:** when a turn ends with no pending tool calls, `checkNextSpeaker` asks a utility model whether the `model` should speak next and, if so, the harness sends "Please continue."; `LoopDetectionService` watches repeated tool calls (5), repeated content chunks (10) and an LLM check after 30 turns, injecting a corrective message on the first detection and aborting on the second. `core/core/client.ts:L777–L795`, `L840–L857`, `L905–L937`, `L1302–L1328`; `core/utils/nextSpeakerChecker.ts:L14–L43`; `core/services/loopDetectionService.ts:L29–L65`, `L185–L215`, `L260–L300`
- **Approval gates and hooks:** the scheduler's `_processToolCall` runs the BeforeTool hook, then `checkPolicy` -> `PolicyEngine.check` (TOML rules plus approval mode DEFAULT/AUTO_EDIT/YOLO/PLAN) yielding ALLOW/DENY/ASK_USER, escalates taint-risk invocations to ASK_USER, and resolves ASK_USER through `resolveConfirmation` on the message bus, cancelling the whole batch on a user Cancel; BeforeAgent hooks can stop or block a run, and AfterAgent hooks can stop it or force one more turn. `core/scheduler/scheduler.ts:L640–L770`; `core/scheduler/policy.ts:L53–L75`; `core/policy/policy-engine.ts:L301–L304`, `L350–L357`; `core/core/client.ts:L956–L988`, `L1004–L1058`; `core/hooks/types.ts:L43–L54`
- **Model routing and sub-agents:** per prompt a `ModelRouterService` composite (Fallback, Override, ApprovalMode, classifier strategies, Default) picks the model, which then sticks for the sequence; `AgentTool` runs a `LocalAgentExecutor` whose `runInternal` loops `executeTurn` until `complete_task`, `maxTurns` or a `maxTimeMinutes` deadline, and returns the result as a tool result (built-in agents: codebase investigator, CLI help, generalist). `core/core/client.ts:L797–L826`; `core/routing/modelRouterService.ts:L39–L75`; `core/agents/agent-tool.ts:L217–L243`; `core/agents/local-executor.ts:L582–L598`, `L685–L718`; `core/agents/registry.ts:L286–L288`

## Input
- **User message:** the CLI's `submitQuery` hands the typed parts to `geminiClient.sendMessageStream`; `@path` references are expanded by `handleAtCommand` through the `read_many_files` tool before submission. `cli/ui/hooks/useGeminiStream.ts:L1910–L1916`; `cli/ui/hooks/atCommandProcessor.ts:L690–L699`
- **Tool results:** completed calls' `functionResponse` parts become the next user content; a queued user steering hint is prepended to that content; if the model was switched by a quota error the responses are only recorded to history. `cli/ui/hooks/useGeminiStream.ts:L2280–L2326`; `core/agent/legacy-agent-session.ts:L278–L308`, `L341–L342`
- **Answers the model asked for:** `AskUserTool` receives the user's answers from the confirmation payload and returns them as JSON `llmContent`. `core/tools/ask-user.ts:L171–L179`, `L187–L248`
- **IDE context:** open files and cursor state from the IDE companion are appended as a user part when no tool call is pending. `core/core/client.ts:L459–L470`, `L755–L771`

## Context
- **System prompt:** `PromptProvider.getCoreSystemPrompt` composes snippet sections (mandates, workflows, sandbox, git, user memory, skills, plan-mode tool list) chosen by model generation, or loads a `GEMINI_SYSTEM_MD` override file with substitutions. `core/prompts/promptProvider.ts:L47–L135`; `core/prompts/snippets.ts:L136–L336`
- **Project and user memory:** `GEMINI.md` files are read from the global `~/.gemini` dir, upward from the cwd to the project root, and from extensions, then concatenated into the user-memory section. `core/tools/memoryTool.ts:L11`; `core/utils/memoryDiscovery.ts:L209`, `L295`, `L317`, `L342`, `L463–L471`
- **History shape:** `GeminiChat` keeps a comprehensive history and derives a curated one (invalid model turns dropped) that is what gets sent. `core/core/geminiChat.ts:L220–L255`, `L1270–L1278`
- **Compaction:** before each call `tryCompressChat` runs when the last prompt token count reaches 50% of the model's limit; it truncates to budget, splits keeping the last 30%, summarizes the rest with a utility model into a `<state_snapshot>`, and falls back to truncation only after an inflated result; an optional `ContextManager` pipeline (masking, distillation, rolling summary processors) replaces this when enabled. `core/context/chatCompressionService.ts:L45`, `L269`, `L467–L560`, `L595–L614`; `core/core/client.ts:L670–L725`, `L1226–L1283`; `core/context/contextManager.ts:L90–L122`
- **Tool output masking:** `tryMaskToolOutputs` replaces bulky older tool outputs once protected recent output exceeds 50k tokens, and the request is token-estimated against the window before sending. `core/context/toolOutputMaskingService.ts:L25–L28`; `core/core/client.ts:L727–L744`, `L1288–L1297`

## Model interface
- **Client:** `createContentGenerator` builds a `GoogleGenAI` SDK client (API key, Vertex, gateway, proxy agent) or the Code Assist OAuth generator, wrapped in `ModelMappingContentGenerator` and `LoggingContentGenerator`, optionally `RecordingContentGenerator`. `core/core/contentGenerator.ts:L210–L239`, `L293–L310`, `L385–L427`
- **Streaming and retries:** `generateContentStream` is wrapped in `retryWithBackoff` (default 10 attempts, 5s to 30s backoff on 429/5xx); mid-stream invalid-content or network errors are retried up to 4 attempts with exponential backoff and a `RETRY` event tells the UI to discard partial output. `core/core/geminiChat.ts:L105–L109`, `L664–L700`, `L739–L794`, `L1180–L1230`; `core/utils/retry.ts:L20`, `L42–L46`, `L205`
- **Fallback model:** a persistent 429 calls `handleFallback`, which selects the next available model from the policy chain and consults a user handler whose intent (`retry_always`, `retry_once`, `stop`, ...) decides whether to switch. `core/fallback/handler.ts:L26–L80`, `L157–L196`
- **Tool-call format:** native Gemini `functionCall` parts; `Turn.run` turns each into a `ToolCallRequest` event and yields `Finished` with the finish reason and usage. `core/core/turn.ts:L270–L300`, `L380–L414`, `L508–L521`

## Output
- **Tool set:** core tools registered in `Config` (ls, read_file, grep/ripgrep, glob, edit, write_file, shell, web_fetch, web_search, memory, ask_user, activate_skill, agent tools) plus MCP tools discovered into the `ToolRegistry`. `core/config/config.ts:L4014–L4060`; `core/tools/tool-registry.ts:L287–L302`, `L370`, `L663`; `core/tools/mcp-tool.ts:L501`
- **Executor and parallelism:** the scheduler dequeues contiguous parallelizable calls as one batch, validates them concurrently, and executes all scheduled calls with `Promise.all`, streaming live output into state. `core/scheduler/scheduler.ts:L519–L566`, `L777–L821`
- **Shell execution:** commands run under `node-pty` with a 16MB buffer, an inactivity timeout, and optional backgrounding. `core/services/shellExecutionService.ts:L50`, `L454–L470`; `core/tools/shell.ts:L554–L660`
- **Sandbox:** `createSandboxManager` picks macOS `sandbox-exec` (seatbelt profiles), Linux bubblewrap with seccomp, or a Windows manager; the CLI can also run itself inside a docker/podman container. `core/services/sandboxManagerFactory.ts:L22–L36`; `core/sandbox/macos/MacOsSandboxManager.ts:L178`; `core/sandbox/linux/LinuxSandboxManager.ts:L303–L318`; `cli/utils/sandbox.ts:L121`, `L402–L403`
- **Result presentation and truncation:** shell output above 40,000 chars is saved to the project temp dir and replaced by a truncated excerpt; stream events are rendered incrementally by `processGeminiStreamEvents`. `core/scheduler/tool-executor.ts:L202–L232`; `core/config/config.ts:L483`; `cli/ui/hooks/useGeminiStream.ts:L1917–L1920`

## Production concerns
- **Persistence:** context/input record: `ChatRecordingService` writes each session as a JSONL file under the project temp `chats/` dir (sub-agents nested under the parent id) for resume. `core/services/chatRecordingService.ts:L779–L823`
- **Safety & security:** control flow and output: TOML policy engine with approval modes and non-interactive deny default, taint-risk escalation to ASK_USER, OS sandboxes, hook shell commands with a 60s timeout. `core/policy/policy-engine.ts:L301–L304`; `core/scheduler/scheduler.ts:L687–L696`; `core/hooks/hookRunner.ts:L252–L262`
- **Observability:** OpenTelemetry logs, metrics and traces exported over OTLP gRPC/HTTP plus Clearcut; `logApiResponse` records duration, status and token usage including cached tokens. `core/telemetry/sdk.ts:L15–L21`; `core/telemetry/loggers.ts:L307–L330`; `core/telemetry/types.ts:L691`
- **Resilience:** model interface and context: connection and mid-stream retries, model fallback on persistent 429, pre-flight overflow detection and compaction, loop recovery. `core/core/geminiChat.ts:L739–L794`; `core/core/client.ts:L727–L744`, `L1302–L1328`
- **Performance:** output and context: parallel tool batches, streaming, compaction at 50% of the window, tool-output masking, model routing to cheaper models by classifier. `core/scheduler/scheduler.ts:L519–L566`; `core/routing/strategies/classifierStrategy.ts:L31–L32`
- **Evaluation:** `evals/` behavioral evals (38 `.eval.ts`) check what the model chooses to do; `integration-tests/` (48 `.test.ts`) replay recorded API responses through `FakeContentGenerator`. `evals/README.md:L1–L20`; `core/core/contentGenerator.ts:L216–L228`

## Hard to place
- **Model calls that steer the loop:** `checkNextSpeaker`, the LLM loop check and the classifier router are model calls whose only effect is a go-again or routing decision; by the routing rule they are control flow even though each is itself a request to the model interface. `core/utils/nextSpeakerChecker.ts:L43–L80`; `core/services/loopDetectionService.ts:L260–L300`; `core/routing/strategies/classifierStrategy.ts:L132`, `L171`
- **Hooks as bundles:** BeforeAgent `additionalContext` is context, BeforeTool arg modification is output, AfterAgent stop/continue is control flow, and BeforeModel/AfterModel hooks edit the request inside the chat layer; the hook runner spawning a shell process fits no primitive. `core/core/client.ts:L978–L988`; `core/scheduler/scheduler.ts:L670–L674`; `core/core/geminiChat.ts:L1173–L1176`; `core/hooks/hookRunner.ts:L7`
- **Turn loop split across packages:** the client only ever issues one model call per `processTurn`; the model/tool alternation is owned by the caller (CLI hook or `LegacyAgentProtocol`), so the "loop" is control flow assembled from two files. `core/core/client.ts:L644–L663`; `core/agent/legacy-agent-session.ts:L260–L343`

## Summary
| Primitive | Design decision |
|---|---|
| Input | CLI/ACP parts with @file expansion; tool results and AskUser answers re-enter as functionResponse parts |
| Context | Snippet-composed system prompt, hierarchical GEMINI.md memory, curated history, 50% threshold snapshot compression, tool masking |
| Model interface | @google/genai or Code Assist streaming, 10-attempt backoff, mid-stream retries, policy-chain model fallback |
| Output | Registry of core and MCP tools, parallel batches, node-pty shell, seatbelt/bwrap/container sandboxes, 40k truncation |
| Control flow | Caller-driven tool loop, 100-turn cap, next-speaker and loop checks, policy/confirmation gate, hooks, classifier routing, sub-agents |
