# GitHub Copilot cloud agent and agent mode

**Source:** https://docs.github.com/en/copilot (official docs; source not published) · **Version:** documentation as of 2026-10-16 · **Language:** not documented
**Path conventions:** `G` = https://docs.github.com/en/copilot ; every citation is `G/page § Section heading` and was read on 2026-10-16. The docs now call the coding agent "Copilot cloud agent"; the legacy path `G/concepts/agents/coding-agent/about-coding-agent` serves the page titled "GitHub Copilot on GitHub.com" and is cited as `G/concepts/copilot-surfaces/copilot-on-github`. Agent mode (the IDE loop) is documented only at summary level on docs.github.com; its VS Code internals live on code.visualstudio.com and are out of scope here, so several mechanisms read "not documented".
**What it is:** Copilot cloud agent is GitHub's hosted coding agent: given an issue, a prompt or a `@copilot` mention it works "in its own ephemeral development environment, powered by GitHub Actions", pushes commits to a `copilot/` branch and opens one pull request per task. Agent mode is the in-editor loop in VS Code, Visual Studio, JetBrains, Xcode and Eclipse that edits files and runs commands "iterating until the task is done". Models are reached through GitHub's Copilot service (hosts such as `api.*.githubcopilot.com`), with provider models from OpenAI, Anthropic, Google, Microsoft, Moonshot AI and xAI. `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § About customizing Copilot cloud agent's development environment`; `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Introduction`; `G/reference/ai-models/supported-models § Supported AI models in Copilot`

## Control flow
- **Cloud agent session loop:** a session researches the repository, plans, implements, runs tests and linters, then pushes; the inner model-tool loop is not documented; each session "has a maximum execution time of 59 minutes" that "cannot be extended or bypassed", with a shorter `timeout-minutes` allowed in `copilot-setup-steps.yml`. `G/concepts/copilot-surfaces/copilot-on-github § Chat and agentic experiences § Delegating work`, `§ Limitations and compatibility § Agentic work`
- **Stop rule:** a session ends when the work is pushed and (if asked) a pull request is opened, or when a person clicks Stop session, which "ends the GitHub Actions run and preserves any commits already pushed"; sessions "do not create pull requests automatically" unless the prompt asks. `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Stop a session`; `G/how-tos/copilot-on-github/use-copilot-agents/research-plan-iterate § Research, plan, and iterate on code changes with Copilot cloud agent`
- **Approval gates the harness consumes (cloud):** no tool-level approvals during a session (MCP tools run "autonomously"); gates sit at the edges: only write-access users can trigger, GitHub Actions "workflows are not triggered until Copilot cloud agent's code is reviewed" and a write-access user clicks Approve and run workflows, and the requester cannot approve the PR; `preToolUse` hooks can "approve or deny tool executions". `G/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers § Introduction`; `G/concepts/agents/cloud-agent/risks-and-mitigations § Copilot cloud agent can push code changes to your repository`; `G/concepts/agents/hooks § Types of hooks`
- **Approval gates (agent mode):** terminal commands "require your confirmation by default" unless the administrator or editor settings allow them to run automatically; enterprise managed settings control "whether users can bypass permission checks"; iteration or request caps are not documented on docs.github.com. `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Introduction`; `G/concepts/copilot-surfaces/copilot-in-ides § Using Copilot in other IDEs § Entry points in JetBrains IDEs`
- **Sub-agents and automations:** custom agents (`.github/agents/NAME.md`) are instantiated when assigned to a task; agent mode in VS Code and JetBrains can hand a self-contained subtask to a subagent (depth and result return not documented); automations start a session on a schedule (hourly, daily, weekly) or on issue-created, PR-opened or PR-synchronized events with a chosen tool set. `G/concepts/agents/cloud-agent/about-custom-agents § About custom agents`; `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Extending agent mode with tools`; `G/concepts/agents/cloud-agent/about-automations § Triggers`, `§ Tools and actions`

## Input
- **Entry points:** assigning an issue, the agents tab or panel, Copilot Chat (`/task` carries over the chat context), `@copilot` in a PR comment, seeding a repository, a failing Actions run, GitHub Mobile, IDEs, REST API, GitHub CLI, the GitHub MCP Server and integrations; an eyes reaction confirms the session started. `G/how-tos/use-copilot-agents/cloud-agent/create-a-pr § Starting GitHub Copilot sessions`; `G/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github § Starting from Copilot Chat`, `§ Continuing work on a pull request § Tracking and continuing a session`
- **Mid-session steering:** a follow-up typed below the session log is applied "after it finishes its current tool call"; each steering message consumes AI credits; in agent mode a follow-up prompt redirects the agent before it finishes. `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Steer an agent session`; `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Steering an agent while it works`
- **Review comments re-enter:** `@copilot` mentions on any pull request, or batched review comments via Add to batch, start a new session on that PR's branch; comments from users without write access "are never shown to the agent"; hidden characters such as HTML comments are filtered before input reaches the agent; images dropped into an issue or prompt are processed. `G/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github § Continuing work on a pull request § Asking Copilot to make changes`, `§ Delegating review comments`; `G/concepts/agents/cloud-agent/risks-and-mitigations § AI prompts can be vulnerable to injection`; `G/how-tos/copilot-on-github/use-copilot-agents/research-plan-iterate § Provide visual context`
- **Tool results re-enter:** not documented beyond session logs showing "tool calls" and "commands" with their results feeding the next step. `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Review session logs`

## Context
- **Custom instructions:** `.github/copilot-instructions.md` (repository-wide), `.github/instructions/*.instructions.md` with `applyTo` globs (cloud agent and code review only on GitHub.com), nested `AGENTS.md` where "the nearest `AGENTS.md` file in the directory tree will take precedence", or a root `CLAUDE.md`/`GEMINI.md`, plus organization instructions; "Instructions are automatically added to requests that you submit to Copilot" and "all sets of relevant instructions are provided to Copilot"; `excludeAgent: cloud-agent` keeps a file from the cloud agent. `G/how-tos/configure-custom-instructions/add-repository-instructions § Creating repository-wide custom instructions`, `§ Creating path-specific custom instructions`, `§ Custom instructions in use`; `G/concepts/prompting/response-customization § Precedence of custom instructions`
- **Custom agents and skills:** an agent profile supplies "Custom instructions that define the agent's behavior and expertise" and a `tools` allowlist; agent skills are "folders of instructions, scripts, and resources" in `.github/skills`, `.claude/skills` or `.agents/skills` that Copilot loads when relevant (loading mechanism not documented). `G/concepts/agents/cloud-agent/about-custom-agents § Agent profile format`; `G/concepts/agents/about-agent-skills § About agent skills`
- **Memory:** Copilot Memory keeps repository-level facts (with code citations, created only from write-access users' activity) and user-level preferences; when Copilot creates context for an agent session it retrieves relevant memories, checks citations against the current branch and "Only validated facts are used"; unused entries are deleted after 28 days; used by cloud agent, code review, CLI and agentic autofix. `G/concepts/agents/copilot-memory § How Copilot Memory stores, retains, and uses information § Repository-level facts`, `§ Retention and validation`, `§ Feature availability`
- **Session context and codebase access:** chat and the cloud agent share session context, which is "separate from Copilot Memory"; the GitHub MCP server gives read-only access to the current repository by default; the agent reads the checked-out repository in its Actions environment; in agent mode VS Code adds the active file and selection and `#codebase` references the workspace. `G/concepts/copilot-surfaces/copilot-on-github § Chat and agentic experiences § Session context`, `§ Limitations and compatibility § Agentic work`
- **Summarization and window handling:** not documented; the only window fact is that a 1M-token context "is available in Visual Studio Code and Copilot CLI only" and larger settings raise credit consumption. `G/reference/ai-models/supported-models § Models with extended capabilities`

## Model interface
- **Models:** the cloud agent offers Auto plus Claude (Opus 5, 5.5, Sonnet 5.5, Haiku 4.5, 5.5), Gemini (3.7, 3.8 Flash, 4 Argon), GPT (5.4 mini, 5.6 Luna/Sol/Terra, 6 Astra/Luna/Sol, 6.1 Sol), Grok (4.5 to 4.7) and MAI-Code-1.1-Flash; a reasoning-level dropdown appears for models that support it. `G/how-tos/use-copilot-agents/cloud-agent/changing-the-ai-model § Supported models`, `§ Reasoning level`
- **How reached:** through GitHub's Copilot API hosts (`api.*.githubcopilot.com`, `uploads.github.com` must be reachable from the runner); wire format and streaming are not documented; Anthropic retains Fable 5/5.1 prompts for safety classifiers while other Claude models run under zero data retention. `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § Upgrading to larger GitHub-hosted GitHub Actions runners`; `G/reference/ai-models/supported-models § Supported AI models in Copilot`
- **Auto selection and fallback:** "Where a model picker is not available, Auto will be used automatically"; Auto combines a system that "tracks real-time system health and availability" with one that "evaluates task complexity", excludes models outside the plan or blocked by policy, and gives a 10% discount; GPT-5.3-Codex is the LTS model "used in the event no other models are available". `G/how-tos/use-copilot-agents/cloud-agent/changing-the-ai-model § Introduction`; `G/concepts/models/auto-model-selection § Auto with task optimization`, `§ Policies and availability`, `§ Discount for using auto model selection`; `G/reference/ai-models/supported-models § Supported AI models in Auto model selection`
- **Limits and billing:** usage is metered in AI credits (1 credit = $0.01) where "Each token is priced based on the model used"; Business includes 1,900 and Enterprise 3,900 credits per user per month; retry policy is not documented. `G/concepts/billing/usage-based-billing-for-organizations-and-enterprises § What are GitHub AI Credits?`, `§ How do AI credits work?`

## Output
- **Tool set:** the cloud agent has a Bash tool (named in the firewall docs), file-editing and repository tools, the built-in GitHub MCP server (read-only token scoped to the current repository) and Playwright MCP server, plus repository-configured MCP servers; the exact built-in tool list is not documented. `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-firewall § Limitations`; `G/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers § Introduction`, `§ Customizing the built-in GitHub MCP server`
- **Execution environment:** an ephemeral GitHub Actions job on a GitHub-hosted Ubuntu runner (larger, Windows or self-hosted ephemeral runners optional); `.github/workflows/copilot-setup-steps.yml` with a single `copilot-setup-steps` job preinstalls dependencies, honoring only `steps`, `permissions`, `runs-on`, `services`, `snapshot` and `timeout-minutes` (max 59); if a setup step fails "Copilot will skip the remaining setup steps and begin working". `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § Customizing Copilot's development environment with Copilot setup steps`, `§ Using self-hosted GitHub Actions runners`
- **Sandboxing and network:** an integrated firewall limits internet access by default to a recommended allowlist (package registries, container registries, certificate authorities) plus org and repo custom rules; it "only operates within the GitHub Actions appliance environment", covers only processes started through the Bash tool (not MCP servers or setup steps), and a blocked request adds a warning to the PR naming the address and command. `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-firewall § Overview`, `§ Limitations`, `§ Understanding the recommended firewall allowlist`
- **MCP:** JSON in repository settings with `type` (`local`, `stdio`, `http`, `sse`) and a required `tools` allowlist (`*` for all); only tools, not resources or prompts; no OAuth remote servers; secrets as `COPILOT_MCP_*` variables; MCP tools "will be able to use the tools provided by the server autonomously" with no approval. `G/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers § Writing a JSON configuration for MCP servers`, `§ Introduction`, `§ Adding an MCP configuration to your repository`
- **Result presentation:** commits pushed to a `copilot/` branch via "simple push operations" only (no direct `git push`), a draft pull request (or Diff view in the session before one is requested), screenshots and logs in session logs; Copilot "cannot mark its PRs ready for review, approve them, or merge them"; in agent mode edits stream into the editor and can be undone. `G/concepts/agents/cloud-agent/risks-and-mitigations § Copilot cloud agent can push code changes to your repository`; `G/how-tos/copilot-on-github/use-copilot-agents/research-plan-iterate § Iterate on code changes`; `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Steering an agent while it works`

## Production concerns
- **Persistence:** session logs and shared sessions are kept and queryable (observability); Copilot Memory outlasts sessions with a 28-day unused-deletion timer (context); the Actions environment is ephemeral and only pushed commits survive a stop (output). `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Query past sessions`, `§ Stop a session`; `G/concepts/agents/copilot-memory § Retention and validation`
- **Safety & security:** firewall and read-only GitHub token (output); write-access-only triggers, hidden-character filtering, `copilot/` branch confinement, workflow approval, requester cannot approve, secret scanning of Copilot's code, rulesets and branch protections still apply (control flow and output); `preToolUse` hooks can deny; MCP tools run autonomously so allowlisting read-only tools is recommended; `.github/hooks/*.json` run as shell commands. `G/concepts/agents/cloud-agent/risks-and-mitigations § Copilot cloud agent can push code changes to your repository`, `§ AI prompts can be vulnerable to injection`, `§ Unvalidated code can introduce vulnerabilities`; `G/concepts/agents/hooks § Types of hooks`; `G/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers § Writing a JSON configuration for MCP servers`
- **Observability:** session logs show "Reasoning", "Tool calls" and "Commands", with token usage and session length on the overview; every commit links back to its session log; setup-step and Start MCP Servers output appears in the logs; JetBrains supports OpenTelemetry agent monitoring. `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Monitor agent activity`, `§ Review session logs`, `§ Trace commits to session logs`; `G/concepts/copilot-surfaces/copilot-in-ides § Using Copilot in other IDEs § Entry points in JetBrains IDEs`
- **Resilience:** 59-minute hard timeout; setup failures are skipped rather than fatal; Auto routes on live service health; hooks have `timeoutSec` default 30 and run synchronously; model-request retries and compaction on overflow are not documented. `G/concepts/copilot-surfaces/copilot-on-github § Limitations and compatibility § Agentic work`; `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § Customizing Copilot's development environment with Copilot setup steps`; `G/concepts/models/auto-model-selection § Auto with task optimization`; `G/concepts/agents/hooks § Hook configuration format`
- **Performance:** preinstalled dependencies via setup steps avoid trial-and-error installs; larger runners for CPU, memory and disk; cached tokens priced separately (caching mechanism not documented); keep hooks "under 5 seconds when possible". `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § Preinstalling tools or dependencies in Copilot's environment`, `§ Upgrading to larger GitHub-hosted GitHub Actions runners`; `G/concepts/billing/usage-based-billing-for-organizations-and-enterprises § How do AI credits work?`; `G/concepts/agents/hooks § Performance considerations`
- **Evaluation:** not documented beyond thumbs up or down feedback on Copilot's pull requests and comments. `G/how-tos/use-copilot-agents/cloud-agent/review-copilot-prs § Give feedback on Copilot's work`

## Hard to place
- **GitHub Actions as both executor and loop boundary:** the Actions job is the output executor (sandbox, runner) but its `timeout-minutes` and the Stop session button end the loop, so one artifact carries an output mechanism and a control-flow budget; placed in both. `G/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment § Customizing Copilot's development environment with Copilot setup steps`; `G/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents § Stop a session`
- **Workflow approval after the session:** the Approve and run workflows gate is a human decision the harness consumes, but it fires after the agent has stopped, gating CI on the PR rather than the agent's loop; it is a control-flow gate of GitHub's PR pipeline, not of the agent harness. `G/how-tos/use-copilot-agents/cloud-agent/review-copilot-prs § Manage GitHub Actions workflow runs`
- **Copilot Memory validation:** a record kept for the model (context) that is re-validated against the current branch before use, which is a context-assembly step performed by a model-driven check; the docs do not say whether a model call is involved, so the mechanism is not documented. `G/concepts/agents/copilot-memory § How Copilot Memory stores, retains, and uses information § Repository-level facts`
- **Agent mode internals:** docs.github.com describes agent mode only as iterating with command confirmation; its loop, tool list and request caps are documented by the editor vendors, so the harness cannot be fully deconstructed from this source. `G/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode § Introduction`

## Summary
| Primitive | Design decision |
|---|---|
| Input | Issues, @copilot mentions, chat handoff, API and automations; steering applied after the current tool call; write-access only |
| Context | Layered instruction files, custom agents, skills and validated 28-day memory; summarization not documented |
| Model interface | GitHub-hosted Copilot API, Auto routing on health and task complexity, LTS fallback, AI-credit metering |
| Output | Ephemeral Actions runner with firewall, Bash plus read-only GitHub MCP, pushes to copilot/ branch, draft PR |
| Control flow | Background session with 59-minute cap, no in-session approvals, edge gates on triggers and workflows, automations |
