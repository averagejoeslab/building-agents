# OpenAI Codex CLI

**Source:** https://github.com/openai/codex · **Version:** commit f0c5077c34ec7a76b4ad9134835925e6ae3d72ec (2026-10-15) · **Language:** Rust (workspace under `codex-rs/`)
**Path conventions:** all paths are relative to `codex-rs/`. `core/` = crate `codex-core`; `session/` = `core/src/session/`; `tools/` under core = `core/src/tools/`; top-level crates (`codex-api`, `sandboxing`, `rollout`, `otel`, `prompts`, `protocol`, …) are siblings of `core/`. Line ranges are `L<start>–L<end>` at the pinned commit.
**What it is:** Codex is OpenAI's terminal/IDE coding agent. A `Session` (one thread) receives `Op` submissions over a channel, runs each user turn as a task that loops "sample → run tool calls → sample again" until the model stops calling tools, and talks to the OpenAI Responses API over HTTP SSE or a Responses WebSocket. It wraps execution in OS sandboxes (Seatbelt / seccomp+bwrap / Windows restricted token), gates risky actions with user or "Guardian" (model-reviewer) approvals, persists every thread as a JSONL rollout, and can spawn sub-agent threads that are full `Session`s of their own.

## Control flow
- **Submission loop (session-level dispatcher):** `submission_loop` `select!`s on shutdown, the `rx_sub` channel and mailbox updates, then matches each `Op` (TurnInput, Interrupt, ExecApproval, UserInputAnswer, Compact, Review, Shutdown…). `core/src/session/handlers.rs:L440–L727`
- **Turn admission modes:** `turn_input::handle` routes a TurnInput by mode: `StartOrSteer`, `StartIfIdle`, `ContinueIfIdle` (recovery requires an internal response item), `Steer { expected_turn_id }`. `core/src/session/turn_input.rs:L230–L296`
- **Task spawn replaces the active task:** `Session::spawn_task` first calls `abort_all_tasks(TurnAbortReason::Replaced)` then `start_task`, which registers the task on `active_turn`, seeds pending input from the mailbox, and sets a fresh `CancellationToken`. `core/src/tasks/mod.rs:L273–L340`
- **Abort / interrupt:** `abort_all_tasks` takes the active turn, cancels the task and clears pending approvals; on `Interrupted` it may immediately start a new turn for pending work. `core/src/tasks/mod.rs:L564–L592`
- **Outer task loop (RegularTask::run):** calls `run_turn` repeatedly until there is no pending input or a terminal error was recorded. `core/src/tasks/regular.rs:L105–L124`
- **Inner turn loop (run_turn):** `loop { drain pending input → capture StepContext → build sampling input → run_sampling_request → decide follow-up }`; `needs_follow_up = model_needs_follow_up || has_pending_input`; stops with `break` when `!needs_follow_up` after stop hooks run. `core/src/session/turn.rs:L453–L578`, `L604`, `L718–L821`
- **Stop condition from the model:** `try_run_sampling_request` sets `needs_follow_up = true` when any output item is a tool call, and on `ResponseEvent::Completed { end_turn: Some(false) }`. `core/src/stream_events_utils.rs:L351–L354`; `core/src/session/turn.rs:L3112–L3118`
- **Stop hooks can force another iteration:** `run_turn_stop_hooks` result `should_block` with a continuation prompt records a hook message, sets `stop_hook_active` and `continue`s the loop; `should_stop` breaks. `core/src/session/turn.rs:L718–L768`
- **Mid-turn roll-over on context limit:** `should_roll_over = auto_compaction_enabled && needs_follow_up && (new_context_window requested || token_limit_reached || background candidate ready)` triggers `run_auto_compact(..MidTurn..)` then `continue`. `core/src/session/turn.rs:L654–L716`
- **Steering (user message while a turn runs):** `steer_input` validates the active task is a Regular task (Review/Compact are non-steerable), then pushes the input onto `turn_state.pending_input` for the next loop iteration. `core/src/session/turn_input.rs:L799–L889`
- **Pending-input drain point:** `get_pending_input` splits off `turn_state.pending_input.items` and appends mailbox items only if the turn currently accepts mailbox delivery. `core/src/session/input_queue.rs:L400–L432`
- **Sampling retry loop:** `run_sampling_request` wraps `try_run_sampling_request` in a `loop` whose continuation is decided by `handle_response_stream_error` (retry budget `stream_max_retries`), and returns early with `needs_follow_up: true` on preempt. `core/src/session/turn.rs:L1707–L1835`
- **Approval gate consumed by harness (user):** `Session::request_command_approval` registers a `oneshot` under the approval id, emits `EventMsg::ExecApprovalRequest`, and awaits `rx_approve` (defaulting to `Abort` if dropped); `exec_approval` resolves it, and `Abort` calls `interrupt_task`. `core/src/session/mod.rs:L2923–L3012`; `core/src/session/handlers.rs:L177–L207`
- **Approval precedence:** hooks first, then Guardian (model reviewer) if enabled/strict, else user. `core/src/tools/approvals.rs:L479–L498`, `L541–L557`
- **Session-scoped approval cache:** `with_cached_approval` returns `ApprovedForSession` without asking when every cache key already holds that decision. `core/src/tools/sandboxing.rs:L72–L110`
- **Sub-agent spawn (effect of `spawn_agent` tool):** `thread_spawn::spawn` builds a `SessionSource::SubAgent(ThreadSpawn{parent_thread_id, depth, …})` and calls `agent_control.spawn(SpawnRequest{ input: AgentInput::Message{ mode: TriggerTurn }, … })`. `core/src/thread_spawn.rs:L58–L167`
- **Depth and fan-out limits:** `exceeds_thread_spawn_depth_limit(depth, max_depth)` (`depth > max_depth`) rejects a spawn with "Agent depth limit reached. Solve the task yourself."; `reserve_spawn_slot` returns `AgentLimitReached { max_threads }` when the registry is full. `core/src/agent/registry.rs:L85–L109`; `core/src/tools/handlers/multi_agents/spawn.rs:L74–L80`
- **Sub-agent results return:** `wait_agent` polls child status futures with `timeout_at(deadline, …)` (default `DEFAULT_WAIT_TIMEOUT_MS`) and collects final statuses; `send_input` steers or starts a child turn through `start_or_steer_turn`. `core/src/tools/handlers/multi_agents/wait.rs:L95–L99`, `L181–L200`; `core/src/agent/control.rs:L137–L165`
- **Delegate (review / guardian) sub-session:** `run_codex_thread_one_shot` → `run_codex_thread_interactive` → `Session::spawn(SessionSpawnArgs{ thread_source: Subagent|GuardianReview, agent_control: Provided, … })`; child events/ops are forwarded via `forward_session_io` tasks. `core/src/codex_delegate.rs:L105–L228`, `L231–L262`
- **Routing keyed to the work (review model):** the review task clones config, disables web search/collab, sets `base_instructions = REVIEW_PROMPT`, `approval_policy = Never`, and `model = config.review_model` before delegating. `core/src/tasks/review.rs:L105–L140`
- **Routing keyed to the work (guardian model):** the reviewer session resolves its own `review_model` and reasoning effort separately from the parent. `core/src/guardian/review_session.rs:L330–L372`
- **Code mode: model-written program sequences tools (output), but can call back into the harness:** nested calls from a cell go through `CodeModeCellDelegate::invoke_tool` → `DispatchMessage::InvokeTool` to the turn worker; the program sequences tools only, not model calls. `core/src/tools/code_mode/delegate.rs:L317–L360`
- **Session token budget (stop):** `record_rollout_budget_usage` returns `SessionBudgetExceeded` once weighted usage reaches `limit_tokens`. `core/src/agent/control/budget.rs:L12–L17`; `core/src/rollout_budget.rs:L48–L65`
- **Model-requested context reset (`new_context_window` tool):** the handler calls `session.request_new_context_window()`, which the run_turn roll-over check consumes via `take_new_context_window_request`. `core/src/tools/handlers/new_context_window.rs:L44–L56`; `core/src/session/turn.rs:L659–L663`

## Input
- **Op channel + public thread API:** `CodexThread::submit(op)` sends into `io.tx_sub`; `next_event()` reads `io.rx_event`. `core/src/codex_thread.rs:L258–L260`, `L773–L775`

- **Person's answer the MODEL consumes:** `request_user_input` tool awaits `session.request_user_input(...)` and serializes the `RequestUserInputResponse` back as the tool result; delivered by `Op::UserInputAnswer { id, response }`. `core/src/tools/handlers/request_user_input.rs:L78–L100`; `protocol/src/protocol.rs:L791–L797`

- **Inter-agent mail / mailbox:** `Op::InterAgentCommunication` and mailbox updates (`mailbox_updates`, `notify_mailbox`) feed pending input; mailbox delivery can preempt a response between items. `core/src/session/handlers.rs:L447–L479`, `L649–L656`; `core/src/session/turn.rs:L2913–L2932`
- **Hook-contributed input:** `drain_async_hook_results` records results of async hooks before/after the user prompt. `core/src/hook_runtime.rs:L782`; `core/src/session/turn.rs:L185`, `L591`

## Context
- **Base instructions come from the model catalog:** `render_model_instructions` reads `model_info.model_messages.instructions_template`; the bundled default is `BASE_INSTRUCTIONS = include_str!("../prompt.md")` in models-manager, overridable by `config.base_instructions`. `prompts/src/model_instructions.rs:L8–L17`; `models-manager/src/model_info.rs:L16`, `L46–L48`
- **Prompt assembly per sampling request:** `build_prompt` packs `input` (history), `tools = tool_router.model_visible_specs()`, `parallel_tool_calls: true`, `base_instructions`, `output_schema`; with incremental tools (WebSocket continuation) tools and instructions are sent empty. `core/src/session/turn.rs:L1666–L1694`
- **History normalization before send:** `for_prompt` → `normalize_history`: ensure every call has an output, drop orphan outputs, strip images/audio the model can't take. `core/src/context_manager/history.rs:L603–L617`, `L968–L982`
- **Tool-output truncation on record:** `record_item_with_metadata` applies `truncate_function_output_payload(output, policy, …)` to Function/CustomToolCallOutput using the model's `truncation_policy` (live history only; rollout keeps full payload). `core/src/context_manager/history.rs:L517–L519`, `L568–L577`
- **World-state sections (diff-injected context):** `WorldStateSection` trait — typed sections (`agents_md`, `environment`, `permissions`, `tools`, `model`, …) each render a diff vs. the previous snapshot; `WorldStateSnapshot::merge_patch_from` produces an RFC 7386 merge patch. `core/src/context/world_state/mod.rs:L302–L330`, `L381–L425`
- **Per-step world-state injection:** `record_step_world_state_if_changed` renders the step's world state, records only the changed fragments into history, and persists a `RolloutItem::WorldState` patch. `core/src/session/mod.rs:L3762–L3793`
- **AGENTS.md discovery:** walks from project root (marker `.git` by default) down to cwd, concatenating every `AGENTS.md`, bounded by `project_doc_max_bytes`; skipped for untrusted projects. `core/src/agents_md.rs:L1–L18`, `L58–L68`; refreshed per step in `capture_step_context_inner`. `core/src/session/mod.rs:L3915–L3924`
- **AGENTS.md as a world-state section:** `AgentsMdState` renders replacement/removal notices when the instructions change. `core/src/context/world_state/agents_md.rs:L11–L60`
- **Environment context:** `FileSystemContext { workspace_roots, permission_profile }` and `NetworkContext` are rendered into the model-visible environment section. `core/src/context/environment_context.rs:L10–L30`, `L213`
- **Developer instructions + extension contributors:** `build_initial_context_with_world_state` collects developer sections, plugin recommendations, and `context_contributors().contribute_thread_context/turn_context` fragments into developer/user slots. `core/src/session/mod.rs:L4473–L4560`
- **Skills injected on mention:** `build_skills_and_plugins` loads prompts for explicitly mentioned skills (`load_skill_prompts`) and converts each fragment into a response item recorded into history. `core/src/session/turn.rs:L1099`, `L1165–L1190`, `L1222–L1236`; recorded at `L409–L416`
- **Memory read-path context:** `MemoryContextFragment::{ReadInstructions (developer), ExtractionEvidence (user)}`, capped below 10k tokens; memory root is `$CODEX_HOME/memories`. `core/src/context/memory.rs:L1–L30`; `memories/read/src/lib.rs:L13`
- **Tool catalog for the step:** `built_tools` builds a `ToolRouter` from MCP tools, connectors and tool-suggest candidates; `capture_step_context_inner` joins MCP refresh and tool build into a `StepContext`. `core/src/session/turn.rs:L1884–L1973`; `core/src/session/mod.rs:L3959–L4030`
- **Deferred tools (tool search):** `ToolExposure::Deferred` tools are omitted from the initial list and discoverable through the `tool_search` tool. `tools/src/tool_executor.rs:L48–L62`; `core/src/tools/handlers/tool_search.rs:L68–L85`
- **Compaction trigger math:** `context_window_token_status` computes `token_limit_reached` (auto-compact limit + fallback buffer, or `effective_context_window_percent` of the window) and `turn_end_compaction_threshold_reached` (`model_post_turn_compact_threshold_percent`). `core/src/session/context_window.rs:L53–L130`
- **Pre-turn / post-turn compaction:** `run_pre_sampling_compact` runs before the user input is recorded; post-turn compaction runs when `foreground_due || candidate.is_some()`. `core/src/session/turn.rs:L192–L212`, `L779–L817`
- **Compaction implementation selection:** `run_auto_compact` chooses token-budget reset (`Feature::TokenBudget`), remote `ResponsesCompactionV2`, or local summarization. `core/src/session/turn.rs:L1507–L1570`; `core/src/compact_remote_v2.rs:L112–L140`
- **Local summarization compaction:** `run_compact_task_inner_impl` sends history + `SUMMARIZATION_PROMPT` (`prompts/templates/compact/prompt.md`) to the model, then `build_compacted_history` keeps initial context + up to `COMPACT_USER_MESSAGE_MAX_TOKENS = 20_000` tokens of recent user messages + the summary. `core/src/compact.rs:L62–L64`, `L264–L330`, `L702–L760`
- **Background (speculative) compaction:** `async_compaction::maybe_start` launches a parallel compaction once usage passes `async_compaction_threshold_percent` of the window, deduped by history version/model/hash. `core/src/session/async_compaction.rs:L1–L9`, `L62–L95`
- **Model-queryable context remaining (`get_context_remaining` tool):** reports `base_window_tokens_remaining` from `context_window_token_status`. `core/src/tools/handlers/get_context_remaining.rs:L85–L92`

## Model interface
- **Client lifetimes:** `ModelClient` lives for the session; `ModelClientSession` is created per turn, caches a Responses WebSocket and the `x-codex-turn-state` sticky-routing token. `core/src/client.rs:L1–L26`, `L295–L303`
- **Wire format:** `ResponsesApiRequest { model, input, tools, tool_choice: "auto", parallel_tool_calls, reasoning, store: false, stream: true, include: ["reasoning.encrypted_content", …], prompt_cache_key, text, … }` posted to `/responses`. `core/src/client.rs:L1040–L1095`; `codex-api/src/endpoint/responses.rs:L110–L139`
- **Transport selection + fallback:** `ModelClientSession::stream` tries `stream_responses_websocket` when the provider supports it and falls back to `ResponsesHttpExecutor::stream_responses_http`; `try_switch_fallback_transport` permanently disables WebSockets for the session. `core/src/client.rs:L2363–L2435`
- **SSE event parsing + idle timeout:** `process_sse` maps `response.output_item.done`, `response.output_text.delta`, `response.completed|incomplete` to `ResponseEvent`s; each poll is `timeout(idle_timeout, stream.next())` with default `DEFAULT_STREAM_IDLE_TIMEOUT_MS = 300_000`. `codex-api/src/sse/responses.rs:L345–L470`, `L554–L558`; `model-provider-info/src/lib.rs:L66`, `L513–L516`
- **Retry policy:** `handle_response_stream_error`: terminal errors (context exceeded, usage limit, invalid request…) return `None` delay; retryable ones use server `Retry-After` else exponential backoff with ±10% jitter; budget `DEFAULT_STREAM_MAX_RETRIES = 5`; unbounded connection retries (5s→60s doubling) behind `Feature::UnboundedConnectionRetries`; after exhausting the budget on WebSocket it switches to HTTPS and resets the counter. `core/src/responses_retry.rs:L23–L24`, `L57–L176`; `protocol/src/error.rs:L410–L440`; `codex-client/src/retry.rs:L43–L52`; `model-provider-info/src/lib.rs:L67`, `L506–L508`
- **Content-filter retry injects guidance (context effect):** on `ContentFilter` the retry path records a `ContentFilterGuidance` user fragment before retrying. `core/src/responses_retry.rs:L67–L82`
- **Receiving the stream:** `try_run_sampling_request` opens `client_session.stream(prompt, model_info, …)` and loops on `stream.next()` under preempt/cancellation. `core/src/session/turn.rs:L2667–L2715`
- **Token usage from the wire:** on `Completed { token_usage, … }` the session records usage (`record_token_usage_info`) and emits a token-count event. `core/src/session/turn.rs:L3069–L3118`, `L3295–L3301`
- **Auth-expiry recovery:** `PendingUnauthorizedRetry` retries a request once after refreshing credentials on 401. `core/src/client.rs:L1582–L1636`, `L1781–L1925`
- **Prompt cache key:** `prompt_cache_key` is sent per request (override or thread-derived) so the server reuses cached prefixes. `core/src/client.rs:L646–L668`, `L1060`, `L1090`

## Output
- **Tool call recognition:** `ToolRouter::build_tool_call` turns `FunctionCall`, `CustomToolCall`, client-executed `ToolSearchCall`, etc. into a `ToolCall`. `core/src/tools/router.rs:L257–L335`
- **Dispatch:** `handle_output_item_done` logs the call, persists the item, and pushes `tool_runtime.handle_tool_call(call, token)` into the in-flight queue; non-tool items become turn items and are emitted to the client. `core/src/stream_events_utils.rs:L315–L432`
- **Concurrency of tool calls from one response:** `ToolCallRuntime::handle_tool_call` spawns each call on tokio; parallel-safe tools take a read lock on `parallel_execution: RwLock<()>`, others a write lock (serialized). `core/src/tools/parallel.rs:L51`, `L141–L237`; `core/src/tools/router.rs:L246–L250`
- **Streaming text to the person:** `OutputTextDelta` is parsed and emitted as assistant text deltas; the TUI appends them via `on_agent_message_delta` → `handle_streaming_delta`. `core/src/session/turn.rs:L3120–L3135`; `tui/src/chatwidget/streaming.rs:L206–L208`
- **Diff artifact for the user:** `TurnDiffTracker` accumulates file changes and emits `EventMsg::TurnDiff { unified_diff }` after each response. `core/src/session/turn.rs:L441–L443`, `L3307–L3317`
- **Exec tool (`exec_command` / `write_stdin`):** Unified Exec manages PTY processes with output caps (`DEFAULT_MAX_OUTPUT_TOKENS = 10_000`, `UNIFIED_EXEC_OUTPUT_MAX_BYTES = 1 MiB`) and yield-time bounds. `core/src/unified_exec/mod.rs:L1–L25`, `L68–L76`; `core/src/tools/handlers/unified_exec/exec_command.rs:L109`; `core/src/tools/handlers/unified_exec/write_stdin.rs:L39`
- **Exec timeout:** `DEFAULT_EXEC_COMMAND_TIMEOUT_MS = 10_000`; `ExecExpiration::{Timeout, DefaultTimeout, Cancellation, TimeoutOrCancellation}`. `core/src/exec.rs:L63`, `L173–L223`
- **Orchestrator (approval → sandbox → run → retry):** `ExecApprovalRequirement::{Skip, Forbidden, NeedsApproval}` decides whether to ask; on sandbox denial it retries without a sandbox only if policy allows (`Never`/`OnRequest` do not retry). `core/src/tools/orchestrator.rs:L164–L222`, `L439–L470`
- **Sandbox technology:** `get_platform_sandbox` → macOS `MacosSeatbelt`, Linux `LinuxSeccomp` (bwrap + seccomp + Landlock), Windows `WindowsRestrictedToken`/`WindowsMxc`. `sandboxing/src/manager.rs:L50–L63`; `protocol/src/sandbox.rs:L29–L35`; `sandboxing/src/{seatbelt.rs,bwrap.rs,landlock.rs}`; `linux-sandbox/src/seccomp.rs`
- **Remote executor:** `codex-exec-server` is a JSON-RPC server for spawning/controlling subprocesses via `codex-utils-pty`, used for non-local environments. `exec-server/README.md` (top), `exec-server/src/lib.rs:L1–L12`
- **Patch tool safety:** `assess_patch_safety` auto-approves patches confined to writable roots (still run in a sandbox), rejects under `Never`, otherwise asks. `core/src/safety.rs:L67–L125`, `L146–L180`
- **MCP tool calls:** `handle_mcp_tool_call` prepares the call, applies approval policy, and invokes the server via `prepared_call.call_with_preparation`. `core/src/mcp_tool_call.rs:L131–L145`, `L473–L478`
- **Code mode executor (`exec` tool):** the `exec` tool runs model-written JS in a V8 host process reached over gRPC; nested tool calls are brokered back to the harness. `code-mode-protocol/src/lib.rs:L54`; `core/src/code_mode_host.rs:L1–L4`; `core/src/tools/code_mode/execute_handler.rs:L176–L179`
- **Sub-agent tool surface:** `spawn_agent`, `send_input`, `wait_agent`, `resume_agent`, `close_agent` handlers. `core/src/tools/handlers/multi_agents/{spawn.rs,send_input.rs,wait.rs,resume_agent.rs,close_agent.rs}`
- **Review sub-agent as a tool-free delegate:** results come back as events through `forward_events`. `core/src/codex_delegate.rs:L200–L228`

## Design decisions (one line each: the choice this harness made within a primitive)
- Input: a single `Op` channel per thread; user text during a running turn is queued (steer) rather than starting a new turn, and the model's questions come back as a typed `UserInputAnswer` op.
- Context: history is the Responses item list itself; environment/instructions are typed "world-state sections" injected as diffs, tool outputs are token-truncated in live history only, and compaction is pluggable (local summary, remote v2, or budget reset).
- Model interface: Responses API only (`WireApi::Responses`), WebSocket-first with session-wide HTTP fallback, server-advised retry timing, `store: false` with encrypted reasoning replay.
- Output: every risky action goes through one orchestrator (approval → platform sandbox → run → sandbox-denied retry); tools run concurrently under a read/write gate; a V8 "code mode" lets the model batch tool calls in JS.
- Control flow: one task per turn, inner loop until the model emits no tool call (or `end_turn=false`), with compaction roll-over, stop hooks, and sub-agents that are full `Session`s coordinated by `AgentControl` with depth/thread caps.

## Hard cases
- **Guardian (auto-review of approvals):** a harness-consumed gate (control flow) whose decision is produced by a *model* in a separate `Session` (`ThreadSource::GuardianReview`). Rule: "an approval the harness consumes is control flow"; the reviewer itself is an inner harness (multi-agent rule). Placed as control flow, with the reviewer's own loop as a nested harness. `core/src/guardian/mod.rs:L1–L3`; `core/src/codex_delegate.rs:L133–L137`
- **Content-filter retry that injects guidance:** retrying is model interface, but it also records a user fragment into history (context). Split per rule "assign by function". `core/src/responses_retry.rs:L67–L82`
- **Incremental tools over WebSocket:** `build_prompt` deliberately sends empty tools/instructions when the server already holds them (`previous_response_id`). What the model is shown is unchanged, but the request contents depend on transport state — placed as model interface with a context dependency. `core/src/session/turn.rs:L1675–L1689`; `core/src/client.rs:L2137–L2160`
- **Remote compaction v2:** the *server* summarizes (`CompactionImplementation::ResponsesCompactionV2`); the harness decides when (context) but the summarizer is the model/provider. Placed as context (the fitting step) with the call as model interface. `core/src/compact_remote_v2.rs:L112–L140`
- **Code mode:** the model-written program runs in V8 and sequences only tools (output per rule), yet nested calls re-enter the harness's approval/sandbox path, so each nested call is a normal output-side tool call. `core/src/tools/code_mode/delegate.rs:L317–L360`
- **`new_context_window` / `get_context_remaining` tools:** tools whose only effect is on context (reset request) or that expose context state to the model; the call is output, the effect is context/control flow per the "effect" rule. `core/src/tools/handlers/new_context_window.rs:L44–L56`
- **World-state diffing:** context mechanism that also writes a `RolloutItem::WorldState` for persistence; the model-facing part is context, the file write is persistence. `core/src/session/mod.rs:L3762–L3793`
- **Steer vs. mailbox vs. hooks as inputs:** three different channels (user steer queue, inter-agent mailbox, async hook results) all merge into `pending_input` before the next request; all are input, drained by control flow. `core/src/session/input_queue.rs:L400–L432`
- **DOES NOT FIT (partially): plan mode streaming parser.** `PlanModeStreamState` parses the assistant's streamed text into a "proposed plan" item and can suppress/redirect deltas — it is output rendering that also changes what is recorded as the last agent message (feeds control flow's stop decision). It straddles output and control flow by design. `core/src/session/turn.rs:L1992`, `L2709`, `L2846–L2858`
