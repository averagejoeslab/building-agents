# Hermes Agent

**Source:** https://github.com/NousResearch/hermes-agent · **Version:** commit 7bf3766f3db72d4643d1a78d18e51c1d9ddf1d6d (2026-10-15) · **Language:** Python (TypeScript for the TUI/desktop front-ends, out of scope)
**Path conventions:** paths are relative to the repo root (`hermes-agent/`). `L` = line. Clone read as untrusted data; nothing executed.
**What it is:** A personal agent by Nous Research that runs one agent core (`AIAgent`) behind a prompt_toolkit CLI/TUI, ~25 messaging-platform gateway adapters (Telegram, Discord, Slack, …), an OpenAI-compatible HTTP server, an ACP adapter, a cron scheduler and a desktop app. The model is reached through an OpenAI-SDK chat-completions client by default, with alternative wire transports for Anthropic Messages, OpenAI Responses ("codex") and Bedrock Converse selected by `api_mode`; providers are plugins and the model slug is config.

## Control flow
- **Turn entry + lease:** `AIAgent.run_conversation` builds a task/turn id and admits a durable turn lease before forwarding to the loop (one turn per session at a time). `agent/turn_facade.py:L22`, `agent/turn_facade.py:L83`
- **Main loop:** `_run_conversation_turn` runs `while (api_call_count < max_iterations and iteration_budget.remaining > 0) or _budget_grace_call`; each iteration = begin → prepare → assemble → preflight gate → API retry loop → normalize → `run_tool_round` if tool calls else `finish_text_response`; post-loop `finalize_turn`. `agent/conversation_loop.py:L1656–L1706`
- **Phase dispatch:** each phase is a sibling function returning a verdict with `action ∈ {fallthrough, continue, break, return}`; `_run_phase` copies verdict fields back into `_LoopState`. `agent/conversation_loop.py:L1389–L1502`
- **Inner retry loop:** `_run_api_retry_loop` loops `while retry_count < max_retries` over guard → build → call → check, with `handle_api_interrupt` / `handle_api_error` branches. `agent/conversation_loop.py:L1505–L1534`
- **Step budget:** `IterationBudget` is a thread-safe counter with `consume()`/`refund()`; `max_iterations` defaults to `sys.maxsize` (unlimited, shared with subagents); a tool round whose only tool was `execute_code` refunds its iteration; a reasoning-only stall that triggers a model fallback sets `_budget_grace_call` for one extra call. `agent/iteration_budget.py:L25–L56`, `run_agent.py:L241`, `agent/turn_tool_round.py:L199–L200`, `agent/turn_truncation.py:L630–L635`
- **Stop gates (go again vs. hand back):** on a text answer, `apply_stop_gates` runs verify-on-stop → `pre_verify` plugin hook → kanban stop guard; a nudge appends a user-role row and continues the loop, holding the answer as a budget-exhaustion fallback. `agent/turn_stop_gates.py:L105–L140`, `agent/turn_stop_gates.py:L35–L50`
- **Tool-call guardrail halt:** a `ToolCallGuardrailController` decision can end the turn (`guardrail_halt`) after a tool round; identical-call stall threshold is 3. `agent/turn_tool_round.py:L179–L193`, `agent/tool_guardrails.py:L30`, `agent/tool_guardrails.py:L307`
- **Approval gate (harness consumes the answer):** `check_all_command_guards` runs floor blocks → yolo/`off` bypass (process `--yolo`, session `/yolo`, `approvals.mode`) → permanent allowlist → unattended-context policy → `detect_dangerous_command` → `_human_decision`; answers are `once/session/always/deny/timeout`; in gateway ask mode the tool returns `status="pending_approval"` instead of blocking. `tools/approval.py:L1151–L1200`, `tools/approval.py:L506–L510`, `tools/approval.py:L796–L802`, `tools/approval_prompt.py:L37`, `tools/terminal_tool.py:L1019–L1028`
- **Interrupt / redirect crossing a response:** if a redirect arrived while the request was in flight the response is discarded and a restart is armed; `_apply_active_turn_redirect` then appends a checkpoint + correction row so role alternation holds. `agent/turn_api_call.py:L148–L167`, `agent/conversation_loop.py:L322–L340`
- **Gateway steer:** a message arriving while a turn runs is injected via `agent.steer()` or queued; after a tool batch, pending steer is folded onto tool results once the per-turn budget is enforced. `gateway/run_inbound.py:L649–L664`, `agent/tool_executor.py:L1209–L1220`
- **Delegation (sub-agents):** `delegate_task` refuses when `_delegate_depth >= delegation.max_spawn_depth` (default 1 = flat); children are full `AIAgent` instances built with `child_depth = parent + 1` and role orchestrator/leaf derived from depth. `tools/delegate_tool.py:L520–L527`, `tools/delegate_tool_config.py:L151–L159`, `tools/delegate_tool.py:L199–L234`
- **Child run, parallelism and result return:** `_run_single_child` runs a pre-built child on a worker thread, heartbeats the parent, and returns `{status ∈ completed|interrupted|failed, exit_reason}`; a batch runs on `DaemonThreadPoolExecutor(max_workers=batch.max_children)` polled with short waits; `background=True` returns a dispatch handle. `tools/delegate_tool.py:L342–L406`, `tools/delegate_tool_dispatch.py:L118–L145`, `tools/delegate_tool_dispatch.py:L470–L478`
- **Work-keyed model routing (auxiliary):** titling, compression summaries, vision etc. resolve via `_resolve_auto_route` (main model → per-task fallback chain → discovery chain); titles come from one small-model call off the critical path. `agent/auxiliary_client.py:L4659–L4684`, `agent/title_generator.py:L1–L5`
- **Mixture-of-Agents turn:** `/moa` gathers reference-model context before each iteration while the normal loop keeps tool calling. `agent/moa_loop.py:L1–L5`
- **Cron turns:** the scheduler runs `agent.run_conversation` on a worker thread under an inactivity watchdog (default 600 s) on a fresh `AIAgent(platform="cron")`. `cron/scheduler.py:L1961–L1963`, `cron/scheduler.py:L2496–L2525`
- **Codex app-server handoff:** when `api_mode == "codex_app_server"` the whole turn is handed to an external codex subprocess; on failure a fallback is activated and the generic loop retries the same user turn. `agent/conversation_loop.py:L1650–L1651`, `agent/conversation_loop.py:L1537–L1552`

## Input
- **CLI REPL:** a worker thread drains `_pending_input` (queue) and dispatches each input; `_looks_like_slash_command` routes to `process_command`, else `self.chat(...)`; `/skill-name` is rewritten into a user message. `hermes_cli/cli_tui_runtime_mixin.py:L31–L47`, `hermes_cli/cli_tui_runtime_mixin.py:L139`, `cli.py:L710`, `cli.py:L1300`
- **CLI chat turn:** `chat()` runs the agent on a daemon thread; input typed meanwhile goes to `_interrupt_queue` and is re-queued as the next turn; the call is `run_conversation(user_message, conversation_history[:-1], stream_callback, task_id, persist_user_message)`. `hermes_cli/cli_chat_turn_mixin.py:L49–L60`, `hermes_cli/cli_chat_turn_mixin.py:L115–L118`, `hermes_cli/cli_chat_turn_mixin.py:L326–L330`
- **Gateway event shape:** every adapter normalizes to `MessageEvent(text, message_type, user_id, …)`; adapters subclass `BasePlatformAdapter`; in-tree adapters (signal, webhook, bluebubbles, weixin, yuanbao, whatsapp_cloud, api_server) plus plugin adapters (telegram, discord, slack, matrix, teams, email, irc, …). `gateway/platforms/event.py:L45–L51`, `gateway/platforms/base.py:L1876`, `gateway/platforms/` (listing), `plugins/platforms/` (listing)
- **Gateway inbound pipeline:** `_handle_message` = admit → pending-reply intercepts → authority admission → running-session handling (steer/interrupt/preempt) → idle commands → `_handle_message_with_agent`. `gateway/run_inbound.py:L1196–L1300`
- **Authorization and bot-loop budget at admission:** unauthorized users get a pairing code (DM) or are ignored before any session state is touched; bot-authored messages are capped by a sliding window per conversation. `gateway/run_inbound.py:L201–L225`, `gateway/bot_loop_guard.py:L1–L5`
- **Gateway → agent call:** the turn runner calls `agent.run_conversation(api_message, **kwargs)` with `persist_user_message`, display kind and the raw platform message id. `gateway/run_turn_runner.py:L934–L936`
- **HTTP and webhook input:** OpenAI-compatible aiohttp server (`/v1/chat/completions`, `/v1/responses`, `/v1/runs`, …); webhook payloads are treated as untrusted and get no file/system execution toolset. `gateway/platforms/api_server.py:L1–L5`, `toolsets.py:L41`
- **ACP input:** the ACP agent calls `agent.run_conversation(user_message=…, conversation_history=state.history)`. `acp_adapter/server.py:L816–L819`
- **Model asks the user (clarify):** `clarify` is an inline agent tool whose UI is a platform callback; the gateway intercepts the reply and its result returns to the model. `tools/clarify_tool.py:L1–L6`, `tools/clarify_tool.py:L111`, `gateway/run_inbound.py:L339`
- **Tool results captured:** every executed tool's result is committed as a `role: tool` row (`_commit_tool_result`); invalid names get an error tool row so each call has a matching result. `agent/tool_executor.py:L1066`, `agent/turn_tool_round.py:L116–L121`
- **Multimodal:** native image parts attached to the user turn stay visible to `vision_analyze` for the turn. `agent/conversation_loop.py:L1749`

## Context
- **User message staging:** `messages = list(conversation_history)` + staged user dict appended; `current_turn_user_idx` recorded. `agent/turn_context.py:L1104–L1115`
- **System prompt as three cache tiers:** `stable` (SOUL.md from HERMES_HOME or default identity, guidance, pinned skills, coding brief) → `context` (caller `system_message`, project context files, workspace) → `volatile` (skills index, memory, plugin sections, profile line, timestamp, runtime environment). Never re-rendered mid-session. `agent/system_prompt.py:L730–L793`, `agent/system_prompt.py:L796–L805`, `agent/system_prompt.py:L544–L550`, `agent/prompt_builder.py:L1652–L1700`
- **Project context files:** `.hermes.md` → `AGENTS.md` chain → `CLAUDE.md` → `.cursorrules`, loaded from cwd at startup only; cap 20 000 chars floor, dynamic 6 % of the window up to 500 000, overridable by `context_file_max_chars`. `agent/prompt_builder.py:L1783–L1788`, `agent/system_prompt.py:L709–L722`, `agent/prompt_builder.py:L1156–L1171`
- **Memory files:** `MEMORY.md` (2 200 chars) and `USER.md` (1 375 chars) are rendered into the volatile tier; the `memory` tool edits them. `agent/system_prompt.py:L516–L541`, `tools/memory_tool_store.py:L186`, `tools/memory_tool_store.py:L618`
- **External memory providers:** one plugin provider at a time; `build_system_prompt()` block plus per-turn `prefetch_all(query)` text injected into the request. `agent/memory_manager.py:L1–L4`, `agent/memory_manager.py:L501–L511`, `agent/turn_context.py:L903–L931`
- **Skills index + progressive disclosure:** names/descriptions in the prompt; `skill_view` loads a SKILL.md on demand as a tool result. `agent/system_prompt.py:L301–L314`, `tools/skills_tool.py:L2–L5`
- **Byte-stable prompt restored from DB:** on resume the stored `system_prompt` row is reused if it matches the runtime; rebuilt only after compression (`invalidate_system_prompt`). `agent/conversation_loop.py:L749–L772`, `agent/system_prompt.py:L808–L826`, `hermes_state_common.py:L377–L380`
- **Tool definitions:** `get_tool_definitions(enabled/disabled toolsets)` at init; `_HERMES_CORE_TOOLS` is the always-present core. `agent/agent_init.py:L1118`, `model_tools.py:L215`, `toolsets.py:L11–L39`
- **Tool Search deferral:** MCP/plugin and selected core tools are replaced in the model-visible array by `tool_search / tool_describe / tool_call` bridge tools, catalog rebuilt per assembly. `tools/tool_search.py:L1–L7`
- **Request assembly order:** `build_api_messages` → MoA context → canonicalization; "ORDER IS LOAD-BEARING" for cache breakpoints; system row prepended. `agent/turn_request_assembly.py:L106–L130`, `agent/turn_context.py:L1344`
- **Compaction trigger:** `ContextCompressor(threshold_percent=0.50, protect_first_n=3, protect_last_n=20)`; `should_compress_info` fires when `tokens >= threshold_tokens` unless in cooldown or the ineffective breaker; per-model threshold overrides. `agent/context_compressor.py:L2811–L2832`, `agent/context_compressor.py:L3006–L3015`, `agent/context_compressor.py:L2659–L2671`
- **Compaction algorithm:** prune old tool-result bodies (no LLM) → pick boundaries on the pruned copy → auxiliary-model summary → clean orphaned tool pairs. `agent/context_compressor.py:L5528–L5575`, `agent/context_compressor.py:L3285–L3300`
- **Where compaction runs:** turn-start compaction; a pre-API preflight gate comparing the assembled request with the threshold (insufficient progress blocks further passes); 413 / context-length provider errors compress and restart. `agent/turn_context_compaction.py:L129`, `agent/turn_preflight_gate.py:L20–L120`, `agent/turn_overflow.py:L1–L6`, `agent/turn_overflow.py:L463`
- **Gateway session hygiene:** a second compaction layer at 0.85 of the window between turns. `gateway/run_turn_hygiene.py:L94–L102`
- **Tool-output truncation:** 40 % head / 60 % tail with one marker; limits 50 000 bytes, 2 000 lines, 2 000 chars/line; `read_file` pages by char budget and reports `next_offset`. `tools/tool_output_truncate.py:L1–L12`, `tools/tool_output_limits.py:L13–L15`, `tools/file_tools.py:L96–L113`
- **Spill-to-file instead of truncating:** results over the per-tool threshold are written to `$HERMES_HOME/cache/spillover/{id}.txt` and replaced by preview + path; `enforce_turn_budget` caps the batch. `tools/tool_result_storage.py:L1–L6`, `tools/tool_result_storage.py:L293–L300`, `tools/tool_result_storage.py:L359`
- **Subdirectory hints:** AGENTS.md/CLAUDE.md found while navigating are appended to the tool result, never to the system prompt. `agent/subdirectory_hints.py:L1–L5`
- **Untrusted-result wrapping:** web/browser/MCP results ≥ 32 chars are wrapped in `<untrusted_tool_result>` with delimiter neutralization. `agent/tool_dispatch_helpers.py:L484–L495`, `agent/tool_dispatch_helpers.py:L572–L595`
- **History source on resume:** CLI loads `get_messages_as_conversation(session_id, repair_alternation=True)`; gateway loads `load_transcript` then hygiene. `hermes_cli/cli_agent_setup_mixin.py:L593–L596`, `hermes_state_messages.py:L1537–L1545`, `gateway/run_turn_prepare.py:L693–L700`
- **Pluggable context engine:** `context.engine` selects a plugin that owns `should_compress/compress` and may expose tools. `agent/context_engine.py:L1–L7`

## Model interface
- **Transport registry:** `anthropic`, `codex`, `chat_completions`, `bedrock` transports behind `ProviderTransport` (convert_messages/convert_tools/build_kwargs/normalize_response/validate_response). `agent/transports/__init__.py:L18–L31`, `agent/transports/base.py:L12–L51`
- **Client construction:** `_build_client` picks the Anthropic SDK, the MoA facade, boto3 Bedrock, or the OpenAI SDK client (shared httpx) by `api_mode`; GPT-5.x on a direct OpenAI URL auto-upgrades `chat_completions` → `codex_responses`. `agent/agent_init.py:L1029–L1042`, `agent/agent_init.py:L990–L1026`, `agent/agent_init.py:L482–L499`
- **Request kwargs:** `_build_api_kwargs_for_mode` branches anthropic / bedrock / codex / chat-completions builders. `agent/chat_completion_helpers.py:L1555–L1572`
- **Per-attempt request build:** re-apply reasoning echo for the provider, re-render prompt-cache decoration, strip images for rejecting models, LLM request middleware (trace kept), `pre_api_request` hook, optional `HERMES_DUMP_REQUESTS` dump. `agent/turn_api_request.py:L93–L205`, `agent/turn_api_request.py:L152–L153`
- **Prompt-cache decoration:** `build_prompt_cache_plan` places Anthropic `cache_control` markers; OpenAI-style history is converted to Anthropic content blocks. `agent/prompt_caching.py:L298–L308`, `agent/anthropic_message_convert.py:L1–L4`
- **Call issue:** `perform_api_call` chooses streaming (`_should_stream`: preferred even with no consumer, off for ACP/external-process providers) and runs through `run_llm_execution_middleware`. `agent/turn_api_call.py:L67–L167`, `agent/turn_api_call.py:L46–L64`
- **Streaming receive:** `_StreamingCall` issues `chat.completions.create(**stream_kwargs)` with `stream_options.include_usage`; the Anthropic path uses `messages.stream`; a cross-turn stale-stream breaker runs first. `agent/chat_completion_helpers.py:L3993–L4006`, `agent/chat_completion_helpers.py:L2734`, `agent/chat_completion_helpers.py:L2957–L2966`, `agent/chat_completion_helpers.py:L3412`
- **Non-stream call on a worker thread:** per-request client so interrupts close only that connection; a stale-call detector kills and raises. `agent/chat_completion_helpers.py:L1292–L1305`
- **Retry policy:** `api_max_retries` default 3; wait = provider `Retry-After` (capped) else `jittered_backoff(retry, base 2.0, max 60)` = min(base·2^(n−1), max) + jitter; adaptive policy for 429. `agent/agent_init.py:L1441–L1446`, `agent/turn_recovery.py:L1401–L1430`, `agent/retry_utils.py:L121–L130`, `agent/turn_api_error.py:L406–L417`
- **Error classification:** `classify_api_error` → structured `ClassifiedError` (retryable / should_compress / rotate credential / fallback); plugins may override via `transform_api_error_classification`. `agent/error_classifier.py:L974–L980`, `hermes_cli/plugins.py:L126–L130`
- **Backup model when unservable:** `try_activate_fallback` walks `_fallback_chain`, swapping client/model/provider in place, on classified failover or after retries exhaust; a persistent credential pool gives same-provider failover. `agent/chat_completion_helpers.py:L2086–L2121`, `agent/turn_api_error.py:L341`, `agent/turn_api_error.py:L380`, `agent/credential_pool.py:L1`
- **Post-exhaustion auto-recovery:** when retries and the chain are spent on a transient outage, the turn parks with a countdown and re-enters the retry loop (`auto_recovery_cycles` default 5). `agent/turn_recovery_autorecover.py:L1–L7`
- **Response validation + normalization:** `validate_response_shape` via the transport; `normalize_model_response` yields an assistant message with string content. `agent/turn_recovery.py:L1524–L1530`, `agent/turn_response_intake.py:L120–L128`
- **Degenerate-response ladders:** empty/thinking-only → partial-stream recovery → nudge → prefill continuation ×2 → budgeted retries → fallback provider; `finish_reason=length` → continuation nudges (up to 4), truncated tool-call retries with max_tokens boosts, repetition abort. `agent/turn_empty_response.py:L1–L5`, `agent/turn_truncation.py:L1–L6`, `agent/repetition_guard.py:L141`
- **Usage receipt:** `record_response_usage` folds `response.usage` into the compressor, session counters and state.db. `agent/turn_usage.py:L73–L79`

## Output

- **Registry call path:** `handle_function_call` → aliases → bridge unwrap → request middleware → `_pre_dispatch_guards` (`pre_tool_call` hook, fail-closed on timeout) → `registry.dispatch` → `post_tool_call` → `transform_tool_result`. `model_tools.py:L873–L967`, `model_tools.py:L823–L846`, `hermes_cli/plugins_dispatch.py:L51`
- **Terminal tool:** plan → acquire env → bounded pre-exec guard → approval guards → foreground or background spawn; description tells the model output is auto-truncated to a file. `tools/terminal_tool.py:L1360–L1475`, `tools/terminal_tool.py:L160–L165`
- **Execution backends (sandboxes):** local, docker, singularity/apptainer, modal, daytona, vercel_sandbox, ssh, plus plugin envs; built by `_ENV_BUILDERS`. `tools/terminal_tool_backends.py:L54`, `tools/terminal_tool_backends.py:L239–L241`
- **Programmatic tool calling:** `execute_code` runs a model-written Python script in a persistent per-conversation kernel that calls Hermes tools over RPC; only stdout returns. `tools/code_execution_tool.py:L1–L10`, `tools/code_kernel.py:L1–L5`
- **Browser:** agent-browser CLI over local headless Chromium, cloud backends, a user CDP endpoint or Camofox; accessibility-tree snapshots with `@eN` refs. `tools/browser_tool.py:L1–L8`
- **Persist-before-execute:** the assistant tool-call row is flushed to SQLite before any tool runs; a failed append ends the turn. `agent/turn_tool_round.py:L131–L153`
- **Rendering and delivery:** single-writer stream ownership with delta/reasoning fan-out; open stream boxes flushed before tools; gateway `delivery.py` routes responses to targets and `response_filters.py` decides whether a turn is delivered to the chat. `agent/stream_delivery.py:L1–L3`, `agent/turn_tool_round.py:L160–L164`, `gateway/delivery.py:L1–L2`, `gateway/response_filters.py:L1–L4`
- **Sub-agent spawn tool:** `delegate_task` (output) whose effect is the control-flow delegation above. `tools/delegate_tool.py:L488`

## Design decisions (one line each: the choice this harness made within a primitive)
- Input: one normalized `MessageEvent`/`run_conversation(user_message, conversation_history, task_id)` seam shared by CLI, ~25 gateway adapters, HTTP, ACP and cron; mid-turn messages become steer/redirect rather than new turns.
- Context: a three-tier byte-stable system prompt (identity → project files → volatile memory/skills/time) rebuilt only after compression; compaction at 50 % of the window by prune-then-summarize with a separate auxiliary model; oversized tool output is spilled to files, not dropped.
- Model interface: OpenAI chat-completions wire by default with pluggable transports (Anthropic, Responses, Bedrock) and provider plugins; streaming always on; 3 retries with backoff, then a configurable fallback chain, then a bounded auto-recovery wait.
- Output: a fixed core tool set sent on every call plus a Tool Search bridge for the long tail; tool batches split into parallel-safe segments; terminal execution behind pluggable sandboxes (local/docker/modal/…) and a regex-plus-human approval gate; tool-call rows persisted before execution.
- Control flow: synchronous phase-verdict loop with an unlimited default iteration budget, verify-on-stop nudges that re-enter the loop, flat delegation by default (`max_spawn_depth=1`) with threaded children, and task-keyed auxiliary model routing.

## Hard cases
- **Tool Search bridge (`tool_search`/`tool_describe`/`tool_call`):** a tool call the model makes (output) whose only job is to decide which tool schemas the model sees (context); resolved by "assign by function": the catalog read is context, the unwrapped `tool_call` re-dispatch is output. `tools/tool_search.py:L1–L7`, `model_tools.py:L701–L709`
- **`execute_code` programmatic tool calling:** a program the model writes at run time that sequences only tools → output (rule 27); but the loop refunds the iteration it used, which is control flow. `tools/code_execution_tool.py:L1–L10`, `agent/turn_tool_round.py:L199–L200`
- **Subdirectory hints and untrusted wrapping inside the tool result path:** code in the output executor that changes what the model is shown; assigned to context by rule 20. `agent/subdirectory_hints.py:L1–L5`, `agent/tool_dispatch_helpers.py:L572–L595`
- **Stop-gate nudges:** the harness appends a synthetic user row and goes again; the decision is control flow, the row's text is context, and it is not input (no person wrote it). `agent/turn_stop_gates.py:L105–L140`
- **Approval inside the terminal tool:** the gate runs inside the tool executor and blocks the worker thread (CLI) or returns `pending_approval` and ends the call (gateway); the person's answer is consumed by the harness → control flow by rule 26, even though the code lives in `tools/`. `tools/terminal_tool.py:L1013–L1047`
- **Reasoning-only stall → model fallback:** a model swap triggered by unusable output rather than an HTTP failure; placed in model interface because the request "could not be served" with content, not keyed to the work. `agent/turn_truncation.py:L630–L635`
- **Prompt-cache decoration:** `cache_control` markers are wire-format (model interface) but the tiered ordering of the system prompt exists only to keep them effective (context design); split across both. `agent/prompt_caching.py:L298–L308`, `agent/system_prompt.py:L730–L793`
- **Gateway session hygiene (0.85 compaction):** compaction performed by the gateway outside the agent turn; still context (fits the window) but hosted in a different process layer. `gateway/run_turn_hygiene.py:L94–L102`
- **Codex app-server mode — DOES NOT FIT cleanly:** with `api_mode == "codex_app_server"` the whole turn (loop, tool execution, model calls) is handed to an external OpenAI Codex subprocess and Hermes only projects its events into rows and arms a fallback on failure; the five primitives collapse into one opaque external harness that is not a sub-agent (no delegation, no outer loop). `agent/conversation_loop.py:L1650–L1651`, `agent/conversation_loop.py:L1537–L1552`
- **ACP / external-process "providers":** `acp://` base URLs make the "model" another agent process; streaming is disabled and the model interface boundary is another harness. `agent/turn_api_call.py:L46–L56`
- **Mixture-of-Agents:** several model calls per iteration issued by the harness (control flow) whose outputs are appended to the user message (context). `agent/moa_loop.py:L1–L5`
