# pi (pi-mono coding agent)

**Source:** https://github.com/badlogic/pi-mono · **Version:** commit 5ab7fe74c400097b386662205cd93900695b8a71 (2026-10-15) · **Language:** TypeScript (Node/Bun)
**Path conventions:** `agent/` = `packages/agent/src/`; `ai/` = `packages/ai/src/`; `ca/` = `packages/coding-agent/src/`; `ex/` = `packages/coding-agent/examples/extensions/`; `ev/` = `packages/evals/`. All paths relative to the repo root. Package scope at this commit is `@earendil-works/*` (pi-agent-core, pi-ai, pi-coding-agent).
**What it is:** pi is a terminal coding agent by Mario Zechner (badlogic) with a layered design: `pi-agent-core` holds a minimal agent loop, `pi-ai` holds provider adapters (Anthropic, OpenAI, Google, Bedrock, Mistral, …) behind one `StreamFunction`, and `pi-coding-agent` wraps both in an `AgentSession` with JSONL session trees, compaction, retries, built-in tools, and an extension system; interactive TUI, print, JSON, and RPC modes sit on top. The model is reached over HTTPS/SSE (or WebSocket for some providers) through provider SDKs or raw fetch, with `maxRetries: 0` so pi owns retry policy.

## Control flow
- **Inner/outer loop (`runLoop`):** inner `while (hasMoreToolCalls || pendingMessages.length > 0)` issues one model call per iteration; outer `while (true)` re-enters only if follow-up messages arrived or `finishTurn` asked for one more context-only turn, else breaks and emits `agent_end`. `agent/agent-loop.ts:L163–L321`
- **Stop on error/abort:** an assistant `stopReason` of `"error"` or `"aborted"` is a hard exit: `finishTurn` is called, `turn_end`/`agent_end` emitted, loop returns. `agent/agent-loop.ts:L245–L256`
- **Go-again decision:** `hasMoreToolCalls = !executedToolBatch.terminate`; if the response had no tool calls and no steering/follow-up is queued, the loop ends. `agent/agent-loop.ts:L258–L278`, `L295–L318`
- **`finishTurn` decision hook:** returns `{action:"end"}` (stop now) or `{action:"continue"}` (force one more request); undefined keeps normal scheduling. `agent/agent-loop.ts:L286–L298`, `agent/types.ts:L146–L158`
- **Early termination from tools:** a batch ends the run only when every finalized tool result sets `terminate: true` (`shouldTerminateToolBatch`); a blocked `beforeToolCall` may set it too. `agent/agent-loop.ts:L690–L692`, `L745–L755`, `agent/types.ts:L66–L74`
- **Steering vs. follow-up queues:** `Agent.steer()` injects after the current turn's tools finish; `followUp()` waits until the agent would otherwise stop; drain modes `"one-at-a-time"` (default) or `"all"`. `agent/agent.ts:L143–L174`, `L247–L248`, `L299–L306`, `L496–L503`; polled in the loop at `agent/agent-loop.ts:L176`, `L204–L206`, `L295`, `L302–L308`
- **One run at a time:** `prompt()` throws if a run is active; `continue()` resumes from a user/toolResult tail, else drains steering/follow-up queues. `agent/agent.ts:L373–L381`, `L384–L411`, `L507–L530`
- **Abort:** `Agent.abort()` fires the run's `AbortController`; `AgentSession.abort()` also cancels retry backoff, compaction, branch summary, then waits for idle. `agent/agent.ts:L341–L343`; `ca/core/agent-session.ts:L2464–L2474`
- **Session post-run loop:** `_startRun` calls `agent.prompt(messages)` then loops `_handlePostAgentRun()` → `agent.continue()` while retry/overflow-recovery/queued messages/extension `agent_before_settle` ask for more. `ca/core/agent-session.ts:L1837–L1882`, `L1943–L1981`, `L1983–L2005`
- **Auto-retry budget (session level):** `_prepareRetry` increments `_retryAttempt`, stops past `maxRetries`, sleeps `retryDelayMs()` (abortable), omits the failed assistant message from projection, and returns true so the loop re-issues the request. Defaults `enabled: true, maxRetries: 3, baseDelayMs: 2000`. `ca/core/agent-session.ts:L3792–L3832`; `ca/core/settings-defaults.ts:L18–L26`
- **Overflow recovery is one-shot:** `_checkCompaction` case 1 compacts and retries the turn once (`_overflowRecoveryAttempted` guard); case 2 (completed response) compacts without retry; case 3 threshold compacts without retry. `ca/core/agent-session.ts:L2977–L3115`
- **Virtual-model routing keyed to the work:** `prepareRequest` resolves a virtual model to a physical one per request with `reason: "user" | "continuation" | "retry"`, storing router state as a session entry; a router (extension-registered) picks the model. `ca/core/agent-session.ts:L815–L843`; `ca/core/model-runtime.ts:L1003–L1034`; `ca/core/virtual-models.ts:L1–L11`, `L43–L50`
- **Extension boundary hooks that can force another turn:** `turn_end` and `agent_before_settle` handlers return `continue: true` and may commit boundary drafts; the session validates `canContinue` first. `ca/core/agent-session.ts:L847–L897`, `L1983–L2005`
- **`tool_call` approval gate (extension):** `beforeToolCall` → `runner.emitToolCall`; first handler returning `{block:true}` wins; the `permission-gate` example asks `ctx.ui.select` and blocks when no UI. `ca/core/agent-session.ts:L659–L682`; `ca/core/extensions/runner.ts:L1249–L1267`; `ex/permission-gate.ts:L13–L33`
- **Project trust gate:** `resolveProjectTrusted` checks a persisted trust store, an extension `project_trust` handler, a `defaultProjectTrust` setting ("ask" default), then prompts; untrusted cwd means project `.pi/` extensions/skills/prompts/SYSTEM.md are not loaded. `ca/core/project-trust.ts:L47–L97`; `ca/core/trust-manager.ts:L30–L39`, `L45–L59`, `L67–L97`
- **Sub-agents (example extension, not core):** the `subagent` tool spawns a separate `pi --mode json -p --no-session` process per agent, in `single`, `parallel`, or `chain` modes, and returns the child's final output as the tool result (depth 1; results return as tool-result text). `ex/subagent/index.ts:L298`, `L342–L348`, `L470–L475`; `ex/subagent/README.md`
- **Nested tool calls from tools:** `ctx.executeTool()` runs through `runToolCall` with the session's hooks; ids are `<parent>/<n>` and never enter the transcript (sequences only tools → output by rule, but concurrency is serialized by a queue). `ca/core/nested-tool-calls.ts:L161–L200`; `agent/agent-loop.ts:L811–L819`; `ca/core/extensions/types.ts:L384–L395`

## Model interface
- **`StreamFunction` contract:** `(model, normalizedTranscript, options) => AssistantMessageEventStream`; errors must terminate the stream with `stopReason "error"|"aborted"`. `ai/types.ts:L379–L394`
- **Loop → stream boundary:** `streamAssistantResponse` resolves the API key via `getApiKey` (expiring tokens), calls `streamFunction`, and folds `start`/`*_delta`/`done`/`error` events into a partial `AssistantMessage` in context. `agent/agent-loop.ts:L399–L407`, `L414–L458`
- **Session stream function:** `modelRuntime.streamSimple` → `lazyStream` (async setup behind a sync stream) → `prepareRequest` (auth/headers) → provider `streamSimple`. `ca/core/sdk.ts:L420–L431`; `ca/core/model-runtime.ts:L723–L749`; `ai/api/lazy.ts:L46–L62`; `ai/models.ts:L907–L914`
- **Anthropic adapter:** builds a `@anthropic-ai/sdk` client (API key or OAuth bearer with Claude Code identity headers), calls `client.beta.messages.create(params, {maxRetries: 0, signal, timeout})`, decodes SSE by hand. `ai/api/anthropic-messages.ts:L603–L645`, `L1018–L1060`, `L475–L500`, `L534`
- **Provider-level retry:** `retryProviderRequest` mirrors SDK policy (408/409/429/5xx or `x-should-retry`), honors `retry-after(-ms)` up to `maxRetryDelayMs` (default 60 s, else fail fast so the outer policy sees it), otherwise `min(0.5·2^n, 8)s` with 25 % jitter, abortable. `ai/utils/provider-retry.ts:L25–L37`, `L53–L69`, `L107–L128`; `ai/api/anthropic-messages.ts:L658–L666`
- **Assistant-level retry classifier:** `isRetryableAssistantError` matches overloaded/429/5xx/network text but excludes quota/billing patterns; `retryAssistantCall` does bounded exponential backoff `baseDelayMs·2^(n−1)` capped at 60 s. `ai/utils/retry.ts:L7–L28`, `L30–L60`, `L121–L137`, `L196–L246`, `L257–L262`
- **Overflow detection:** regex table over provider error texts (`prompt is too long`, `request_too_large`, …) with non-overflow exclusions (rate limit), used to divert to compaction instead of retry. `ai/utils/overflow.ts:L37–L63`, `L76–L80`; `ca/core/agent-session.ts:L3739–L3743`
- **Strict-tools fallback within the adapter:** a 400 "compiled grammar too large"/"Too many strict tools" rebuilds params without preferred strict schemas and retries once. `ai/api/anthropic-messages.ts:L667–L691`
- **Stream termination:** abort → `stopReason "aborted"`, exceptions → `"error"` with `errorMessage`; `done` carries the final message with usage and cost. `ai/api/anthropic-messages.ts:L897–L933`; `ai/utils/event-stream.ts:L26–L58`
- **Prompt caching:** `cache_control` on the last user/system block and last tool declaration; retention `short`/`long`/`none`; `sessionId` forwarded for cache-aware backends. `ai/api/anthropic-messages.ts:L1529–L1555`, `L1659`; `ai/types.ts:L239–L249`
- **Thinking mapping:** pi `ThinkingLevel` maps to Anthropic effort or `budget_tokens` (adaptive vs. budget thinking), interleaved-thinking beta header. `ai/api/anthropic-messages.ts:L944–L1012`, `L1296–L1305`, `L195`
- **Wire-level hooks:** `onPayload` (extension `before_provider_request` may replace the body), `onResponse` (`after_provider_response`), `onProviderStreamEvent`. `ai/api/anthropic-messages.ts:L653–L656`, `L693`, `L700`; `ca/core/sdk.ts:L382–L409`; `ai/types.ts:L174–L182`, `L218–L223`
- **Transport/options:** `transport: "sse"|"websocket"|…`, `timeoutMs`, `maxRetries`, `maxRetryDelayMs`, custom `fetch`, custom `headers`. `ai/types.ts:L144`, `L157–L210`, `L235–L238`
- **Credential handling:** OAuth tokens auto-refresh under a file lock with a timeout; `auth.json` written with mode `0o600` in a `0o700` dir. `ai/auth/resolve.ts:L119–L142`; `ca/core/auth-storage.ts:L37`, `L71`
- **Direct-route virtual model outside the loop:** `streamSimple` on a virtual model routes with `reason: "direct"` and withholds the caller's credentials when the provider differs. `ca/core/model-runtime.ts:L725–L743`

## Output
- **Tool execution pipeline:** `prepareToolCall` (lookup, `prepareArguments`, schema validation, `beforeToolCall`) → `executePreparedToolCall` (`tool.execute(id, args, signal, onUpdate)` in try/catch, duration measured) → `finalizeExecutedToolCall` (`afterToolCall` may replace content/details/isError). `agent/agent-loop.ts:L708–L777`, `L821–L857`, `L859–L910`
- **Parallel vs. sequential:** default `"parallel"`: preflight sequentially, run allowed tools concurrently with `Promise.all`, emit results in source order; `"sequential"` if configured or any called tool has `executionMode: "sequential"`. `agent/agent-loop.ts:L508–L523`, `L586–L660`; `agent/types.ts:L308–L317`
- **Truncated-output guard:** if the response `stopReason` is `"length"`, every tool call is failed with an error result instead of executed. `agent/agent-loop.ts:L263–L270`, `L478–L503`
- **Built-in tool set:** `read, bash, powershell, edit, write, grep, find, ls` (default four: read, bash, edit, write). `ca/core/tools/index.ts:L95–L105`; `ca/core/system-prompt.ts:L64`
- **bash executor:** `spawn(shell, args, {cwd, detached, env: process.env + bin dir})`, stdout/stderr streamed, optional per-call timeout, abort kills the whole process group with `SIGKILL` (`taskkill /T` on Windows). `ca/core/tools/bash.ts:L97–L166`; `ca/utils/shell.ts:L138–L150`, `L187–L215`
- **edit tool:** exact unique `oldText`→`newText` replacements against the original file, BOM/LF normalization, fuzzy-match fallback with diff details; file mutations serialized per real path. `ca/core/tools/edit.ts:L152`, `L190–L194`; `ca/core/tools/edit-diff.ts:L28–L37`; `ca/core/tools/file-mutation-queue.ts:L32–L61`
- **read tool:** text with `offset`/`limit` and head truncation; images returned as image blocks (resized) or omitted for non-vision models. `ca/core/tools/read.ts:L96`, `L159–L177`, `L80–L83`
- **grep/find:** spawn ripgrep (`rg`, downloaded if missing). `ca/core/tools/grep.ts:L119–L121`, `L168`
- **MCP tools:** the built-in `mcp` extension registers each connected server's tools via `pi.registerTool` (hidden exposure when only reachable from codemode) and forwards calls with `client.callTool`. `ca/extensions/mcp/index.ts:L387–L460`; `ca/extensions/mcp/tools.ts:L337–L339`
- **codemode tool:** the model writes JavaScript that calls other tools; it runs in a QuickJS WASM sandbox (256 MiB heap, 2 workers max, 10k-token output cap, optional `timeout_ms`), with no Node/fs/network; nested calls use `ctx.executeTool`. `ca/extensions/codemode/tool.ts:L1–L10`, `L118–L120`; `ca/extensions/codemode/execute.ts:L50–L59`, `L254`, `L510–L522`
- **Rendering streamed fragments:** the TUI updates a streaming assistant component on each `message_update` and creates tool components as tool calls appear; JSON mode writes each event as one JSON line; print mode prints final assistant text. `ca/modes/interactive/interactive-mode.ts:L3524–L3536`; `ca/modes/print-mode.ts:L108–L112`, `L139–L158`
- **Extension UI as output:** `ctx.ui.select/confirm/input/editor` render dialogs (also used by approval gates). `ca/core/extensions/types.ts:L149–L157`, `L240`

## Design decisions (one line each: the choice this harness made within a primitive)
- Input: three capture surfaces (TUI editor, print/JSON CLI, JSONL RPC) all funnel into `AgentSession.prompt()`, with mid-run input split into "steer" (after this turn) vs. "follow-up" (after the agent would stop), one message at a time by default.
- Context: the transcript is a persisted tree; every request is a projection of the active branch (compaction entry + kept tail + context edits), the system prompt is a set of named XML sections diffed into system-message patches, and tool declarations are transcript deltas, so replaying the file reproduces the exact request.
- Model interface: one `StreamFunction` contract across ~15 provider adapters with SDK retries disabled (`maxRetries: 0`) and pi's own two-tier retry (HTTP-level with retry-after cap, assistant-level with error-text classification), overflow routed to compaction rather than retry.
- Output: tools are plain `{name, parameters (TypeBox), execute}` objects; parallel execution by default with per-file mutation serialization; no sandbox in core (OS sandboxing and permission prompts are extensions); a QuickJS-sandboxed `codemode` tool lets the model script tool calls.
- Control flow: a two-level loop in `pi-agent-core` (tool calls/steering inner, follow-ups outer) plus a session-level outer loop for retries/overflow recovery/extension continuations; sub-agents are not in core but an example spawns child `pi` processes; per-request model routing via virtual models.

## Hard cases
- **`before_provider_request` payload hook:** lives in the adapter (`onPayload`) at the wire boundary, but an extension can rewrite the request body, i.e. decide what the model is shown. By the function rule it is Context when it changes content; the transport callback itself stays Model interface. `ai/api/anthropic-messages.ts:L653–L656`; `ca/core/sdk.ts:L382–L386`
- **Virtual-model routing:** `prepareRequest` chooses the physical model per request by reason (user/continuation/retry) — keyed to the work, so Control flow — even though it is implemented inside the model-runtime layer; the `reason: "retry"` branch after a failed request overlaps Model interface's "backup model" (resolved: the router decides based on work state, so Control flow). `ca/core/agent-session.ts:L815–L843`; `ca/core/model-runtime.ts:L1003–L1034`
- **Strict-tools 400 fallback:** an in-adapter request rebuild on a specific 400 (drops strict schemas). It alters the request contents, but the trigger is "request could not be served" — assigned Model interface by the unavailability rule. `ai/api/anthropic-messages.ts:L667–L691`
- **Compaction summary call:** a second model call issued by the Context primitive (summary generation). Rule: Context never calls the model; here it does, through the same `StreamFunction`. Resolved as Context mechanism using the Model interface as a service; noted as a borderline.
- **Nested tool calls / codemode:** a script the model writes sequences only tools (Output by rule), yet it also reaches `models.*` (classifiers, image models) from inside the sandbox — a model call issued from inside a tool. `ca/extensions/codemode/tool.ts:L1–L10`; `ca/extensions/codemode/execute.ts:L50`. Partially DOES NOT FIT: a tool that calls models is neither pure Output nor Control flow in the given scheme.
- **`agent_before_settle` / `turn_end` boundaries:** extensions may commit "boundary drafts" (entries appended to the session: Context) and return `continue` (Control flow) in one hook; decomposed per rule 28. `ca/core/agent-session.ts:L847–L897`, `L1983–L2005`
- **`pi-durable` package:** a second, experimental harness in the same repo (durable task graph, child tasks, commit-before-show) sharing `pi-ai`; not deconstructed here beyond noting it exists. `packages/durable/README.md:L1–L6`, `L581`
- **Telemetry package:** span interface exists and `telemetryContext` is passed through options, but no span is started in `ai/`, `agent/`, or `ca/` at this commit — recorded as "interface present, emission not found". `packages/telemetry/src/index.ts:L1–L22`; `ai/api/simple-options.ts:L48`
