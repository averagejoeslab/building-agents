# Cline

**Source:** https://github.com/cline/cline · **Version:** commit 23791b9323aadd91d7dbaea8a8fa262cd2f7ad0b (2026-10-15) · **Language:** TypeScript (Bun/Node)
**Path conventions:** `ag/` = `sdk/packages/agents/src/`; `co/` = `sdk/packages/core/src/`; `ll/` = `sdk/packages/llms/src/`; `sh/` = `sdk/packages/shared/src/`; `cli/` = `apps/cli/src/`. All paths relative to the repo root.
**What it is:** Cline is an open-source coding agent (Cline Bot Inc.) shipped as a VS Code extension, a CLI, and an SDK. At this commit the harness is a layered monorepo: `@cline/agents` holds the stateless loop (`AgentRuntime`), `@cline/core` adds sessions, persistence, compaction, hooks, the tool set, and sub-agents, and `@cline/llms` reaches providers through the Vercel AI SDK (`streamText`) behind a gateway registry. Tool calls use the providers' native tool-calling wire format.

## Control flow
- **Iteration loop and stop rule:** `execute` loops `while iteration < maxIterations`, issues one model request per iteration, executes the reply's tool calls, and returns `completed` when a turn has no tool calls or a `completesRun` tool (such as `submit_and_exit`) succeeded; exceeding `maxIterations` throws and the run fails. `ag/agent-runtime.ts:L836–L838`, `L949–L972`, `L1005–L1027`, `L2383–L2403`
- **Completion reminders:** when a required completion tool exists and a turn has no tool calls, a reminder user message is appended and the loop continues instead of stopping. `ag/agent-runtime.ts:L744–L786`, `L955–L963`
- **Budgets and safety stops:** `MistakeTracker` counts consecutive mistakes (default 6) and either injects guidance or stops; `LoopDetectionTracker` (CLI default: soft at 3, hard at 5 identical calls) appends a recovery notice or escalates to the mistake limit; any hook returning `{stop}` raises `ControlledStopError`. `co/runtime/safety/mistake-tracker.ts:L80–L164`; `co/runtime/safety/loop-detection.ts:L66–L124`; `co/runtime/orchestration/session-runtime-orchestrator.ts:L471–L510`, `L1465–L1498`; `ag/agent-runtime.ts:L2777–L2788`; `cli/runtime/defaults.ts:L6–L9`
- **Approval gate:** `prepareToolExecution` resolves a per-tool policy and, when `autoApprove === false`, awaits `requestToolApproval`; the CLI answers with a terminal `[y/N]` prompt or a file-based desktop IPC polled for up to 5 minutes, and a rejection becomes an error tool result. `ag/agent-runtime.ts:L2477–L2541`; `cli/utils/approval.ts:L68–L113`; `co/runtime/tools/tool-approval.ts:L29–L102`
- **Sub-agents (depth 1 per spawn, inner harness is a `SessionRuntime`):** the `spawn_agent` tool builds a delegated `SessionRuntime` with its own tools, `maxIterations`, and parent id, awaits `run(task)`, and returns text, iteration count, and usage as the tool result; `AgentTeam` composes worker/reviewer teams. `co/extensions/tools/team/spawn-agent-tool.ts:L117–L204`; `co/extensions/tools/team/delegated-agent.ts:L149–L158`; `co/extensions/tools/team/multi-agent.ts:L239–L245`, `L535–L587`
- **Plan/Act modes as a bundle:** plan mode swaps the system prompt (context), installs a `beforeTool` command guard that rejects file-editing shell commands (output filter), and exposes `switch_to_act_mode` so the model can change mode (control flow). `sh/prompt/cline.ts:L22–L58`; `co/runtime/orchestration/runtime-builder.ts:L546–L566`; `co/extensions/tools/command-guard.ts:L1–L23`

## Input
- **Host entry:** `LocalRuntimeHost.runTurn` takes a prompt with optional images and file paths, records `session.input_sent`, and either runs the turn or enqueues it (`queue` or `steer` delivery) when a run is active. `co/runtime/host/local-runtime-host.ts:L1142–L1224`; `co/runtime/orchestration/user-input-builder.ts:L10–L37`
- **Mid-turn steering:** `steer` prompts are consumed at every request boundary by `consumePendingUserMessage`, which appends them as a user message before the request; `queue` prompts drain after the turn finishes. `ag/agent-runtime.ts:L1687–L1695`, `L2302–L2321`; `co/runtime/host/local-runtime-host.ts:L861–L868`; `co/runtime/turn-queue/pending-prompt-service.ts:L54–L120`
- **Tool results re-enter:** each executed call becomes a `tool` message holding a `tool-result` part (`isError` on failure or rejection) pushed onto `state.messages`. `ag/agent-runtime.ts:L2628–L2647`, `L974–L982`
- **Model-consumed answers:** the `ask_question` tool returns the person's chosen option as a tool result (input by rule), distinct from the harness-consumed approval. `co/extensions/tools/definitions.ts:L818–L837`; `cli/utils/approval.ts:L119–L125`

## Context
- **System prompt:** `buildClineSystemPrompt` fills the ACT or YOLO template (platform, date, IDE, cwd, workspace metadata, rules) and appends mode instructions; the orchestrator merges extension rules and passes the result to the runtime. `sh/prompt/cline.ts:L152–L213`; `sh/prompt/system/act.ts:L1–L36`; `co/runtime/orchestration/session-runtime-orchestrator.ts:L139–L152`, `L990–L1027`
- **Request assembly:** `prepareModelRequest` clones the transcript, lists tool definitions, appends pending steer input, runs `prepareTurn` (compaction) and then `beforeModel` hooks that may replace messages, tools, or options; the orchestrator's `beforeModel` runs message builders that convert to the provider's message format. `ag/agent-runtime.ts:L1656–L1736`; `co/runtime/orchestration/session-runtime-orchestrator.ts:L1152–L1192`
- **Hook context injection:** `beforeRun`, `beforeTool`, and `afterTool` hooks may return `appendContext`, which is buffered and flushed as one user message after the tool results. `ag/agent-runtime.ts:L1099–L1133`, `L2457–L2466`, `L2606–L2614`
- **Compaction trigger and strategies:** `createContextCompactionPrepareTurn` estimates request tokens, scales the budget by observed provider under-counting (capped at 4x), compacts when the estimate reaches 90% of the effective input limit, and targets 70%; `agentic` compaction calls a summarizer model over messages before a cut index that preserves 20k recent tokens, `basic` compaction drops and truncates by projection policy. `co/extensions/context/compaction.ts:L267–L420`; `co/extensions/context/compaction-shared.ts:L15–L37`; `co/extensions/context/agentic-compaction.ts:L116–L175`; `co/extensions/context/budget-projection/project.ts:L479–L560`
- **Oversized tool results:** tools marked `resultPolicy: "cache-oversized"` have results longer than `maxCachedResultChars` stored in a tool-result cache and replaced by a preview in the transcript. `co/runtime/orchestration/session-runtime-orchestrator.ts:L1160–L1180`, `L1001–L1005`

## Model interface
- **Gateway and providers:** `DefaultGateway.stream` resolves provider and model from a registry, validates model-side tools, derives `maxTokens`, and calls the provider's `stream`; built-in providers wrap AI SDK modules (Anthropic via `@ai-sdk/anthropic`). `ll/providers/gateway.ts:L273–L408`; `ll/providers/vendors/anthropic.ts:L15–L70`
- **Streaming and tool-call wire format:** `streamText` runs with `maxRetries: 5`, `experimental_repairToolCall`, and native tools; the runtime consumes `text-delta`, `reasoning-delta`, `tool-call-delta`, `usage`, and `finish` events and classifies a finish error (`classifyProviderError`, `isRetryableProviderError`). `ll/providers/ai-sdk.ts:L1086–L1097`, `L2436–L2446`; `ag/agent-runtime.ts:L1808–L1830`, `L1877–L1895`, `L1988–L2008`
- **Turn-level retries:** the runtime re-issues a turn that failed with a retryable provider error up to 3 times with 1 s to 15 s exponential backoff, only when nothing was streamed; an AI SDK middleware retries empty streams up to 3 times. `ag/agent-runtime.ts:L72–L91`, `L1202–L1322`; `ll/providers/middleware/retry-empty-response.ts:L97–L101`, `L273–L340`
- **Prompt caching:** Anthropic-compatible routing attaches `cache_control` according to per-provider prompt-cache routes. `ll/providers/routing/anthropic-compatible.ts:L51–L91`, `L199–L227`

## Output
- **Tool set:** default tools are `read_files`, `search_codebase`, `run_commands`, `fetch_web_content`, `editor` (or `apply_patch`), `skills`, `ask_question`, and optionally `submit_and_exit`; MCP server tools, plugin tools, and team tools are appended by the runtime builder. `co/extensions/tools/definitions.ts:L915–L981`; `co/runtime/orchestration/runtime-builder.ts:L568–L598`
- **Executor and concurrency:** `executeToolCalls` prepares every call, then runs adjacent `parallel`-mode calls under `Promise.all` and `sequential` ones one at a time; each tool carries `timeoutMs` (default 30 s), `retryable`, and `maxRetries` (default 3). `ag/agent-runtime.ts:L2343–L2381`; `sh/tools/create.ts:L108–L138`
- **Shell execution:** `run_commands` runs its commands concurrently through `createShellExecutor`, which spawns the default shell (detached on POSIX) with a rolling output collector capped at `maxOutputChars` and a per-command timeout; there is no OS sandbox for commands, while plugins run in a `SubprocessSandbox` or `WorkerSandbox`. `co/extensions/tools/definitions.ts:L180–L263`; `co/extensions/tools/executors/bash.ts:L717–L760`, `L1133–L1182`; `co/runtime/tools/subprocess-sandbox.ts:L126–L160`; `co/runtime/tools/worker-sandbox.ts:L91–L130`
- **Result presentation:** `tool-started`, `tool-updated` (streaming command output), `tool-finished`, and `assistant-text-delta` events are emitted to hosts (CLI TUI, VS Code webview) through the session event bridge. `ag/agent-runtime.ts:L2543–L2556`, `L2578–L2590`, `L2692–L2760`
- **Checkpoints:** hook-based checkpoints snapshot the working tree with a stash-style commit plus an untracked-files parent, kept under private git refs per session for restore from the UI. `co/hooks/checkpoint-hooks.ts:L249–L260`, `L349–L360`, `L437–L450`, `L497–L540`

## Production concerns
- **Persistence:** session rows live in a SQLite `sessions.db` (provider, model, cwd, status, `messages_path`); messages are persisted through `persistSessionMessages` on runtime events and reloaded from `messages_path` on resume (context); compaction state is saved to a sidecar. `co/services/storage/sqlite-session-store.ts:L25–L90`; `co/runtime/host/local-runtime-host.ts:L352–L366`, `L754–L770`, `L1620–L1627`; `co/runtime/host/history.ts:L418–L447`
- **Safety & security:** per-tool approval policies with an approval callback (control flow), the plan-mode command blacklist and hook `skip`/`stop` controls (output filters), provider-executed tool calls skipped locally, and command timeouts. `ag/agent-runtime.ts:L2420–L2500`; `co/extensions/tools/command-guard.ts:L1–L23`; `cli/runtime/tool-policies.ts:L30–L86`
- **Observability:** `CORE_TELEMETRY_EVENTS` (session, `task.tokens`, `task.tool_used`, `task.provider_api_error`, `task.mistake_limit_reached`) through a `TelemetryService` with OpenTelemetry and Langfuse adapters; the runtime logs request diagnostics and emits `status-notice` events for retries and compaction. `co/services/telemetry/core-events.ts:L43–L82`; `co/services/telemetry/TelemetryService.ts:L11–L40`; `ll/services/langfuse-telemetry.ts:L1–L40`; `ag/agent-runtime.ts:L1721–L1733`
- **Resilience:** provider-error turn retry, one-shot overflow recovery (compact and retry), max-tokens recovery by compaction then up to 3 concision nudges, a single continuation after an unknown finish, AI SDK request retries honoring retry-after, and abort propagation. `ag/agent-runtime.ts:L1163–L1200`, `L1363–L1448`, `L1481–L1596`; `ll/providers/ai-sdk.ts:L1086–L1097`
- **Performance:** streamed deltas, parallel tool groups, prompt-cache routing, oversized-result caching, a char-based token estimator corrected by provider feedback, and idle-timeout sandboxes. `ag/agent-runtime.ts:L2362–L2380`; `co/extensions/context/compaction.ts:L335–L372`; `co/runtime/tools/subprocess-sandbox.ts:L148–L160`
- **Evaluation:** 290 Bun unit-test files across agents, core, and llms (the runtime alone has a 4,920-line test), provider VCR fixtures, CLI end-to-end tests, and `evals/` with smoke tests and `cline-bench` run under Harbor in Docker or Daytona. `ag/agent-runtime.test.ts:L1–L40`; `ll/tests/provider-vcr/README.md:L1–L31`; `cli/cli.e2e.test.ts:L1–L40`; `evals/e2e/run-cline-bench.ts:L1–L40`

## Hard to place
- **Provider-executed tools:** Anthropic `web_search` runs inside the provider; the harness sees it only as `tool-call-delta` events with `execution` metadata, records it as model tool activity, and skips local execution; the tool runs on the model side, so the output primitive is partly outside the harness, and the rules do not cover it. `ag/agent-runtime.ts:L1877–L1895`, `L2422–L2432`; `ll/providers/vendors/anthropic.ts:L29–L47`
- **Agentic compaction:** a context component (`prepareTurn`) itself issues a model request to the summarizer; by function the trigger and cut are context and the summarizer call is model interface, but the call is sequenced from inside context assembly, not by the loop. `co/extensions/context/agentic-compaction.ts:L116–L175`; `co/extensions/context/compaction-shared.ts:L678–L720`
- **Mistake and loop trackers:** one component both appends guidance as a user message (context) and decides to abort the run (control flow); the rules split it by effect. `co/runtime/orchestration/session-runtime-orchestrator.ts:L1465–L1498`; `co/runtime/safety/mistake-tracker.ts:L128–L160`
- **Subprocess hook files:** user hook scripts are bundles that can cancel a run (control flow), modify context, and observe events (observability); each decomposes under the rules. `co/hooks/subprocess.ts:L133–L180`; `co/hooks/hook-file-hooks.ts:L760–L770`

## Summary
| Primitive | Design decision |
|---|---|
| Input | Host runTurn with text, images, files; steer queue consumed per request; tool results as tool messages |
| Context | Templated system prompt plus rules, cloned transcript, hook context, estimator-driven compaction at 90% via summarizer |
| Model interface | Gateway over Vercel AI SDK streamText, native tools, 5 SDK retries plus 3 turn retries with backoff |
| Output | Native tool calls in parallel groups with timeouts; shell spawn, editor, MCP; git-ref checkpoints |
| Control flow | Loop until no tool calls or completion tool; maxIterations, mistake and loop trackers, approval gates, sub-agents |
